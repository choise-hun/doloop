## 1. libtalk이 빠른 이유

| 장치 | 내용 |
| --- | --- |
| 1:1 원스톱 수직 슬라이스 | AI 하나가 DB → API → 화면 → 테스트를 Step 하나로 관통. 주니어 인계·명세 왕복·"파일 7개/700줄" 제한 없음 |
| main 직접 커밋·push | Step마다 로컬 검증 뒤 분리 커밋. PR·CI 대기 없음 |
| 문서 최소화 | 기준 문서 7개 + 상태판 1개(`AI_작업_기록.md`). Step별 명세·결과 파일 없음. `AGENTS.md`·`GEMINI.md`는 10줄짜리 포인터, 규칙 본문은 `CLAUDE.md` 한 곳 |
| Phase 단위 적대적 리뷰 | Phase가 끝나면 **다른 모델**이 명령을 다시 실행하고 공격(동시성·권한·가드 3곳 변형)한다. S1/S2/S3 등급, 같은 모델·같은 세션 리뷰는 관문으로 안 침 |
| 결함 레지스트리 | 발견한 결함(`DEF-*`)을 재발 방지 가드(`H-*`)로 바꿔 누적. 다음 세션이 먼저 읽음 |
| 권한 허용 목록 | `.claude/settings.json`에 git·테스트 명령 허용, force push·`reset --hard` 거부 |

## 3. 추천 — 채택 4건, 비채택 2건

**채택 추천**

1. **시니어 원스톱을 기본으로.** 4단계 주니어 인계는 사용자가 그 작업에 지정했을 때만 쓴다. 시니어가 구현·검증·PR·CI 확인까지 한 세션에서 끝낸다(이번 WF-1이 이 방식). 바꿀 곳: `CLAUDE.md` 첫 줄·"긴 작업"·"병행" 절, `협업_시니어주니어.md` §1.2 배정 표, `문서_운영.md` §6.
2. **Step별 결과 파일을 줄인다.** diff 300줄 미만 Step은 결과 파일을 따로 만들지 않고 진행 파일의 실행 기록 줄에 명령·결과를 적는다. 명세도 계약(API·스키마)·화면 배치가 바뀔 때만 쓴다.
3. **대기능 마감 때 적대적 리뷰 1회.** 마지막 Step PR에서 다른 모델(또는 `/code-review`)이 libtalk 체크리스트 중 doloop에 맞는 4가지를 실행한다: 계약 대조, 요청 경합·취소, 테스트 변형 3곳, 문서-코드 표류. 발견은 새 레지스트리 파일 대신 **기존 `docs/rules/*.md`에 한 줄로** 넣는다(이미 같은 역할).
4. **진입 파일 포인터화 + 권한 허용 목록.** `AGENTS.md`·`GEMINI.md`를 `CLAUDE.md`를 가리키는 짧은 파일로 줄이고, `.claude/settings.json`(지금 없음)에 git·`npm`·`npx playwright`·`./gradlew` 허용과 force push·`reset --hard` 거부를 둔다.

**비채택 추천**

- **main 직접 push**: 운영 중인 서비스라 PR + CI는 유지한다. 대기 시간은 원스톱(인계 없음)으로 이미 줄어든다.
- **시안·정렬규격 생략**: 화면 배치 변경의 `프론트_정렬규격.md` 순서는 실제 깨짐을 잡아 온 장치라 유지한다.
