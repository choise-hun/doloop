# M1A-1 결과 — iOS YouTube 오류 153 보정 실기기 확인

> 2026-11-15 / Mac / 시니어(Claude) + 사용자(실기기 조작). 진행 파일: [진행_M0-1_앱도입](../진행_M0-1_앱도입.md)
> 시험 코드: 버리는 브랜치 `spike/M0-1-ios153`(base `spike/M0-0`, 커밋 `08a7054`, main 미반영). 문서 PR [#36](https://github.com/choise-hun/doloop/pull/36).

## 1. 판정

- **통과.** 우리 쪽 https 페이지에 YouTube 플레이어를 두고 앱(`capacitor://localhost`)에서 그 페이지를 iframe으로 넣는 방식(후보 1)이 iPhone·iPad에서 **T1(오류 153 없이 인라인 재생)·T2(재생·정지·A-B 3회 반복·0.75/1.5배가 iframe 너머로 적용, 현재 시각이 앱으로 돌아옴)** 모두 통과했다(사용자 확인).
- 같은 빌드의 대조군 C0(지금 방식 그대로 앱 번들에서 직접 임베드, `origin=capacitor://localhost`)은 **오류 153이 재현**됐다 → 통과는 방식 차이 때문이다.
- 서버 없이 되는지 본 C2(앱 번들 직접 임베드 + `origin`·`widget_referrer`=`https://com.ulevelp.spike`)는 **153**이었다 → 플레이어 파라미터만으로는 보정되지 않는다.
- 따라서 iOS 원격 로드(B)로 물러설 필요가 없다. **M1A-2에서 후보 1을 운영 방식으로 들인다**(§4, 운영 헤더 변경은 승인 필요).

## 2. 기기와 결과

| 기기 | 모델·OS | 후보 1 T1 | 후보 1 T2 | C0(대조군) | C2 |
| --- | --- | --- | --- | --- | --- |
| iPhone | iPhone18,3 · iOS 27.2.1 | 통과 | 통과 | 153 | 153 |
| iPad | iPad16,1 · iOS 27.2.1 | 통과 | 통과 | 시험 안 함 | 시험 안 함 |

- 시험 영상 `M7lc1UVf-VE`(YouTube IFrame API 공식 예제 영상), 비로그인. 판정은 사용자가 기기에서 직접 본 결과이며 로그·영상 증거는 보관하지 않았다.
- 플레이어 페이지는 **임시 Cloud Run 서비스** `ulevelp-player-spike`(프로젝트 `ulevelp`, `asia-northeast3`, nginx)에 올렸다. 운영 서비스 `ulevelp`·운영 코드·헤더는 바꾸지 않았다. 시험 뒤 서비스·이미지(`ulevelp/player-spike`)를 삭제했다(§5).

## 3. 공식 문서와 원인

| 항목 | 내용 | 출처 |
| --- | --- | --- |
| 오류 153 원인 | 임베드 플레이어(IFrame API 포함)는 `HTTP Referer` 요청 헤더로 사용자를 밝혀야 한다. Referer가 비는 환경은 다른 수단으로 밝혀야 하며, 어기면 기능이 줄 수 있다. 153이라는 번호는 공식 문서에 없다(외부 보고들이 Referer 누락과 연결) | [YouTube RMF](https://developers.google.com/youtube/terms/required-minimum-functionality) |
| WebView 앱 | 로컬 HTML은 `baseUrl`로 Referer를 정하고, 값은 `https://<앱 ID>`(iOS Bundle ID 소문자). Referer를 못 정하면 `origin` 플레이어 파라미터를 쓴다 | 같은 문서 |
| `origin`·`widget_referrer` | `origin`은 IFrame API 보안 수단(자기 도메인), `widget_referrer`는 임베드된 URL(Analytics용) | [Player parameters](https://developers.google.com/youtube/player_parameters) |
| Capacitor iOS | `server.iosScheme`은 `http`·`https`로 정할 수 없다. `server.hostname`은 `localhost` 유지 권장. `server.url`은 운영용 아님 | [Capacitor config](https://capacitorjs.com/docs/config) |

- 해석: `capacitor://` 페이지 안의 하위 iframe 요청에는 https Referer가 붙지 않고, WKWebView에서 하위 요청 헤더를 직접 바꿀 수도 없다. C2 결과로 `origin`·`widget_referrer` 값만 바꿔서는 안 된다는 것도 확인했다. 후보 1에서는 YouTube iframe의 부모가 https 페이지라 Referer가 그 페이지 출처(`Referrer-Policy: strict-origin-when-cross-origin`)로 붙는다.
- WebKit은 `frame-ancestors capacitor://localhost` 같은 custom scheme host-source를 지원했다(iframe이 떴으므로 CSP 일치).

## 4. M1A-2 입력(운영 적용 때 정할 것)

1. **운영 헤더 변경(승인 필요).** 지금 Ktor는 모든 응답에 `X-Frame-Options: DENY`(`src/main/kotlin/ulevelp/Main.kt:334`), HTML에 `frame-ancestors 'none'`(`:436`)을 붙이고 CI 배포 스모크가 `/`에서 이를 검사한다(`.github/workflows/deploy-cloudrun.yml:84-85`). 플레이어 전용 경로 **하나만** `X-Frame-Options`를 빼고 `frame-ancestors capacitor://localhost https://localhost`로 바꾸며, 나머지 경로와 스모크는 그대로 둔다. 그 페이지에는 시험물과 같은 좁은 CSP(`default-src 'none'`, YouTube 스크립트·frame만)를 준다.
2. **메시지 계약.** 부모→플레이어 `{type:'cmd', cmd:'play'|'pause'|'seek'|'rate', value}`, 플레이어→부모 `ready`(가능 배속 포함)·`status`(250ms 간격 `time`·`duration`·`state`·`rate`)·`error`. 양쪽 다 상대 출처를 허용 목록으로 검사한다. 시험물: `spike/ios153/player/player.js`, `spike/ios153/app/index.html`.
3. **PracticePage 연결.** 지금 `playerRef.current`의 동기 호출(`getCurrentTime`·`getDuration`·`seekTo`·`setPlaybackRate`·`cueVideoById`·`playVideo` 등, `frontend/src/pages/PracticePage.tsx:258·434·511·521-580`)을 같은 모양의 어댑터로 감싸고, 시각은 마지막 `status` 값을 쓴다. A-B 반복 정밀도(250ms 간격 영향)는 이번에 재지 않았다.
4. **Android도 같은 방식을 쓸지.** Android는 직접 임베드로 이미 통과했다(M0-0). 코드 경로를 하나로 두려면 Android도 iframe을 쓰고 실기기 재확인이 필요하다. 플랫폼별로 나누면 확인은 줄지만 경로가 둘이 된다 → M1A-2 명세에서 결정.
5. 오프라인 위험은 늘지 않는다(YouTube 재생 자체가 네트워크 필요). 앱 본체는 여전히 번들(A)이다.

**시험하지 않은 것:** 후보 1 상태의 T3~T5(Web Audio·녹음 동시·앱 왕복), Android에서의 후보 1, 운영 도메인 위 동작, 로그인 상태, A-B 반복 정밀도.

## 5. 재현 방법

`spike/M0-1-ios153` 브랜치에서:

```bash
# 플레이어 페이지(임시 Cloud Run). gcloud run deploy --source 는 Cloud Build 기본 서비스 계정 IAM 부족으로 실패했다 → 로컬 빌드·push
cd spike/ios153/player
IMG=asia-northeast3-docker.pkg.dev/ulevelp/ulevelp/player-spike:m1a1
docker build --platform linux/amd64 -t $IMG . && docker push $IMG
gcloud run deploy ulevelp-player-spike --image $IMG --project ulevelp --region asia-northeast3 \
  --allow-unauthenticated --max-instances 1 --memory 128Mi --port 8080
# → https://ulevelp-player-spike-d5ympfsmfq-du.a.run.app (시험 화면 기본값)

# 앱: 시험 화면만 번들
cd ../../.. && CAP_WEB_DIR=spike/ios153/app npx cap sync ios
cd ios/App && xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -destination 'id=<기기 UDID>' DEVELOPMENT_TEAM=<팀 ID> CODE_SIGN_STYLE=Automatic -allowProvisioningUpdates build
xcrun devicectl device install app --device <UDID> <DerivedData>/Build/Products/Debug-iphoneos/App.app
xcrun devicectl device process launch --device <UDID> com.ulevelp.spike

# 정리
gcloud run services delete ulevelp-player-spike --project ulevelp --region asia-northeast3
gcloud artifacts docker images delete $IMG --delete-tags
```

- 무료 Personal Team 프로비저닝 프로필은 2026-11-22에 만료된다. 그 뒤에는 Xcode가 `-allowProvisioningUpdates`로 새로 받는다.
- 실패한 `--source` 시도가 만든 빈 저장소 `cloud-run-source-deploy`와 버킷 `run-sources-ulevelp-asia-northeast3`도 삭제했다.
