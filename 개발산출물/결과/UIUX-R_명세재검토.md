## 2. 항목

### F1 (중요) UXR-1 §6 — `abPair` 참조가 매 렌더 바뀜 → A/B 재생 요청 폐기

- 명세 문구: “슬롯 순서를 바꾸면 `abPair` 참조가 바뀌어 기존 effect가 무효화한다 — 추가 코드 없음.” 이 전제는 **슬롯이 바뀔 때만 참조가 바뀐다**고 가정했다. 실제로는 그렇지 않다.
- 실제 코드:
  - `frontend/src/components/songRecord/SongRecordPanel.tsx:93-96`: `abPair`를 렌더마다 새 배열 `[tA, tB]`로 만든다.
  - `SongRecordParts.tsx:262-278`: `AbCompare`의 `useEffect([abPair])`가 렌더마다 실행되어 `abReqSeqRef`를 올린다.
  - `:304-309`: 진행 중 재생 요청의 `isSlotValid()`가 토큰 불일치로 false가 된다.
- 재렌더 원인:
  - `PracticePage.tsx:1355-1358`: 영상 재생 중 250ms마다 `setCurrentTime` 호출.
  - `:1366`: 녹음 중 50ms마다 `setRecElapsedSec` 호출.
  - `SongRecordPanel`은 memo가 아니라서 부모와 함께 다시 그려진다.
- 사용자 영향: 영상이 재생 중일 때 A 또는 B 재생 버튼을 누르면 URL 발급이나 Drive 다운로드가 끝나기 전에 요청이 버려진다. 소리가 나지 않고 오류 문구도 없다. 영상을 멈춘 상태에서는 정상이다.
- 기원: UXR-1 이전 코드(`d42e28e`)도 `sortAbTakes`로 매 렌더 새 배열을 만들었다. 즉 기존 결함인데, UXR-1 명세가 이를 “문제없음”으로 확정해 놓쳤다. UXR1-7 테스트는 슬롯 교체만 보고 부모 재렌더는 재현하지 않는다.
- 추천 수정(소작업, `fix(record)`):
  - `abPair`를 `useMemo(() => tA && tB ? [tA, tB] : null, [tA, tB])`로 고정한다. `tA`·`tB`는 `takes` 배열 원소라 같은 응답이면 참조가 같다.
  - 테스트를 추가한다: A 재생 URL 응답을 붙잡은 상태에서 부모를 재렌더한다(재생 중 `currentTime` 갱신 또는 강제 상태 변경). 응답을 풀면 `#srAbAudioA`에 src가 할당돼야 한다. 수정 전 Red를 확인한다.
- 같은 패턴 점검: `LogPage.tsx:338`도 IIFE로 매 렌더 새 배열을 만든다. TRAILS 화면은 주기적 재렌더가 없어 증상은 낮지만, 같은 PR에서 함께 고정하는 것을 권장한다.

### F2 RV-6·UXR-2 P5 — hidden 결함 오판(작성: Claude)

- 명세는 “`.field{display:flex}`가 `hidden`을 덮는 실제 결함”이라고 단정했다. 그러나 `frontend/src/styles/tokens.css:175`에 전역 `[hidden]{display:none!important}`가 있어 결함은 없었다.
- 구현 단계에서 발견해 규칙을 추가하지 않았다([UXR-2 결과](UXR-2.md)). 코드 영향은 없다. 상위 명세 RV-6에 정정 표기를 추가했다(이번 세션).
- 교훈: CSS 단정은 계산 스타일 또는 전역 규칙 `git grep "\[hidden\]"`까지 확인한 뒤에 한다.

### F3 CMR-1 §4 — `discover.empty`·`discover.recent` 유지 전제 오류

- 홈은 빈 상태에 줄을 숨기므로 `discover.empty`를 쓰지 않는다. 명세의 “유지” 지시는 I0-6(미사용 키 금지)과 충돌했다.
- 구현 중 삭제로 바로잡고 명세도 고쳤다([CMR-1 결과](CMR-1.md) §4). 남은 영향은 없다.

### F4 상위 §5.3 — `POST /songs` 응답 `created` 필드 가정

- 상위 명세(Codex)는 응답의 `created`로 신규/기존을 구분한다고 가정했다. 서버 본문은 `{song}`뿐이다(`SongRoutes.kt:70-75`).
- 2026-11-11 검토에서 RV-4로 보정했다. CMR-3이 이 보정을 따른다. 코드 영향은 없다.

### F5 상위 §5.5·UR-15 — “CSS columns” 문구 잔존

- RV-8(JS 라운드로빈 열, ≥1150 3열)이 우선이고 구현도 그렇다(`EpisodeLogFeed.tsx:18-34`). 다만 본문이 그대로라 처음 읽는 사람이 오해할 수 있다.
- RV-8 행에 “§5.5·UR-15 대체” 표기를 추가했다(이번 세션).

### F6 상위 §5.2a — 빈 상태 문구 “연습 기록이 없어요” vs CMR-1 키 “연습이 없어요”

- CMR-1이 `community.allEmpty` 값을 확정했고, CMR-2 D15가 이 값을 유지한다. 문구 차이일 뿐 기능 영향은 없다.

### F7 UXR-3 결과 — PL-08·PL-11의 “통과” 근거 부족

- PL-08(분류 수정·가져오기 후 같은 목록 재조회): 근거가 “기존 서랍 기능 유지 및 `renderSongItem` 반영 확인”이다. 재조회를 단언하는 E2E는 없다. 코드에는 재조회 호출이 있다(`PracticePage.tsx:1226`, `:1330`, `:2506`).
- PL-11(접힌 목록 Tab 제외·focus ring): 근거가 UXR3-PL01·02와 다크 레이아웃 통과다. 접힌 본문의 Tab 제외를 직접 단언하지 않는다.
- 처리: 기능 결함 근거는 없다. 결과 표의 판정은 “부분 — 전용 테스트 없음”이 정확하다. 다음 practice 화면 작업이나 F1 수정 PR에서 두 테스트를 보강할 것을 권장한다.

### F8 UXR-1 D2 — “A/B 비교(접기 가능)”를 “선택 0개면 비노출”로 해석

- 명시적 접기 토글을 만들지 않았다. 상위 의도(공간 절약)는 충족하지만 사용자가 직접 접을 수는 없다. 결함은 아니고, 요구가 다시 나오면 소작업으로 다룬다.

### F9 UXR-3 §6 — Drive 안내 “축약 표시” 미적용

- 구현은 스타일만 compact로 바꾸고 문구는 유지했다(진행 파일 §8.1에 기록됨). 의미 보존 조건은 충족한다. 결함은 아니다.

## 3. 상위 보정이 반복된 이유

- 보정은 모델 교체가 아니라 **실제 코드·DTO 대조 시점의 차이**에서 나왔다. 상위 명세(2026-11-10, Codex)는 화면 의도를 정한 문서이고 서버 DTO를 모두 열어 보지는 않았다. 세부 명세 단계에서 DTO를 열 때마다 어긋남이 드러났다(RV-4 `created`, CMR-3 D15 길이 필드, 딥링크 부재).
- 오류는 작성 모델과 무관하게 나왔다. F2는 Claude가 만든 오판이고, F1은 Claude가 쓴 UXR-1 명세가 기존 결함을 놓친 경우다. 앞으로 세부 명세의 전제 표(P#)는 다음 세 가지를 확인하도록 강화한다.
  - CSS 단정은 전역 규칙까지 본다.
  - “참조/effect가 X일 때만 바뀐다” 같은 React 단정은 부모 재렌더 원인까지 본다.
  - 응답 필드는 서버 DTO 원문으로 본다.
