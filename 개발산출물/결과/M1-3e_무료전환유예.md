# M1-3e 결과 — 유료 → 무료 전환 유예(주기 끝까지 유료와 같게)

- **날짜:** 2026-11-06 (win) · 브랜치 `feat/m1-3e-credit-grace` (base main)
- **입력:** `결과/M1-3d_크레딧주기.md` §1(D5·D6), `계획/상용_서비스_계획.md` §3-2, 사용자 결정(2026-11-06)
- **계기:** "무료 전환 계정의 남은 월 크레딧 소멸 안내"(`/credits` 필드 추가) 제안을 검토하다가, D5("남은 월 지급분은 주기 끝까지 쓸 수 있다")가 **실제로는 불가능**함을 발견 — 무료는 `ai=false`라 분석이 크레딧 확인 전에 403, 재가입은 남은 잔액을 소멸하고 새로 지급. 사용자 결정: **일반 구독 해지처럼 다음 결제일(주기 끝)까지 Pro와 같은 상태를 유지하고, 그때 남은 월 지급분을 소멸**

## 1. 규칙

| # | 규칙 |
| --- | --- |
| G1 | **실제 티어 = 기준 티어(billing·override) + 유예.** 기준 티어가 무료여도 `credit_cycle_next_at > 지금`이고 `credit_cycle_tier`가 유료면 실제 티어 = `credit_cycle_tier`. 곡·분류·녹음·Drive·AI 한도와 `/me` `tier`·`limits`, 관리 API 응답 `tier`가 모두 이 값 |
| G2 | **유예 끝 = 충전 시각.** 그 시각부터 실제 티어 = 무료(cron 전이어도 시각으로 판정). `monthly-credits` cron이 남은 월 지급분 소멸 + 주기 종료 + **다운그레이드 정리**(학습 기록 공유 끄기·저장소 서버로)를 한 트랜잭션에서 |
| G3 | **다운그레이드 정리는 유예 끝으로 미룬다.** 관리 API로 무료 지정·override 해제, `tier-expire`의 override 만료 모두 주기가 남아 있으면 정리하지 않는다 |
| G4 | **유예 중 재가입 = 해지 취소.** 주기·충전 시각·잔액 그대로, 새 지급 없음(실제 티어가 유료 → 유료라 `topUpCreditCycle`, 차액 0). Pro로 유예 중 Pro+로 올리면 차액만 즉시. (M1-3d D6 "앞 잔액 소멸 + 새 주기"를 대체) |
| G5 | 주기가 끝난 뒤(무료) 재가입은 그 시각에 새 주기(M1-3d D1 그대로) |
| G6 | `GET /credits`: `monthlyGrant`·`nextGrantAt`은 **다음 충전 기준 = 기준 티어**(유예 중 0·null). 새 필드 **`monthlyExpiresAt`** = 유예 중일 때 유예 끝 시각(ISO), 아니면 null. 잔액이 0이어도 유예 중이면 값이 있다(무료로 바뀌는 날 안내용) |
| G7 | 설정 화면: 유예 중이면 다음 지급 줄 대신 `#creditExpire` "M월 D일에 무료 플랜으로 바뀌어요 · 남은 월 지급 N크레딧은 그때 사라져요"(월 지급 잔액 0이면 뒷부분 없음). 유예 계정은 `/me` tier가 유료라 `/credits`를 그대로 부른다 |

**한계(그대로 둠):** `credit_cycle_tier`는 그 주기에 지급한 가장 높은 티어를 기억한다(D3). Pro+ → Pro(유료끼리) → 무료로 내리면 유예 티어는 Pro+다. 유료끼리 내릴 때(Pro+ → Pro)는 지금도 즉시 적용된다(M1-3d D4). 결제(M4-2)가 붙으면 "결제된 티어"로 다시 정한다.
