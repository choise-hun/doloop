## 1. 티어

### 1-1. 실제 티어

```
실제 티어 = tier_override  (tier_override IS NOT NULL AND (tier_override_until IS NULL OR tier_override_until > now()))
         | billing_tier   (그 밖)
```

- `billing_tier`: 결제가 정하는 값. M4-2 전까지 늘 `free`. 결제 웹훅은 이 열만 바꾸고 override는 건드리지 않는다
- `tier_override`·`tier_override_until`: owner 관리 API만 바꾼다. `until` NULL = 기한 없음
- 서버 코드는 한 함수(`TierService.effectiveTier`)로만 계산. SQL로 걸러야 하는 곳(공개 목록)은 같은 식을 쓴다:
  `COALESCE(CASE WHEN p.tier_override IS NOT NULL AND (p.tier_override_until IS NULL OR p.tier_override_until > now()) THEN p.tier_override END, p.billing_tier)`

### 1-2. 한도 (코드 상수 `TierLimits`, DB에 넣지 않음)

| | free | pro | pro_plus |
| --- | --- | --- | --- |
| 곡 | 10 | 100 | 150 |
| 분류 | 2 | 7 | 10 |
| 서버 녹음 총량 | 5,242,880 (5MB) | 104,857,600 (100MB) | 209,715,200 (200MB) |
| 서버 녹음 곡 수(`DISTINCT song_id`) | 2 | 제한 없음 | 제한 없음 |
| 녹음 한 개 길이 | 120초 | 제한 없음(파일 50MB 유지) | 제한 없음(파일 50MB 유지) |
| Drive | 불가 | 허용 | 허용 |
| AI 분석 | 불가 | 크레딧 | 크레딧 |
| 커뮤니티 쓰기(게시·자동 연동·학습 기록 공유·복제) | 불가(열람·팔로우·좋아요·신고·곡 1개 담기만) | 가능 | 가능 |
| 월 지급 크레딧 | 0 | 설정값 `CREDITS_MONTHLY_PRO`(M1-3에서 계산) | 설정값 `CREDITS_MONTHLY_PRO_PLUS` |

- 한도 비교는 "추가하려는 순간"에만 한다(다운그레이드 데이터는 유지, Q8). 이미 11곡인 무료 계정은 곡을 지워 10 미만이 될 때까지 추가 불가
- 같은 `video_id` 곡이 이미 있으면(업서트) 새 곡이 아니므로 한도를 쓰지 않는다
- 녹음 곡 수·총량은 `storage = 'supabase'` 녹음만 센다(Drive 녹음은 사용자 드라이브)

### 1-3. 다운그레이드 (실제 티어가 유료 → free, Q8)

| 언제 | 무엇을 |
| --- | --- |
| 관리 API로 override를 바꾼 그 트랜잭션 | 아래 "정리" |
| 매일 0시 5분(KST) cron `POST /internal/cron/tier-expire` | 기한 지난 override를 NULL로 바꾸고, 실제 티어가 free가 된 계정에 "정리" |
| 그 사이(만료 ~ cron) | 공개 목록 SQL이 실제 티어를 계산해 무료 소유자 폴더를 빼고, 자동 연동은 쓰기 직전에 소유자 티어를 확인해 건너뜀 |

- **정리** = `profiles.share_practice_log=false`(A8, M1-2a) + 그 사용자의 `shared_folders(kind='user')`를 `is_public=false, auto_sync=false`(M1-4가 같은 함수 `TierService.downgradeCleanup`에 더한다). 행·공개본·좋아요는 남는다 → 재구독 뒤 "다시 게시"하면 다시 보인다
- 곡·분류·녹음·노트는 그대로. Drive 녹음은 재생 유지, `storage_provider='drive'`인 무료 계정의 새 업로드는 서버 저장(무료 한도)으로 받는다

## 2. V5 SQL (M1-2a가 그대로 옮긴다)

### 2-1. V5 (확정)

```sql
-- V5__tiers_credits_and_community.sql
-- 티어·크레딧·관리 감사 + 커뮤니티용 profiles 열 (개발산출물/결과/M1-1_스키마설계.md).
-- 커뮤니티 테이블은 M1-4 마이그레이션, BYOK 키 삭제는 M1-3 마이그레이션

-- ============================================================
-- 1. profiles 확장
-- ============================================================
ALTER TABLE profiles
  ADD COLUMN billing_tier        TEXT NOT NULL DEFAULT 'free' CHECK (billing_tier IN ('free', 'pro', 'pro_plus')), -- 결제가 정하는 티어(M4-2 전까지 free)
  ADD COLUMN tier_override       TEXT CHECK (tier_override IN ('free', 'pro', 'pro_plus')),                     -- owner 관리 API 전용
  ADD COLUMN tier_override_until TIMESTAMPTZ,                                                                     -- NULL = 기한 없음
  ADD COLUMN monthly_credits     INTEGER NOT NULL DEFAULT 0 CHECK (monthly_credits >= 0),                        -- 월 지급분(다음 지급 때 소멸)
  ADD COLUMN purchased_credits   INTEGER NOT NULL DEFAULT 0 CHECK (purchased_credits >= 0),                      -- 구매·보상분(소멸 없음)
  ADD COLUMN locale              TEXT CHECK (locale IN ('ko', 'en', 'ja')),                                       -- NULL = 아직 고르지 않음(화면 자동)
  ADD COLUMN is_creator          BOOLEAN NOT NULL DEFAULT false,                                                  -- owner 지정
  ADD COLUMN creator_badge       TEXT CHECK (char_length(btrim(creator_badge)) BETWEEN 1 AND 20),
  ADD COLUMN creator_bio         TEXT NOT NULL DEFAULT '' CHECK (char_length(creator_bio) <= 200),
  ADD COLUMN share_autosync      BOOLEAN NOT NULL DEFAULT false,                                                  -- 설정 "연습 리스트 공유 자동 연동"
  ADD COLUMN share_practice_log  BOOLEAN NOT NULL DEFAULT false,                                                  -- 학습 기록 공유 동의
  ADD CONSTRAINT profiles_override_until_chk CHECK (tier_override_until IS NULL OR tier_override IS NOT NULL);
CREATE INDEX profiles_override_until_idx ON profiles (tier_override_until) WHERE tier_override IS NOT NULL;
CREATE INDEX profiles_creator_idx ON profiles (id) WHERE is_creator;

-- ============================================================
-- 2. analysis_jobs 과금 열 (M1-3이 채운다. 기존 행은 0/NULL = 과금 없음)
-- ============================================================
ALTER TABLE analysis_jobs
  ADD COLUMN reserved_monthly   INTEGER NOT NULL DEFAULT 0 CHECK (reserved_monthly >= 0),
  ADD COLUMN reserved_purchased INTEGER NOT NULL DEFAULT 0 CHECK (reserved_purchased >= 0),
  ADD COLUMN charged_credits    INTEGER CHECK (charged_credits >= 0),            -- 정산 확정액. NULL = 미정산
  ADD COLUMN prompt_tokens      INTEGER CHECK (prompt_tokens >= 0),              -- usageMetadata.promptTokenCount
  ADD COLUMN output_tokens      INTEGER CHECK (output_tokens >= 0),              -- candidatesTokenCount
```

## 3. 크레딧 흐름 (M1-3 구현, 스키마는 V5)

| 시점 | 트랜잭션 안에서 | 원장 행 |
| --- | --- | --- |
| 작업 생성 | 프로필 `FOR UPDATE` → 실제 티어 free면 403 → 예약액 = `ceil(예상입력/4000 + 출력상한/1000)` → 잔액(월+구매) < 예약액이면 402 → **월 지급분부터** 뺀다 → `analysis_jobs.reserved_*` 기록 | `reserve` 음수, 버킷마다 한 행 |
| 완료 | 실제 = `ceil(prompt/4000 + (output+thoughts)/1000)` → 차액 반환(구매분부터 되돌림 — 소멸 없는 쪽 우선). 실제 > 예약이면 잔액 안에서만 더 빼고 모자라는 만큼은 받지 않는다(로그) → `charged_credits`·토큰·`model_version` 기록 | `settle` (+ 반환 / − 추가), 버킷마다 |
| 실패(Gemini 오류·시간 초과) | 예약 전액 반환 | `refund` 양수 |
| 매월 1일 0시 KST cron `POST /internal/cron/monthly-credits` | 계정마다: 남은 월 지급분 소멸 → 실제 티어 유료면 지급(Pro/Pro+ 설정값) | `monthly_expire`(period=지난달) → `monthly_grant`(period=이번 달). 유니크 인덱스로 재시도해도 한 번 |
| 관리 API 지급·차감 | `|delta| ≤ 1000`, 결과 잔액 ≥ 0, `admin_audit` 먼저 쓰고 그 id를 원장에 | `admin_adjust` |

- 불변식(테스트마다): 버킷별 `SUM(delta) = profiles.<버킷>_credits`, 모든 `balance_after ≥ 0`
- 예상 입력 = 텍스트 818 + 구간 초 × 초당 토큰(보통 ~91, 빠름 2.4배, 느림·노트 0.2fps는 M1-3 실측). 구간이 없으면 영상 길이(YouTube Data API, A12)
- 출력 상한 = `maxOutputTokens`(M1-3에서 정함). 스트리밍 중도 차단은 하지 않는다(§3-2)
- 동시 1건 제한(`MAX_CONCURRENT_JOBS_PER_USER = 1`)·하루 20건(`DAILY_LIMIT_PER_USER`)은 유지

## 4. 자동 연동(§3-3) — 어디서 다시 복사하나

- 함수 하나: `SharedFolderSync.resyncCategories(tx, userId, categoryIds)` — 그 분류 중 `auto_sync=true`이고 소유자 실제 티어가 유료인 공개본만, **같은 트랜잭션에서** 항목을 `video_id` 기준으로 업서트·빠진 것 삭제·순서 갱신(좋아요 유지), 제목은 분류 이름으로(N1이 프리셋이면 고른 프리셋 그대로), `published_at=now()`
- 순서 = 원본 분류 화면의 곡 순서(M1-4에서 `SongService` 목록 정렬을 그대로 쓴다)
- 부르는 곳(M1-4가 빠짐없이 연결하고 테스트로 확인):

| 서비스 | 바뀌는 것 |
| --- | --- |
| `SongService.create`·`update`(제목·아티스트·a·b·rate·분류)·`delete`·`migrateLocal`·`replaceCategories` | 곡이 속한 분류 |
| `CategoryService.update`(이름)·`delete` | 그 분류(삭제는 FK가 공개본도 지움) |
| `ExportImportService` 노션 백업 가져오기 확정, `NotionSyncService` pull — 둘 다 화면 은닉·동결 기능이지만 API가 살아 있어 곡을 바꿀 수 있다 | 바뀐 곡의 분류 |
| 재생목록 가져오기(M1-2b), 폴더 복제(M1-4) | 넣은 분류 |

- `share_autosync`를 끄면 그 사용자의 모든 `auto_sync=false`(마지막 공개본은 남음). 켜져 있어야 폴더별 `auto_sync=true`를 받는다(아니면 409 `SHARE_AUTOSYNC_OFF`)

| HTTP | code | 언제 | `detail` |
| --- | --- | --- | --- |
| 401 | `UNAUTHORIZED` | 토큰 없음·잘못됨 | — |
| 403 | `FORBIDDEN` | `/admin/*`를 owner 아닌 사람이 | — |
| 403 | `TIER_UPGRADE_REQUIRED` | 무료가 AI·Drive·커뮤니티 쓰기 | `{feature, tier, nextTier}` |

| 403 | `CATEGORY_LIMIT_EXCEEDED` | 분류 한도 | `{limit, used, tier, nextTier, nextLimit}` |
| 403 | `FREE_TAKE_SONG_LIMIT_EXCEEDED` | 무료 녹음 3번째 곡 | `{limit, used, tier, nextTier, nextLimit}` (`nextLimit` null = 제한 없음) |
| 403 | `TAKE_DURATION_LIMIT_EXCEEDED` | 무료 녹음 120초 초과 | `{limitSec, tier, nextTier}` |
| 413 | `TAKE_QUOTA_EXCEEDED` | 녹음 총량(기존 코드·상태 유지) | `{limitBytes, usedBytes, tier, nextTier, nextLimit}` |

| 409 | `DISPLAY_NAME_REQUIRED` | 이름 없이 게시(A17) | — |
| 409 | `ALREADY_REPORTED` | 같은 폴더 열린 신고 중복 | — |
| 404 | `PLAYLIST_NOT_FOUND` | 재생목록 없음·비공개 | — |

- 남의 자원은 지금처럼 404. 기존 `RATE_LIMITED`(429)·`NO_KEY`(412, M1-3에서 사라짐)는 그대로/정리
- `detail`은 선택 필드(A10). `ApiErrorResponse`에 `val detail: JsonObject? = null` 추가
- **업그레이드 안내(A4)**: `nextTier` = 지금 실제 티어 바로 위(`free`→`pro`, `pro`→`pro_plus`, `pro_plus`→`null`), `nextLimit` = 그 티어의 같은 한도(없으면 `null`). 화면은 `nextTier`가 있으면 "더 많은 … 칸을 쓰려면 업그레이드"를 보여 결제로 보내고, `null`이면 단순 안내만

## 8. 이 설계의 실행 확인 (2026-11-05, 임시 `postgres:16-alpine` 컨테이너)

- (승인 전 원안, 커뮤니티 테이블 포함) §2 SQL을 문서에서 그대로 뽑아 V1~V4 뒤에 적용 → 오류 없음, `public` 테이블 **21개**. 승인 뒤 V5 = §2-1(17개)은 M1-2a가 Testcontainers로 다시 확인한다
- 잘못된 입력은 모두 거부: `billing_tier='gold'`, override 없이 `until`만, 잔액 −1, `monthly_grant`에 `period` 없음, 같은 달 월 지급 중복(`credit_ledger_period_uq`), `period='2026-13'`, 남의 분류로 user 폴더(복합 FK), 비공개인데 `auto_sync`, 운영자 폴더에 `owner_id`, user 폴더에 분류 없음, 같은 달 `monthly_pick` 중복, `month`가 15일, 항목 `a ≥ b`, 자기 팔로우, 열린 신고 중복, 감사 사유 공백
- 정상 입력 성공 + **원본 분류 삭제 → 공개본·항목·신고 0건**(CASCADE, A9)
- 처음 쓴 CHECK `(kind='user') = (owner_id IS NOT NULL AND source_category_id IS NOT NULL)`는 운영자 폴더에 `owner_id`만 넣은 행을 통과시켰다 → 열마다 하나씩 두 CHECK로 고침(위 SQL이 고친 것)
