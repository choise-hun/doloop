## 3. 출력 상한 `maxOutputTokens` = **8192**

- 실측 출력 최대 = **2400**(N2). GA-3 포함 11건 범위 1215~2400. 출력은 태그 수보다 영상 내용에 따라 달라진다(태그 1개 N2가 6개 N1보다 많음)
- 8192 = 최대 실측의 약 3.4배. Gemini 3 계열은 생각 토큰도 `maxOutputTokens` 안에서 쓰므로 여유를 크게 잡았다. 모델 상한(65536)보다 훨씬 작아 예약액을 키우지 않는다
- 예약액에서 출력 몫 = 8192/1000 = 8.2크레딧. 실제 출력 몫은 1.2~2.4크레딧이라 정산 때 6~7크레딧쯤 돌려준다
- **M1-3b에 넘길 것:** 잘리면 응답 `finishReason: "MAX_TOKENS"` + 끝이 잘린 JSON → 지금 코드는 "JSON 파싱 실패"로 작업 실패 → 예약 전액 반환. M1-3b에서 `MAX_TOKENS`를 따로 알아보고 로그·`error`에 남길 것(상한을 다시 볼 근거)

## 4. 1크레딧 원가

### 4-1. 단가 (공식 페이지 `https://aistudio.google.com/docs/pricing` — `ai.google.dev/gemini-api/docs/pricing`에서 301, 2026-11-05 확인)

Gemini 3.8 Flash, Standard 유료 등급, 100만 토큰당:

| | ~2026-12-31 | **2027-01-01~** |
| --- | --- | --- |
| 입력(텍스트·이미지·영상) | $0.75 | **$1.50** |
| 출력(생각 토큰 포함) | $3.75 | **$7.50** |

- 오디오 입력 단가 줄은 따로 없다. 문맥 길이별 단가 구간도 없다
- **2027-01-01부터 두 배.** 결제(M4-2)가 붙는 시점은 그 뒤일 것이므로 **2027 단가로 계산**한다

### 4-2. 1크레딧이 사는 토큰

- 1크레딧 = 입력 4000토큰 **또는** 출력 1000토큰(Q4 산식)
- 2027 단가: 입력 4000 × $1.50/1M = $0.0060, 출력 1000 × $7.50/1M = **$0.0075** → 둘 중 큰 값 **$0.0075**를 1크레딧 원가의 위쪽 경계로 쓴다(올림 때문에 실제로는 더 싸다)
- 실측 확인: §2의 8건을 2027 단가로 계산하면 1크레딧당 $0.0057~$0.0068 → 모두 $0.0075 이하

### 4-3. 환율

| 출처 | 값 | 기준 |
| --- | --- | --- |
| `open.er-api.com/v6/latest/USD` | 1,340.31 | 2026-11-05 00:02 UTC |
| `api.frankfurter.dev/v1/latest?from=USD&to=KRW`(ECB) | 1,338.58 | 2026-11-04 |

- **계산에 쓰는 환율 = 1,500원/$** — 오늘 값(≈1,339)보다 약 12% 위, 52주 최고(1,588)에 조금 못 미치는 버퍼. 환율이 올라도 마진 50%가 깨지지 않게
- 1크레딧 원가 = $0.0075 × 1,500 = **11.25원**

## 6. M1-3b가 코드에 넣을 값

| 이름(제안) | 값 | 위치(제안) |
| --- | --- | --- |
| 고정 모델 | `gemini-3.8-flash` | `NoteService`/`GeminiClient` 상수. `notes.model`·`analysis_jobs.model_version`에도 이 값(응답 `modelVersion`) |
| `maxOutputTokens` | 8192 | `HttpGeminiClient` `generationConfig` |
| 텍스트 토큰(예상 입력) | 818 | 예약 계산 상수 |
| 초당 토큰(예약용) | 노트 39, 느림 58, 보통 92, 빠름 221 | `PACE_FPS` 옆 표 |
| 예약 산식 | `ceil((818 + 초 × 초당)/4000 + 8192/1000)` | `CreditService` |
| 정산 산식 | `ceil(prompt/4000 + (output + thoughts)/1000)` | `CreditService` |
| 월 지급 | Pro 170 · Pro+ 350 · free 0 | `TierLimits` |

예약액 예(산식 그대로, 정산 예상은 출력 2400 가정):

| 요청 | 예약 | 정산 예상 |
| --- | --- | --- |
| 노트 10분 | 15 | 9 |
| 노트 17분 | 19 | 13 |
| 코드 진행 보통 4분 | 14 | 9 |
| 코드 진행 빠름 4분 | 22 | 16 |
| 코드 진행 느림 4분 | 12 | 7 |
| 코드 진행 보통 24초 | 9 | 4 |

- 구간이 없으면 `초` = YouTube `videos.list?part=contentDetails`의 `duration`(ISO 8601, 예 `PT8M11S`). 이 키로 실제 호출해 `PT24S`·`PT8M11S`·`PT17M8S`를 받았다
- 잔액이 예약액보다 적으면 402(설계 §3). 노트 15크레딧 예약이면 Pro 170에서 월 11건까지는 막히지 않고, 정산으로 돌려받아 실제로는 약 18건
