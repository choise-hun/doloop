## 1. 배치 약속 (구현 전에 씀)

| 항목 | 내용 |
| --- | --- |
| 상태 | 기존 `guest`·`user`·`userData`·`pro` + **`retry`**(Pro, 실패한 노트 작업 1건 → 재시도 버튼을 눌러 옵션 패널이 열리고 구간·메모가 채워진 상태, 예상 크레딧 보임) |

## 3. 결정

| # | 결정 | 이유 |
| --- | --- | --- |
| C-1 | **재시도 = 폼 복원까지, 요청은 사용자가 `분석 요청`으로 한 번** | 같은 값으로 바로 다시 보내면 `GEMINI_MAX_TOKENS` 등은 같은 이유로 또 실패하고 크레딧을 또 예약한다. 앱 명세 "바로 **수정** 재요청" — 한 번 눌러 링크·태그·메모·구간이 다 돌아오고 시작 칸에 포커스. 서버에 재시도 경로는 없다(M2-1s §2) |
| C-2 | 재시도 버튼은 **실패한 노트 작업에만**(`kind !== 'progression'`) | `/notes/jobs`에 코드 진행 작업도 섞여 나온다(M2-1s §3). 코드 진행은 속도(pace)가 있어 노트 폼에 채우면 값이 사라진다 |
| C-3 | 버튼 문구: `GEMINI_MAX_TOKENS`면 "구간 줄여서 다시 시도", 그 밖 "다시 시도" | 분량 초과만 구간을 줄이는 게 답. 붐빔·한도 오류에 "구간 줄여서"는 틀린 안내 |
| C-4 | 복원 태그는 폼에 있는 태그만 폼 순서로, 하나도 없으면 기본(화성) | 폼에 없는 태그는 토글할 수 없어 보낼 수도 없다 |
| C-5 | 잘못된 구간이면 예상 크레딧을 묻지 않고 배지를 숨긴다(칸 아래 안내가 대신) | 서버 400을 일부러 부르지 않는다. 요청 버튼은 막지 않고 제출 때 막는다(문구 = 칸 안내와 같음) |
| C-6 | 구간 칸에 `inputMode="numeric"`을 **쓰지 않음**(CHORDS 폼과 다름) | iOS 숫자 키패드에 `:`가 없어 placeholder의 `1:20`을 칠 수 없다 |
| C-7 | 토글 문구 "+ 구간 · 메모 옵션"(앱 명세 "구간 지정 · 메모 옵션"에서 "지정" 뺌) | 390 폼 안쪽 폭에서 "(입력함)"까지 붙는 가장 긴 문구를 짧게 둔다(긴 문구로 두 줄이 되는지는 재지 않음). 지금 문구는 필 한 줄 검사 390·768·1280 통과 |
