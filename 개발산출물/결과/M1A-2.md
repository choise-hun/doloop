## 3. 명세와 다르게 한 것 (6건)

1. `public/config.js`를 커밋 ③이 아니라 ①에 포함 — `scripts/build-app-web.mjs`가 기본 `playerEmbedUrl`을 `public/config.js`에서 읽으므로 커밋 ①만으로 `npm run build:app`이 동작하도록 앞당김.
2. Kotlin 테스트 이름을 `Z4`·`Z5` 대신 `M1A2-Z4`·`M1A2-Z5`로 명명 — `src/test/kotlin/ulevelp/ChordEngineTest.kt`에 이미 기존 `Z4`·`Z6`이 존재하여 이름 충돌 회피.
3. `.github/workflows/deploy-cloudrun.yml` 스모크의 XFO 없음 검사를 `! curl … | grep -qi` 대신 변수 캡처(`PLAYER_HEADERS`) 후 `if echo "$PLAYER_HEADERS" | grep -i "^x-frame-options"; then … exit 1; fi`로 구현 — bash `set -e`에서 `!` 명령 실패로 중단되지 않고 `pipefail`+`grep -q`가 SIGPIPE로 검사를 놓칠 수 있는 문제를 피함.
4. `public/player-embed.html`에 웹 공통 CSP `<meta>`를 유지하고 `<style>` 태그 대신 JS(`public/player-embed.js` 인라인 CSSOM 속성)로 `100%`/`#000`/`margin: 0` 설정 — `test/security.test.js`가 `public/*.html`마다 웹 CSP `<meta>` 1개와 `<style>` 부재를 요구함(목록 밖 테스트 수정 금지). 이에 따라 응답 헤더 `PLAYER_EMBED_CSP`와 `<meta>` CSP가 동시 적용되며, 두 정책의 조합에서 iPhone·iPad A5 실기기 재생 통과(§4, 2026-11-16 사용자 확인).
5. `test/e2e/remote-player.spec.js`(R1)의 HTML CSP `frame-src` 덧붙이기를 spec 내부 헬퍼(`addFrameSrcOrigin`)로 직접 처리 — Playwright worker 내부에서 `.mjs` 동적 import가 정지하는 현상 회피. 실제 `scripts/build-app-web.mjs`의 `addFrameSrcOrigin`은 `test/app_web_bundle.test.js` B4가 검증.
6. `frontend/src/lib/ytBridge.ts`의 개발자용 문자열(`console.warn`, `Error`)을 영어로 작성 — `test/i18n.test.js` LA-1(한글 잔존 0) 준수.
