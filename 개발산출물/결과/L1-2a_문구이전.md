## 6. 문제 해결 및 겪은 점

1. **`import type` 파싱 문제 in `test/r1_home.test.js`**:
   - `import { t, type I18nKey }` 구문 사용 시 Node 내장 vm/정규식 변환기에서 파싱 실패 발생.
   - `import type { I18nKey } ...`와 `import { t } ...`로 분리하여 해결.
2. **`PracticePage.tsx` 내부 `t` 변수 섀도잉**:
   - `uploadTakeNow` 함수 내부에서 `const t = opts?.targetTake || takeRef.current;`로 선언된 변수로 인해 i18n `t()` 함수 호출이 가려져 `TS2349: This expression is not callable. Type 'PendingTakeState' has no call signatures` 발생.
   - 변수명을 `tk`로 변경하여 해결.
3. **I0-3 키 형식 정규식(`[a-z]+(\.[a-z][A-Za-z]*)+`)과 숫자 포함 키**:
   - `practice.ariaRewind5s`, `practice.ariaForward5s` 키에 숫자가 포함되어 I0-3에 위배됨.
   - `practice.ariaRewind`, `practice.ariaForward`로 변경하여 해결.
4. **`test/ch6_stats.test.js:116` 정규식 호환성**:
   - `progressions.ts`의 시드 데이터에서 `title`과 `keyLabel`이 한 줄에 유지되어야 정규식 매칭이 성립됨.
   - `// i18n-keep: 기본 시드 데이터(D5-3)` 마커를 줄 끝에 배치하여 LA-1을 통과하면서 테스트 정규식도 유지.
