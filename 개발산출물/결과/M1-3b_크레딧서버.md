## 2. API (M1-1 §5-4 그대로 + 아래 §3 결정)

| 경로 | 응답 |
| --- | --- |
| `POST /notes/analyze`·`POST /progressions/analyze` | 202 `{jobId, status, reservedCredits}`. 무료 403 `TIER_UPGRADE_REQUIRED` `detail{feature:"ai",tier,nextTier}`, 부족 402 `INSUFFICIENT_CREDITS` `detail{required,balance}` |
| `GET /notes/jobs`·`/notes/jobs/{id}` | 작업에 `reservedCredits`(int), `chargedCredits`(null = 미정산, 실패 = 0), `promptTokens`·`outputTokens`·`thoughtsTokens`(완료만, 아니면 null) |
| `GET /credits` | `{monthly, purchased, total, monthlyGrant, nextGrantAt}` — `nextGrantAt` = 다음 달 1일 00:00 KST(ISO instant), 월 지급 0이면 null |
| `GET /credits/ledger?before=&limit=` | `{rows:[{id,bucket,delta,balanceAfter,reason,jobId,createdAt}], next}` 최근 순, 기본 50·최대 200, `next` = 다음 페이지 `before`(없으면 null). 잘못된 `before`·`limit` 400 |
| `POST /credits/estimate` | `{kind, url, startSec?, endSec?, pace?}` → `{estimatedCredits, reserveCredits}`. 노트는 구간·속도 무시(분석 요청과 같게). 무료도 부를 수 있다(배지용) |
| `POST /internal/cron/monthly-credits` | `{period, users, expired, granted}` |

| B9 | gemini 연동 경로 3개는 **400 `INVALID_INPUT`**("지원하지 않는 연동…"), 다른 모르는 공급자는 **404 유지** | M1-1 §5-4. 기존 404 동작을 넓게 바꾸지 않음 |

## 5. 겪은 문제

- **월 지급 재실행 버그(배포 전 발견):** 첫 구현은 소멸 조건이 "남은 월 지급분 > 0 이고 지난달 소멸 기록 없음"뿐이라, 같은 달에 cron을 다시 돌리면(Scheduler 재시도) 그 달에 막 준 170을 "지난달 소멸"로 지웠다. CreditApiTest C1·C2를 쓰면서 시나리오로 확인 → "이번 달 지급 기록이 있으면 소멸도 건너뜀"(B7)으로 고친 뒤 실행해 통과
- `IntegrationApiTest`의 잘못된 IV 테스트가 `provider='gemini'`로 넣고 있어 V6 뒤에도 23514로 "통과"했을 것(원인이 바뀐 채) → `notion`(`guitar-practice` 앱)으로 바꾸고 gemini 거부는 따로 단언

## 6. M1-3c(화면)에 넘길 것

- `/me` `keys.gemini` 없음 → 분석 버튼 판단은 `limits.ai`(무료 false). 크레딧 잔액은 `/me` `credits{monthly,purchased}` 또는 `GET /credits`
- 오류 안내: 403 `TIER_UPGRADE_REQUIRED`(`detail.feature = "ai"`, `nextTier`) → 업그레이드, 402 `INSUFFICIENT_CREDITS`(`detail.required`·`balance`), 503 `GEMINI_UNAVAILABLE`, 404 `VIDEO_NOT_FOUND`, 400(라이브·시작 ≥ 길이). 412 `NO_KEY`는 분석에서 더 나오지 않는다
- 작업 실패 `error` 앞 코드: 새 `GEMINI_MAX_TOKENS`("구간을 줄여 다시"), `PROVIDER_KEY_INVALID`·`GEMINI_BILLING`은 이제 **서버 쪽 문제**라 "키를 확인하세요" 대신 "잠시 뒤 다시 / 운영자 문의" 문구(B10)
- 202 응답 `reservedCredits`, 작업 `chargedCredits`로 "n크레딧 사용(예약 m)" 표시 가능. 예상 배지는 `POST /credits/estimate`(M2-1)
- `PUT /integrations/gemini` 등은 400 → 설정의 Gemini 칸·키 발급 모달 삭제(진행 파일 M1-3c 줄)

## 7. 나중에 (인수인계 "나중에" 후보)

- `running`에서 멈춘 작업(Job 강제 종료)은 예약을 계속 잡고 있다 — 지금도 상태가 영영 running인 문제와 같음. 일정 시간 지난 running을 failed + 반환하는 정리 cron 후보
- `CryptoService`의 Gemini 키 형식 검사(`GEMINI_API_KEY_REGEX`, provider `gemini` 분기)는 쓰는 곳이 없어졌다 — 지워도 되지만 이 step 범위 밖
- `GEMINI_FRAME_FPS` env를 바꾸면 노트 초당 토큰(39)이 맞지 않는다 — 바꿀 때 `CreditMath.TOKENS_PER_SEC_NOTE`도 다시 실측
- 가격 확정(B-0) 때 월 지급량 재계산(M1-3a §5 — 부가세·수수료 미반영)
