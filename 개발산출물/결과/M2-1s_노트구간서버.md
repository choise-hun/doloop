## 2. M2-1c가 쓸 API (확정)

- `POST /api/v1/notes/analyze` `{ url, tags, memo?, startSec?, endSec? }` — `startSec`·`endSec` 정수 0~86400, `endSec > (startSec ?: 0)`. `null` = 없음. `pace`는 보내도 무시
- `POST /api/v1/credits/estimate` `{ kind: "note", url, startSec?, endSec? }` → `{ estimatedCredits, reserveCredits }` — 구간이 있으면 줄어든다
- 작업 DTO(`GET /notes/jobs`·`/notes/jobs/{id}`): `memo`(없으면 `""`), `startSec`·`endSec`(노트도 채워짐), `tags`, `url`(정규화 `https://www.youtube.com/watch?v=<id>`), `pace`(노트는 항상 `null`)
- 원탭 재시도 = 실패 작업의 `url`·`tags`·`memo`·`startSec`·`endSec`로 `POST /notes/analyze` 한 번. 서버에 재시도 전용 경로는 없다(S-D6: 노트는 중복 409도 없음)
- 잘못된 구간 400 원문(§4)은 화면에서 막고, 서버 400은 기존 오류 표시 경로로

## 3. 결정·정정

- **`GET /progressions/jobs`는 없다** — 진행 파일 S-D5의 "목록 응답 `GET /progressions/jobs`"는 잘못. 진행 작업도 `GET /notes/jobs`(종류 섞임)·`/notes/jobs/{id}`로만 나온다. 경로를 새로 만들지 않았다(범위 밖)
- 노트 `startSec: 0`만 보낸 요청은 "구간 있음"으로 저장된다(진행 분석과 같은 규칙, Gemini `start_offset: "0s"` — 결과 같음). 화면은 빈 칸이면 필드를 보내지 않는 게 S-D4(바이트 동일)에 맞다
- 노트 구간 예약/견적 = `CreditMath.reserve/estimate("note", null, 구간초)` — 초당 39토큰(0.2fps) 그대로. 실측 보정 없음
