### 질문 아님 — AI가 해당 step에서 정한다 (기록만)

- **모델 버전 고정(M1-3):** 지금 별칭이 가리키는 버전을 Gemini 응답 `modelVersion`으로 확인해 그 값으로 고정(`thinkingLevel` 설정 유지)

- **노트(0.2fps) 초당 토큰(M1-3):** 실측
- **결제 테이블:** 구독·웹훅 이벤트 테이블은 M4-2 마이그레이션에서. V5에는 `profiles`의 결제 티어 칸(지금은 늘 `free`)과 `tier_override`·`tier_override_until`만

## 6. 겪은 문제

- M1-1: 처음 쓴 `shared_folders` CHECK `(kind='user') = (owner_id IS NOT NULL AND source_category_id IS NOT NULL)`가 운영자 폴더에 `owner_id`만 넣은 행을 통과시킴 → 열마다 CHECK 두 개로 고침. 이런 "A = (B AND C)" 형태 CHECK는 한쪽만 채운 행으로 꼭 시험할 것
- M1-2a: 첫 테스트 실행에서 옛 녹음 규칙·200MB 쿼터·분류 50개에 기댄 기존 테스트 18개 실패(예상) → 새 규칙으로 고침(결과 §4 표). 증분 컴파일이 테스트 클래스를 잃어 `:test NO-SOURCE`인데 BUILD SUCCESSFUL로 나온 적 있음 → 테스트 수가 0이면 `./gradlew clean test --rerun-tasks`
- M1-2a: A12 "Secret Manager 키를 못 읽음"의 유력 원인 = `deploy-cloudrun.sh` `--set-secrets`에 YouTube·Gemini 키가 없음(DB·Supabase·APP_MASTER_KEY만). M1-2b·M1-3에서 추가
- **A12 확정(2026-11-05):** 시크릿 이름은 **`SYSTEM_GEMINI_API_KEY`**(Gemini)·**`YOUTUBE_DATA_API_KEY`**(YouTube Data API) — 로컬 `.env`의 `YOUTUBE_API_KEY`·`GEMINI_API_KEY`와 이름이 다르다. 둘 다 Secret Manager에 있고 버전 1 enabled. **그러나 IAM 정책이 비어 있어 `ulevelp-runtime`에 `roles/secretmanager.secretAccessor`가 없다**(`DATABASE_URL`은 있음). 고칠 것 두 가지: ① 두 시크릿에 runtime SA `secretAccessor` 부여 ② `deploy-cloudrun.sh` `--set-secrets`에 `SYSTEM_GEMINI_API_KEY=SYSTEM_GEMINI_API_KEY:latest`·`YOUTUBE_DATA_API_KEY=YOUTUBE_DATA_API_KEY:latest` 추가(서비스 + analyze Job, Job은 Gemini만) 후 코드가 읽는 env 이름을 시크릿 이름과 맞춤
- **M1-2b ① 시크릿 연결 완료(2026-11-05):** 다시 보니 ①은 이미 되어 있었다 — `YOUTUBE_DATA_API_KEY`·`SYSTEM_GEMINI_API_KEY` 둘 다 IAM에 `ulevelp-runtime@ulevelp.iam.gserviceaccount.com` `secretAccessor`(+내 계정)가 있다. 시크릿 값으로 `youtube/v3/videos` 호출 → `OK items=1`, 잘못된 키 → `API key not valid`. ②는 `deploy-cloudrun.sh`에 반영(PR #80): 서비스 `--set-secrets`에 두 키, analyze Job에는 `SYSTEM_GEMINI_API_KEY`만. **코드는 env `YOUTUBE_DATA_API_KEY`를 읽는다**(로컬 `.env`의 `YOUTUBE_API_KEY` 줄 이름을 `YOUTUBE_DATA_API_KEY`로 바꿀 것). 운영 반영은 이 PR 머지 후 배포 때
- **M1-3b: 월 지급 cron 재실행 버그(배포 전 발견·수정)** — 소멸 조건이 "남은 월 지급분 > 0 + 지난달 소멸 기록 없음"뿐이면 같은 달 재실행 때 방금 준 월 지급분을 지운다 → "이번 달 지급 기록이 있으면 소멸도 건너뜀"(결과 B7). 월 경계 테스트는 `CreditService.runMonthlyGrant(now)`에 시각을 넣어 11/30 23:59:59 KST·12/1 00:00·재실행을 본다
