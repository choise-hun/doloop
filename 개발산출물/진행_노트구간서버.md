## 1. 목표와 근거

`계획/앱_명세.md` §3.1-2 — 일반 노트 요청에 "분석 구간 지정(시작~끝)"을 열고, 실패한 작업을 원탭 재시도할 때 URL·태그·**메모**가 남아야 한다. 지금 서버는:
- 노트 분석 라우트가 `url`·`tags`·`memo`만 받는다(`routes/NoteRoutes.kt:28-52`)
- 견적은 노트면 구간을 버린다(`routes/CreditRoutes.kt:63-64` — `kind == progression`일 때만 `parseAnalyzeOptions`)
- 작업 실행은 노트면 `GeminiVideoOptions`가 null(`service/NoteService.kt:375-382`)
- 작업 DTO에 `memo`가 없다(`service/NoteService.kt:60-80` `AnalysisJobDto`, 변환 `:696-712` `rowToJobDto`). `analysis_jobs.memo` 열은 이미 있다(`:305`, `:373`)

## 2. 결정 (승인된 API 모양)

| # | 결정 |
| --- | --- |
| S-D1 | `POST /api/v1/notes/analyze` 선택 필드 `startSec`·`endSec`(정수 0~86400, `endSec > (startSec ?: 0)`) — 검증은 `parseAnalyzeOptions`(`routes/ProgressionRoutes.kt:94-106`)와 같은 규칙·같은 400 `INVALID_INPUT` 문구 |
| S-D2 | 노트는 `pace`를 받지 않는다: 본문에 있어도 무시, `analysis_jobs.pace`는 NULL로 저장, Gemini fps는 기본(지금과 같음) |
| S-D3 | `POST /api/v1/credits/estimate` kind `note`도 `startSec`·`endSec`를 읽어 초를 줄인다(`CreditService.estimate` `:392-399`는 이미 `options?.startSec/endSec`를 쓴다 — 라우트만) |
| S-D4 | 구간 없는 노트 요청은 지금과 바이트 단위로 같다(옵션 null, DB 열 NULL, 견적 같음) |
| S-D5 | `AnalysisJobDto`에 `memo: String = ""` 추가(노트·진행 모두). 목록 응답 `GET /notes/jobs`·`GET /progressions/jobs`에 실린다 |
| S-D6 | 중복 작업 막기(`NoteService.kt:240-250`)는 진행 전용 그대로 — 노트에 넓히지 않는다 |
