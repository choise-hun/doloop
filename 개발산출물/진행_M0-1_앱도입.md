## 1. 공식 문서 확인(2026-11-15)

| 항목 | 확인 내용 | 출처 |
| --- | --- | --- |
| 오류 153 정의 | IFrame API 문서 onError 목록: `153` = 요청에 `HTTP Referer` 또는 동등한 API 클라이언트 식별이 없음(2026-11-15 M1A-2 명세 때 확인 — 위 '번호는 공식 문서에 없다'를 정정) | developers.google.com/youtube/iframe_api_reference |
| 오류 153 원인 | 임베드 플레이어(IFrame API 포함) 사용자는 `HTTP Referer` 요청 헤더로 자신을 밝혀야 한다. Referer가 비는 환경(WebView 등)은 다른 수단으로 밝혀야 하며, 지키지 않으면 기능이 줄 수 있다. 153 번호 자체는 공식 문서에 없고, 외부 보고들이 Referer 누락과 153을 연결한다 | developers.google.com/youtube/terms/required-minimum-functionality |
| WebView 앱의 Referer | 로컬 HTML이면 `baseUrl`로 Referer를 정한다. 값은 `https://<앱 ID>`(iOS는 Bundle ID 소문자, 예 `https://com.example.myapp`). Referer를 못 정하는 `SFSafariViewController`는 `origin` 플레이어 파라미터를 쓴다 | 같은 문서 |
| `origin`·`widget_referrer` | `origin`: IFrame API 보안 수단, 자기 도메인을 넣으라고 권장. `widget_referrer`: 플레이어가 임베드된 URL(YouTube Analytics 트래픽 출처 식별용) | developers.google.com/youtube/player_parameters |
| Capacitor iOS scheme | `server.iosScheme`은 WKWebView가 이미 처리하는 `http`·`https`로 정할 수 없다(기본 `capacitor`). `server.hostname`은 기본 `localhost`, 바꾸지 말 것을 권장. `server.url`은 live-reload용, 운영용 아님 | capacitorjs.com/docs/config |
| 운영 서버의 iframe 차단 | Ktor가 모든 응답에 `X-Frame-Options: DENY`(`src/main/kotlin/ulevelp/Main.kt:334`), HTML에 `Content-Security-Policy: frame-ancestors 'none'`(`:436`)을 붙인다. CI 배포 스모크도 `frame-ancestors 'none'`을 검사한다(`.github/workflows/deploy-cloudrun.yml:84-85`). 페이지 CSP는 `frontend/index.html:5` meta | 코드 |

**결론:** 앱 번들(`capacitor://localhost`) 방식은 iOS에서 https scheme을 쓸 수 없고, 하위 iframe 요청의 Referer도 WKWebView에서 직접 정할 수 없다. 그래서 YouTube 플레이어를 https 페이지 안에 두는 방법(후보 1)을 시험한다. 운영 도메인에 두려면 그 한 경로만 iframe을 허용하도록 운영 Ktor 헤더·배포 스모크를 바꿔야 한다 → M1A-1에서는 운영을 건드리지 않고 임시 https 호스트로 원리만 확인한다(§4.1, 사용자 결정).
