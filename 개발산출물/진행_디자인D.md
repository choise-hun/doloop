## 2. 사용자 확인 (2026-11-14)

- 기존 파랑 토큰(`--link`·`--root`·`--guide`)과 지판 색 구분은 **유지**한다. "파랑 폐기"는 새 화면·새 요소에만 해당한다.
- 서비스 이름의 한글 표기는 **필요 없다**(RE:DO만 쓴다).
- 도메인은 **바꿀 수 있으면 바꾼다.** 지금 운영 주소는 Cloud Run 기본 주소뿐이라 새 도메인 구입·DNS·Cloud Run 연결이 필요하다. BR-1 명세에서 방법·비용을 정리하고 실제 연결은 BR-2(사람)에서 한다.

### 2-1. BR-1 판정 (2026-11-14, 시니어 — 승인됨)

- **Step 분할 없음.** 파일 수(수정 16·신규 6)는 상한 7개를 넘지만 14개가 문자열 1~7줄 교체이고 예상 diff는 약 300줄, 사용자 여정은 하나다. 둘로 나누면 각각 하한(100~150줄) 근처가 되고, DS·BR은 이미 Step 6개다. 한 Step으로 두는 것을 예외로 기록한다(명세 §1-1).
- **담당 [주니어].** 기존 셀렉터·공존·암묵 계약 판정 질문 3개 모두 해당 없음(명세 §1-2). 시니어 검토는 3단계(조건이 맞으면 3-P).
- **사용자 결정 U1~U6**(명세 §0): 파일·폴더 이름 표기(`REDO`), 내보내기 파일 이름(서버 응답 헤더 값), 기존 Drive 폴더 처리, 홈 큰 글자를 BR-1에서 로고로 바꿀지, 파비콘·아이콘 모양, 매니페스트·OG를 만들지 않음.
- **도메인(BR-2 입력, 명세 §8):** Cloud Run 도메인 매핑은 서울 리전(`asia-northeast3`)을 지원하지 않는다. 부하 분산기(월 약 $18 + 처리량) 또는 Firebase Hosting 연결(무료 한도, 요청 60초 제한) 중에 고른다.

### 2-2. DS-2 판정 (2026-11-14, 시니어 — 승인 대기)

- **Step 분할 없음.** 코드 파일 9개(화면 4, 다국어 3, 테스트 2)로 상한 7개를 넘지만 다국어 3개는 값 1줄씩이고 예상 diff는 약 200줄, 사용자 여정은 하나다. 메뉴 로고만 떼면 약 40줄이라 단독 Step이 될 수 없다. 한 Step으로 두는 것을 예외로 기록한다(명세 §1-1).
- **담당 [주니어].** id·클래스·`data-*`를 지우거나 옮기지 않고 더하기만 한다. 공존·암묵 계약 해당 없음(명세 §1-2). `AppShell`은 모든 화면이 쓰므로 layout spec 전체를 돌린다. 시니어 검토는 3단계(조건이 맞으면 3-P).
- **사용자 결정 U1~U4**(명세 §0): 상단 메뉴 로고를 HOME 링크 안에 넣기, 구간 배지는 A–B 구간이 있을 때만 줄 전체, 오늘 연습을 마친 칸은 잉크 채움 + 주황 테두리, `home.spec.js` `UIUX-R T1`의 `borderWidth === '1px'` 단언을 변별 단언으로 교체.
- **파일 충돌 없음.** 열린 PR 0건, 다른 활성 진행 파일 2개에 `HomePage`·`AppShell`·`home.spec`·`shell.spec` 없음.

## 3. 겪은 문제

- 시안 페이지 "결정 내용 복사"의 맨 아래 링크가 한 단계 전 조합을 가리키던 오류(해시 갱신 순서) — 수정함. 결정은 본문 목록이 기준이다.
- 네이비 `#191265`는 작은 면적에서 차콜과 구분이 약했다. 최종 결정에서 파랑·네이비 자체를 폐기했다.
- "토큰 밖 색 25곳"은 RG-1 때 수치다. 지금 실제는 22곳이다(`EpisodeShareDialog` 5 → 2). DS-1 명세는 22곳 기준으로 썼다.
- 주황을 `#E64D01`로 바꾸면 라이트 대비가 4.26 → 3.34로 내려간다. 주황을 글자색으로 쓰던 2곳(progressions 경고 문구)과 `--surface2` 위 테두리 1곳을 DS-1에서 함께 고친다(명세 D3·D9).
- BR-1 명세는 PR #19가 아직 OPEN일 때 `step/DS-1`(`52c32a5`)에서 조사해 썼다. 명세와 이 파일의 변경은 그때 커밋하지 않았다. DS-1과 BR-1은 건드리는 파일이 겹치지 않지만 줄 번호는 구현 전에 다시 확인한다.
- 진행 표에 적었던 "manifest·파비콘·OG·크롬 확장"은 코드에 없었다(`frontend/index.html`에 아이콘·OG 태그 없음, `public/`에 매니페스트 없음, `extension/` 폴더 없음). 파비콘만 새로 만들고 나머지는 범위 밖으로 뺐다(명세 U5·U6).
- 콜론(`:`)은 파일 이름에 쓰기 어렵다(Windows 금지, 브라우저가 `_`로 바꿈). 파일·폴더 이름은 `REDO`로 쓰는 안을 명세에 넣었다(U1).
- DS-2 조사에서 나온 것: ① `home.spec.js:83-86`이 프레임 테두리를 `borderWidth === '1px'`로 단언해 상단 바 3px을 넣으면 깨진다(명세 U4·T0) ② 홈 배너 링크 hover가 쓰는 `--panel-bg`는 `tokens.css`에 없는 토큰이다(같은 토큰을 `PracticeSessionCard.module.css`·`EpisodeLogCard.module.css`도 쓴다 — DS-3 입력) ③ 전역 포커스 외곽선이 `--accent`라 잉크 배너 위에서 보이지 않는다(명세 D9) ④ 주황 틴트 위 `--muted`는 라이트 4.31이라 오늘 칸 요일 글자를 `--ink`로 바꾼다(명세 D3) ⑤ 표준 가짜 데이터의 날짜가 `2026-11-03` 고정이라 "오늘+완료" 칸은 전용 상태로 만들어야 한다(명세 T4).
