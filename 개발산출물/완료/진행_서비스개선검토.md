## 4. iOS 스와이프 구현안

- 현재 `ios/App/App/SceneDelegate.swift:7-13`은 CAPBridgeViewController를 직접 만든다. 설치된 Capacitor8.6.2의 `CAPBridgeViewController.swift:154-165`는 WKWebView 기본 생성 및 capacitorDidLoad 확장 지점을 제공한다. 현재 저장소/설치된 Capacitor 소스에 allowsBackForwardNavigationGestures를 켜는 코드가 없다.
- Apple 공식 문서에서 `WKWebView.allowsBackForwardNavigationGestures`는 수평 스와이프 뒤로/앞으로 이동이며 기본false다: [공식 API](https://developer.apple.com/documentation/webkit/wkwebview/allowsbackforwardnavigationgestures). **정적 근거상 기본 제스처 비활성화가 원인 후보**다. 실제 backForwardList/제스처 동작은 구현 전 Simulator에서 확인한다.
- 추천 구현: 앱 소유의 CAPBridgeViewController 하위 클래스에서 capacitorDidLoad 이후 webView의 해당 속성을 true로 설정하고 SceneDelegate 생성 대상을 교체한다. node_modules 수정이나 JS의 좌우 드래그 거리로 이력을 직접 조작하는 방식은 피한다. 기존 SceneDelegateProxy의 warm/cold URL 전달은 유지한다.
- 기존 브라우저 방문 이력을 사용한다. back 이력 없으면 뒤로 안 감, forward 이력 없으면 앞으로 안 감. 뒤로 간 뒤 다른 페이지로 이동하면 기존 forward 이력은 없어지는 일반 동작이다. 홈/PLAYER/기록/설정 이동과 해시·SPA popstate를 검증한다.
- 충돌 관문: 영상/시간 막대 드래그·가로 스크롤·모달·키보드·녹음 중 이탈/미저장 데이터·iOS iframe 플레이어. 일괄적으로 녹음 중에도 강제 이탈시키지 않는다. 이력 생성 방식과 이탈 가드는 세부 구현 명세에서 확정한다.
- 검증: iPhone/iPad Simulator의 실제 가장자리 swipe UI 테스트, back/forward 가능 경계, 돌아온 URL/화면 상태·로그인 유지. 네이티브 변경이므로 iPhone 실기기1대에서 감각/충돌 최종 스모크. Android/웹 전체실기기 재검수는 요구하지 않는다.
