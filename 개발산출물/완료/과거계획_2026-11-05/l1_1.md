### 2.2 `i18n/LocaleResolver.kt` (package `ulevelp.i18n`)

```kotlin
package ulevelp.i18n

import io.ktor.http.*
import io.ktor.server.application.*
import kotlinx.serialization.Serializable

@Serializable
data class DetectedLocaleResponse(
    val locale: String,
    val country: String?,
    val source: String
)

object LocaleResolver {
    const val HEADER_CLIENT_LOCALE = "X-Client-Locale"
    val SUPPORTED_LOCALES: Set<String> = setOf("ko", "en", "ja")

    val GEO_COUNTRY_HEADERS: List<String> = listOf(
        "X-Cloud-Geo-Location",
        "X-AppEngine-Country",
        "CF-IPCountry",
        "CloudFront-Viewer-Country",
        "X-Country-Code"
    )

    /** "ko" | "en" | "ja" (소문자 정규화, "ko-KR" -> "ko"). 지원하지 않는 값이면 null */
    fun normalizeLocale(raw: String?): String?

    /**
     * 요청 헤더에서 국가 코드(ISO 3166-1 alpha-2 대문자, 예: "KR", "JP", "US")를 추출한다.
     * - X-Cloud-Geo-Location이 "KR, Gwangju"처럼 쉼표 구분이면 앞 2글자 국가 코드만 파싱한다.
     * - "XX", "ZZ", "T1" 등 미상 코드는 null로 본다.
     */
    fun extractGeoCountry(headers: Headers): String?

    /** 국가 코드 -> 기본 언어 ("KR" -> "ko", "JP" -> "ja", 그 외 2자리 영문 국가 코드 -> "en") */
    fun mapCountryToLocale(country: String): String?

    /**
     * Accept-Language 헤더(예: "ja-JP,ja;q=0.9,en-US;q=0.8,en;q=0.7")를 q 가중치 내림차순으로 파싱하여
     * SUPPORTED_LOCALES에 매칭되는 첫 언어를 반환한다. 없으면 null.
     */
    fun parseAcceptLanguage(headerValue: String?): String?

    /**
     * 비로그인/초기 진입 환경 감지 순서:
     * 1) X-Client-Locale 헤더가 유효하면 -> (locale, country, source = "header")
     * 2) GeoIP 헤더 국가 코드가 유효하면 -> (mapCountryToLocale(country), country, source = "ip_country")
     * 3) Accept-Language 헤더에 매칭되는 언어가 있으면 -> (locale, country, source = "accept_language")
     * 4) 모두 없으면 -> ("ko", country = null, source = "default")
     */
    fun detectFromRequest(call: ApplicationCall): DetectedLocaleResponse

    /** API 요청에서 사용할 단일 언어 코드 반환 (detectFromRequest(call).locale) */
    fun resolveLocale(call: ApplicationCall): String
}
```

### 2.4 `service/ProfileService.kt` 및 `auth/AuthPlugin.kt` 변경

- `MeResponseDto`에 `val locale: String = "ko"` 필드 포함.
- `ensureUserAndProfile(user: AuthenticatedUser, initialLocale: String = "ko")`:

  - 이미 존재하는 사용자의 `profiles.locale`은 절대 덮어쓰지 않는다 (주니어 체크리스트 "요청마다 반복되는 쓰기 금지").
- `patchMe(userId: UUID, body: JsonObject)`:
  - `body`에 `"locale"` 키가 있으면 문자열인지 및 정확히 `"ko"`, `"en"`, `"ja"` 중 하나인지 검사한다. 아니면 `InvalidInputException("locale은 'ko', 'en', 'ja' 중 하나여야 합니다.")`.

## 5. 처리 순서·트랜잭션 경계

1. **위치·환경 기반 자동 언어 감지 (`LocaleResolver.detectFromRequest`):**
   - DB 접근 없음, 외부 네트워크 호출 없음(0ms 메모리 연산).
   - `X-Client-Locale` 헤더 → `GEO_COUNTRY_HEADERS` (`KR`→`ko`, `JP`→`ja`, 그 외→`en`) → `Accept-Language` (`q` 가중치 내림차순) → 기본값 `"ko"` 순서로 결정.
2. **첫 로그인 시 초기 언어 저장 (`SupabaseAuthPlugin` → `ProfileService.ensureUserAndProfile`):**
   - 인증 플러그인에서 `val reqLocale = LocaleResolver.resolveLocale(call)`을 추출해 `profileService.ensureUserAndProfile(user, reqLocale)`을 호출한다.
   - 이미 가입된 사용자면 단일 `SELECT`로 확인 후 종료(쓰기 쿼리 없음). 신규 사용자면 `ProfilesTable.insertIgnore` 시 `locale = reqLocale`로 저장한다.

## 9. 금지 사항

- 외부 IP 조회 API(`ipapi.co`, `ipinfo.io` 등)를 서버나 브라우저에서 HTTP로 호출하지 않는다.
- `SongsTable.status` DB 저장 값을 `"Practicing"`이나 `"練習中"`으로 바꾸지 않는다(DB에는 항상 `"practicing"`·`"paused"`·`"done"` 코드만 저장하고 `SongDto.status` 표시 라벨만 바꾼다).
- `NotesTable.difficulty`·`ProgressionsTable.evidence`·`ProgressionsTable.instrument`의 DB CHECK 제약 값을 번역하지 않는다.
- 노션 연동은 2026-11-05 중단·동결(`앱_명세.md` §5) — 노션 관련 코드(`OutboxRepository`·`NotionPushWorker` 등)는 건드리지 않는다.
