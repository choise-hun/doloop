## 1. 실행 시점 및 `앱_명세.md` 정합 핵심 사항

1. **작업 수행 시점 (Phase M1~M3 이후 일괄 수행):**
   - AI 노트 `BETA` 명시 및 UX 개편, Pro 전용 유튜브 재생목록 일괄 추가, 곡 폴더·학습 기록 공유 커뮤니티, 유명인 현재 연습 곡 쇼케이스, 스포티파이형 연습곡 큐레이션 UI가 먼저 구현되어 화면과 한국어 문구가 확정된 직후 **`묶음 L` (`L1-1` → `L1-2`)**을 실행합니다.
   - 이렇게 하면 신규 기능 추가 과정에서 `ko·en·ja` 3개 국어 사전을 반복 수정하는 이중 작업이 발생하지 않습니다.
   - 단, DB 스키마 중복 마이그레이션을 피하기 위해 `profiles.locale` (`TEXT NOT NULL DEFAULT 'ko' CHECK (locale IN ('ko', 'en', 'ja'))`) 컬럼은 `Phase M1-1`(`V5__tiers_credits_and_community.sql`)에 함께 포함하거나 `L1-1`에서 추가합니다.
2. **기존 초기 언어 지원 문서에서 폐기·수정된 사항:**
   - **레거시 `public/*.html`·`public/*.js` 수정 폐기:** React 18(`frontend/src/`) 9개 전체 화면 + 신규 큐레이션/커뮤니티/재생목록 모달 컴포넌트만 수정합니다 (`frontend/src/lib/i18n.ts` 및 `useI18n()` 훅). 레거시 `public/*`은 롤백용 동결 원칙에 따라 건드리지 않으며, `R0-T1` 토큰 일치 검사를 위해 `public/styles.css`의 `--font-body` 1줄만 동기화합니다.
   - **노션(Notion) 연동 동결 (`CH-7`·`CH-7b`):** 노션 백엔드 및 속성명은 번역하지 않으며, 설정 화면의 `#advNotion`은 기본 접힘 은닉 상태를 유지합니다.
   - **코드 진행 공유 및 글로벌 분석 캐시(`shared_analysis_cache`) 폐기:** 개인정보 및 저작권 보호를 위해 학습 노트(`notes`)와 코드 진행(`progressions`)은 100% 개인 보관함으로만 운영하며, 글로벌 캐시 관련 설계는 전면 제거했습니다.
   - **시니어·주니어 역할 구분 및 GitHub Pages 전제 폐기:** 단일 `CLAUDE.md` 규칙 및 Cloud Run + 모바일 앱 WebView(`VITE_API_BASE_URL`) 기준으로 일원화했습니다.

## 3. IP 및 기기 환경 값 기반 자동 언어 설정 동작 방식 (웹 & 모바일 앱 공통)

외부 유료 GeoIP API나 추가 라이브러리를 전혀 쓰지 않고(지연 0ms, 개인정보 외부 전송 0건), **Cloud Run 인프라 헤더와 브라우저/모바일 WebView 내장 환경 값(`Intl` 타임존·`navigator.languages`)을 결합한 4단계 폴백 구조**로 동작합니다.

| 우선순위 | 감지 원천 | 세부 환경 값 및 동작 방식 | 적용 환경 |
| :--- | :--- | :--- | :--- |
| **1순위** | **사용자 수동 고정** | 로컬 스토리지 `ulp:lang` (`'ko'` \| `'en'` \| `'ja'`) 및 로그인 계정의 `profiles.locale` 값 | 웹 & 모바일 앱 공통 (수동 선택 시 최우선 유지) |
| **2순위** | **서버 IP 위치 헤더 (`ip_country`)** | `GET /api/v1/locale` 호출 시 Ktor 서버(`LocaleResolver`)가 Google Cloud Run / GFE / CDN이 주입하는 공인 IP 국가 헤더(`X-Cloud-Geo-Location`, `X-AppEngine-Country`, `CF-IPCountry`, `CloudFront-Viewer-Country`)를 읽어 `KR` → `ko`, `JP` → `ja`, 그 외 국가(`US`, `GB` 등) → `en`으로 매핑하고 `ulp:lang-auto`에 24시간 캐시 | Cloud Run 웹 및 모바일 앱(`VITE_API_BASE_URL` 연결 시) |
| **3순위** | **HTTP `Accept-Language` 및 기기 OS 언어** | IP 위치 헤더가 없는 환경(로컬 기동 등)에서 요청 헤더의 `Accept-Language`(q 가중치 내림차순) 및 브라우저/WebView `navigator.languages` 배열을 파싱해 `ko`·`en`·`ja` 중 첫 매칭 언어 선택 | 로컬 서버, 일반 브라우저, iOS/Android WebView |
| **4순위** | **클라이언트 IANA 타임존 (`Intl`)** | 오프라인 캐시 열람 상태이거나 기기 언어가 제3언어(`zh`, `es` 등)일 때 `Intl.DateTimeFormat().resolvedOptions().timeZone`을 확인해 `Asia/Seoul` → `ko`, `Asia/Tokyo` → `ja`, 그 외 → `en`으로 0ms 즉시 추론 | 첫 페인트 즉시 추론(깜빡임 방지) 및 오프라인 모드 |
