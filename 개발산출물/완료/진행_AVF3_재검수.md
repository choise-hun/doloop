- 기존 fixture ID는 같은 DB의 기존 category/shared_folders/song_categories를 읽고 유일성 단언으로 재구성했다. 초기화/TRUNCATE/컨테이너 재생성 없음. 새 전체 pg_dump는 `test-results/av3/db-after-recovery.sql`(0600)에 보존했다. 삭제 전 전체 백업을 보존했다고 주장하지 않는다.
- 재발 방지: `playwright.config.js`의 outputDir을 `test-results/playwright`로 분리하고 CLI에도 `--output=test-results/playwright`를 지정했다. AV-3 README에 기본 루트 출력 경로 사용 금지를 기록했다. 이는 이번 증거 보존에 필요한 검수 설정 변경이다.
- 첫 시트 검수는 동일 공유 fixture를 바꾸는 내 공유 검사와 동시 실행해 대상 카드 부재로 중단됐다. 이후 두 DB 변경 검수는 순차 실행한다. 언어 큐 도구 첫 시도는 실제 `#langSelect`가 select가 아닌 버튼 그룹이라 실패했다. 실제 DOM의 `[data-lang]` 버튼으로 수정했고 실패 attempt를 별도 보존했다. 제품 실패를 단언 완화로 숨기지 않았다.
- 마지막 제품 빌드를 Ktor 재개 후 전역 프로필·호출자·언어 큐·시트·내 공유·기존 데이터 smoke/소유권·실제 로그아웃 순서로 재검수한다. 실로그아웃은 refresh 폐기 때문에 마지막에만 실행한다.

### 추가 영향 호출자 회귀

- `apiClient.me.update`를 사용하는 `drive.enableDriveStorage/disableDriveStorage`의 설정 화면 반환 처리도 조사했다. 전역 상태는 auth 가드가 지키더라도 이전 계정의 완료/AbortError를 현재 계정 `driveStatusMsg`에 표시할 수 있었다.
- 실제 Drive 외부 API/저장소 쓰기는 하지 않고 `ULDrive` 반환만 deferred로 제어하는 화면 회귀 6건(활성화/비활성화 × 성공/일반 실패/AbortError)을 먼저 실행해 6건 실패를 확인했다. 설정 두 호출자에 세션 동일성/AbortError 검사를 추가했다. 공개 함수·서버·Drive API 계약은 변경하지 않는다.
