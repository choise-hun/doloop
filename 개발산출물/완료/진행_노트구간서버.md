## 1. 목표와 근거

`계획/앱_명세.md` §3.1-2 — 일반 노트 요청에 "분석 구간 지정(시작~끝)"을 열고, 실패한 작업을 원탭 재시도할 때 URL·태그·**메모**가 남아야 한다. 지금 서버는:
- 노트 분석 라우트가 `url`·`tags`·`memo`만 받는다(`routes/NoteRoutes.kt:28-52`)
- 견적은 노트면 구간을 버린다(`routes/CreditRoutes.kt:63-64` — `kind == progression`일 때만 `parseAnalyzeOptions`)
- 작업 실행은 노트면 `GeminiVideoOptions`가 null(`service/NoteService.kt:375-382`)
- 작업 DTO에 `memo`가 없다(`service/NoteService.kt:60-80` `AnalysisJobDto`, 변환 `:696-712` `rowToJobDto`). `analysis_jobs.memo` 열은 이미 있다(`:305`, `:373`)

- 잘못된 입력 하나는 curl 또는 테스트로 400 응답 원문을 결과 파일에 붙인다(`endSec <= startSec`)

## 6. 겪은 문제

- **M2-1c:** ① layout `retry` 상태에서 작업 줄 `.runSub`(URL 한 줄 말줄임)가 G3로 처음 걸림 — 의도한 말줄임이라 `data-layout-ignore` + 결과 §4 예외 목록 ② 구현 전 실패 확인 중 dist를 다시 빌드해 결과가 섞일 뻔함 → 프론트 소스만 stash해 깨끗하게 다시 확인(새 테스트 12개 실패·기존 17개 통과)
- **M2-1s:** ① §1·S-D5의 `GET /progressions/jobs`는 없는 경로 — 진행 작업도 `/notes/jobs`로 나온다. 경로는 만들지 않고 S-D5 문구만 고침 ② 기존 `NoteApiTest` n19 끝이 "노트는 구간 무시"를 단언하고 있어 새 동작(구간 저장, pace null)으로 바꿈 ③ 같은 작업 폴더에 주니어 M2-1bd 작업 중 파일(`test/e2e/layout/notes.spec.js` 수정, `test/e2e/notes-form.spec.js` 새로)이 있었다 — M2-1s 커밋에 넣지 않음 ④ 그 주니어가 도중에 같은 폴더에서 `step/M2-1bd`로 브랜치를 바꿔 **M2-1s 커밋 2개(`94058dc`·`00d4add`)가 로컬 `step/M2-1bd` 위에 올라감** → `step/M2-1s`를 그 커밋으로 fast-forward해 push(강제 없음), 이후 커밋은 별도 worktree에서. `step/M2-1bd`는 주니어 작업 중이라 손대지 않음 — PR #113을 M2-1bd보다 먼저 머지하면(merge commit) M2-1bd PR에는 주니어 커밋만 남는다
