## 4. 계약

### 4.1 DB (`V12__share_attachments.sql`)

- `community_share_consents`: `id BIGSERIAL PK`, `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`, `action TEXT NOT NULL CHECK (action IN ('agree','withdraw_recording'))`, `notice_version INTEGER NOT NULL CHECK (notice_version >= 1)`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`. 인덱스 `(user_id, id DESC)`.
- `shared_card_attachments`: `id UUID PK`, `session_id UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE`, `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`, `kind TEXT NOT NULL CHECK (kind IN ('audio_copy'))`, `source_take_id UUID NOT NULL REFERENCES takes(id) ON DELETE CASCADE`, `storage_key TEXT NOT NULL UNIQUE CHECK (storage_key ~ '^shared/[0-9a-f-]{36}\.(m4a|weba|ogg|mp3|wav|aac)$')`(확장자 = `TakeService.MIME_EXT` 값 6종 그대로, `audio/webm` → `weba`. 2026-11-13 PR #12 리뷰 반영), `mime TEXT NOT NULL`(P2 6종 CHECK 복사), `size_bytes BIGINT NOT NULL CHECK (size_bytes BETWEEN 1 AND 10485760)`, `duration_sec INTEGER NOT NULL CHECK (duration_sec BETWEEN 0 AND 300)`, `status TEXT NOT NULL CHECK (status IN ('copying','uploaded','ready'))`, `original_confirmed_at TIMESTAMPTZ NOT NULL`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `ready_at TIMESTAMPTZ`, `CHECK ((status = 'ready') = (ready_at IS NOT NULL))`.
  - `UNIQUE (session_id) WHERE status = 'ready'`, `UNIQUE (user_id) WHERE status IN ('copying','uploaded')`, 인덱스 `(user_id, status)`.
  - `source_take_id` CASCADE는 안전망이다. 정상 경로는 원본 삭제 전에 D10을 호출해 파일을 대기열에 넣는다(S3b-2가 삭제 경로 연결).
- `ALTER TABLE storage_trash ADD COLUMN next_attempt_at TIMESTAMPTZ NOT NULL DEFAULT now()` + 인덱스 `(next_attempt_at)`.

### 4.4 공유 요청의 `attachment`

| 값 | 의미 | 검사 |
| --- | --- | --- |
| 키 없음 / `null` | 유지(D13) | — |
| `{"mode":"keep"}` | 유지 | 추가 키 금지 |
| `{"mode":"none"}` | 제거 + 통계 재스냅샷 | 추가 키 금지 |
| `{"mode":"replace","takeId":"<uuid>","originalConfirmed":true,"uploadId"?:"<uuid>"}` | 이 녹음 사본으로 교체(첫 첨부 포함) | `takeId` UUID, `originalConfirmed`는 JSON `true`만, `uploadId`는 Drive 녹음(S3b-2)에서만 |

`mode` 밖 값·알 수 없는 키·형식 오류 = 400 `INVALID_INPUT`(`episodeKeys` 재사용).

### 4.5 오류 표 (S3b 서버 전체)

| 조건 | HTTP | code / detail |
| --- | --- | --- |
| 본문 형식, `originalConfirmed` 누락, `removeExisting` 누락 | 400 | `INVALID_INPUT` |
| 세션·녹음·카드·첨부가 없음 또는 남의 것, 녹음이 다른 세션 | 404 | `NOT_FOUND` |
| 무료(게시·첨부) | 403 | `TIER_UPGRADE_REQUIRED`(기존) |
| 숨김 카드에 게시 / 공개 이름 / 스냅샷 | 409 | 기존 코드(P10) |
| 녹음 동의 없음·철회됨·버전 미달 | 409 | `SHARE_CONSENT_REQUIRED` `{scope:"recording",requiredVersion}` |
| 카드 공유 동의 없음(**S3b-3부터**) | 409 | `SHARE_CONSENT_REQUIRED` `{scope:"card",requiredVersion}` |
| 동의 요청 버전 ≠ 현재 버전 | 409 | `SHARE_NOTICE_OUTDATED` `{noticeVersion}` |
| 길이 > 300초 / 크기 > 10MB | 409 | `ATTACHMENT_LIMIT_EXCEEDED` `{kind:"duration"\|"size",limit}` |
| 동시 첨부 20개 / 하루 20건(**S3b-2**) | 409 | `ATTACHMENT_LIMIT_EXCEEDED` `{kind:"count"\|"daily",limit}` |
| 이 사용자의 다른 복사가 진행 중 | 409 | `ATTACHMENT_COPY_IN_PROGRESS` |
| Drive 녹음인데 `uploadId` 없음 | 409 | `ATTACHMENT_UPLOAD_REQUIRED` |
| `uploadId` 불일치·만료(**S3b-2**) | 409 | `ATTACHMENT_UPLOAD_INVALID` |
| 복사 중 원본 녹음 삭제 | 409 | `ATTACHMENT_SOURCE_GONE` |
| 복사 중 철회 등으로 준비 행이 사라짐 | 409 | `ATTACHMENT_COPY_EXPIRED` |
| 저장소 미설정 | 503 | `STORAGE_UNAVAILABLE` |
| 저장소 읽기·쓰기·서명 실패 | 502 | `STORAGE_ERROR` |

## 5. 처리 순서 (교체 — 핵심 흐름 골격)

```text
replace(userId, sessionId, title, comment, takeId):
 tx1 = dbQuery {
   ctx = tierContext(userId, lock=true); src = lockSource(userId, sessionId); old = card FOR UPDATE
   P10 사전 검사 전부 (share와 같은 함수로 추출해 재사용)
   requireRecordingConsent(userId)                      // D3
   take = takes where id=takeId, user=userId, session=sessionId ?: 404
   if (ready 첨부의 source_take_id == takeId) return KEEP   // D12 → 아래 단일 트랜잭션 공유
   if take.storage == "drive": 409 ATTACHMENT_UPLOAD_REQUIRED (uploadId 경로는 S3b-2)
   검사 D11(duration_sec, size_bytes)
   이 사용자의 진행 중 행 FOR UPDATE; created_at < now-30분 → D18 회수(행 삭제 + 보류 행 next_attempt_at=now, id를 reclaimIds에)
   진행 중 행 남음 → 409 ATTACHMENT_COPY_IN_PROGRESS
   attId = 새 UUID; key = "shared/$attId.${MIME_EXT[take.mime]}"   // audio/webm → .weba
   insert attachment(status=copying, original_confirmed_at=now, mime/size/duration=take 값)
   guardId = insert storage_trash(key, next_attempt_at = GUARD_HOLD)   // D8: 시각으로 풀리지 않는다
 }
 커밋 뒤 purge(reclaimIds)
 try {
   bytes = storage.download(take.storageKey)            // 실패 → 502 STORAGE_ERROR
   bytes.size !in 1..10MB → 409 ATTACHMENT_LIMIT_EXCEEDED(size)
   storage.upload(key, bytes, take.mime)
   tx2 = dbQuery {
     tierContext lock → lockSource → card FOR UPDATE → P10·동의 재검사
     take 행 존재 재확인 ?: 409 ATTACHMENT_SOURCE_GONE   // 먼저: 원본 삭제는 CASCADE로 첨부 행도 지운다
     att = attachment where id=attId and status=copying FOR UPDATE ?: 409 ATTACHMENT_COPY_EXPIRED
     카드 insert/update (share와 같은 규칙, publishedAt 규칙 현행 유지)
     trashIds = removeShareAttachments { session=sessionId and status=ready and id != attId }
     att → status=ready, ready_at=now, size_bytes=bytes.size;  guard 행 삭제
   }
   커밋 뒤 purge(trashIds); 응답
 } catch (t: Throwable) {
   withContext(NonCancellable) {                         // backend-kotlin §3
     cleanupIds = dbQuery {
       att FOR UPDATE
       ready면 → emptyList()                            // 이 요청의 tx2가 이미 커밋: 건드리지 않는다
       copying이면 행 삭제
       같은 key의 trash 행이 있으면 next_attempt_at=now, 없으면(회수가 이미 purge) 새로 insert → 그 id
     }
     purge(cleanupIds)                                   // 회수 purge 뒤에 끝난 upload도 정리된다
   }
   throw t
 }
```

- 외부 I/O(download/upload) 중에는 트랜잭션을 열지 않는다(backend-kotlin §1). 모든 `catch (Exception)`은 `CancellationException`을 먼저 다시 던진다(§2).
- `keep`·`none`·유지 경로는 기존 `share` 한 트랜잭션. `none`은 같은 트랜잭션에서 `removeShareAttachments { session=sessionId }` 후 커밋 뒤 `purge`.
- `removeAttachment`·`withdraw`·동의 철회(`removeExisting=true`, 조건 `user=userId`)도 잠금(`tierContext(lock)` → `lockSource` → 카드) 뒤 같은 함수, 커밋 뒤 `purge`.
- 재생 주소: `dbQuery { 카드 FOR UPDATE 없이 joined 조회 → eligible → 첨부(session=card.session, id, ready) }` 밖에서 `createSignedUrl(key, 300)`.

- `takes` 테이블 확장, 새 업로드(외부 파일) 경로, 서버가 임의 URL을 가져오기.
- 삭제 경로마다 따로 trash 적재 코드를 쓰기(D10 함수만 사용). 노션 배치의 다른 동작 변경.
