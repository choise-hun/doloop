## 3. 라우팅 — 앱 번들 조립(`scripts/build-app-web.mjs`)

- 방식: **페이지별 index.html 사본.** 링크·라우터는 그대로 둔다(대안인 클릭 가로채기는 링크 70여 곳과 `location.*` 호출을 건드려 웹 회귀 위험이 크다).
- 순서: ① `dist/index.html`이 없으면 0이 아닌 코드로 끝낸다(“먼저 npm run build”). ② `dist-app/`을 비우고 `dist/` 전체 복사. ③ `public/` 전체 복사(P4; `player-embed.*`도 같이 들어가지만 앱은 운영 URL의 것을 쓴다). ④ **앱용 index.html 만들기:** `dist/index.html`의 CSP meta에서 `frame-src` 지시문 끝에 플레이어 출처(`new URL(playerEmbedUrl).origin`, 기본은 `public/config.js`의 값, ⑤의 덮어쓰기 값이 있으면 그 값)를 더한다. `frame-src` 지시문을 찾지 못하면 실패한다(조용히 건너뛰지 않음). 웹용 `dist/index.html`·`frontend/index.html`은 바꾸지 않는다(P17). ⑤ `APP_ENTRY_PAGES`(11개)마다 ④의 앱용 index.html을 그 이름으로 쓴다(`dist-app/index.html` 포함). ⑥ 환경 변수 `APP_PLAYER_EMBED_URL`이 있으면 `dist-app/config.js` 끝에 `window.ULEVELP_CONFIG.playerEmbedUrl = <JSON 문자열>;` 한 줄을 붙인다(https URL만 허용, 아니면 실패) — §7.3 검증용 태그 리비전을 가리킬 때 쓴다.
- export: `APP_ENTRY_PAGES`, `buildAppWeb({ distDir, publicDir, outDir, playerEmbedUrl })`. 명령행 실행 때만 기본 경로로 호출한다. 기본 `playerEmbedUrl`은 `public/config.js` 원문에서 정규식으로 읽는다(못 읽으면 실패).
- `package.json` `build:app` = `npm run build && node scripts/build-app-web.mjs`. 앱 갱신은 `npm run build:app && npx cap sync`.

## 4. safe area

- `tokens.css` `body`: `padding-top: calc(20px + env(safe-area-inset-top, 0px))`. 아래 56px·좌우는 그대로. 브라우저·Playwright에서는 `env()`가 0이라 웹 화면이 픽셀 단위로 같다.
- `--safe-area-inset-*` 변수는 쓰지 않는다(WebView 140 미만은 웹뷰 자체가 여백 안이라 더하면 두 번 띄워진다, P7).
- Android `SystemBars`는 기본값(`css`). 문서가 권하는 `EdgeToEdge.enable(this)`가 8.6.2 템플릿 `MainActivity`에 있는지 구현 때 확인하고, 없으면 넣지 않고 기기 결과를 먼저 본다(**미확인**). 스파이크 로그의 `Error injecting safe area CSS`가 다시 나오면 결과 파일에 기록한다.
- 웹 배치 약속(`data-align-group`)·기하 검사 대상은 바뀌지 않는다 → 4개 폭 스크린샷 대신 `test/e2e/layout/shell.spec.js`·`practice.spec.js` 통과와 실기기(§8.3)로 판정한다.

## 5. iOS 플레이어 iframe

### 5.1 운영 헤더(`Main.kt`, 승인 D3)

- 상수 `PLAYER_EMBED_PAGE = "player-embed.html"`, `PLAYER_EMBED_CSP` = 아래 값(한 줄):
  `default-src 'none'; script-src 'self' https://www.youtube.com/iframe_api https://www.youtube.com/s/player/; frame-src https://www.youtube.com; style-src 'unsafe-inline'; img-src https://i.ytimg.com; frame-ancestors capacitor://localhost https://localhost; base-uri 'none'; object-src 'none'; form-action 'none'`
  (M1A-1에서 iPhone·iPad 통과한 `spike/ios153/player/nginx.conf` 값과 같다.)
- Plugins intercept: 요청 경로가 정확히 `/player-embed.html`일 때만 `X-Frame-Options`를 붙이지 않는다. `nosniff`는 모든 경로 유지.
- 정적 서빙: `relPath == PLAYER_EMBED_PAGE`이면 `frame-ancestors 'none'` 대신 `PLAYER_EMBED_CSP`와 `Referrer-Policy: strict-origin-when-cross-origin`을 붙인다. GET·HEAD 같음. `Cache-Control`은 기존 html 규칙(`no-cache`).
- `/player-embed.js`는 기존 js 규칙 그대로(XFO DENY 유지 — 스크립트라 무관).
- 그 밖 모든 경로(`/`, `/index.html`, `/api/*` 등)의 헤더는 한 글자도 바꾸지 않는다.
- 배포 스모크(`deploy-cloudrun.yml`)에 추가, 기존 `/` 검사는 그대로:
  ```bash
  curl -fsSI "${SERVICE_URL}/player-embed.html" | grep -i "frame-ancestors capacitor://localhost https://localhost"
  ! curl -fsSI "${SERVICE_URL}/player-embed.html" | grep -qi "^x-frame-options"
  ```

### 5.2 플레이어 페이지(`public/player-embed.html`·`.js`)

- 시험물 `spike/ios153/player/index.html`·`player.js`를 바탕으로 하되 진단 코드(`reject` 메시지, `any=1`)는 넣지 않는다.
- 주소 인자: `v`(11자 `[A-Za-z0-9_-]`, 아니면 플레이어를 만들지 않고 `error{code:'bad-video'}`), `start`(0 이상 숫자, 아니면 0), `parent`(허용 목록 `['capacitor://localhost','https://localhost']` 중 하나, 아니면 아무 메시지도 보내지 않고 받지도 않는다).
- `playerVars`: `playsinline:1, rel:0, modestbranding:1, start, origin: location.origin, widget_referrer: location.href`.
- 받는 메시지: `e.origin === parent`이고 `e.source === window.parent`일 때만 처리.
- 페이지는 플레이어 하나만 그리고(검은 배경, 100%×100%), 겹치는 요소를 두지 않는다(P13). 로그인·저장소(localStorage) 접근 코드 없음.

| --- | --- | --- |
| 부모→플레이어 | `{type:'cmd', cmd:'play'}` · `{…'pause'}` · `{…'seek', value:초}` · `{…'rate', value:배속}` · `{…'cue', value:{videoId, startSeconds}}` | 숫자가 아니면 무시 |
| 플레이어→부모 | `{type:'ready', duration, rates:number[], title, author}` | `onReady` 때 한 번 |
| 〃 | `{type:'status', time, duration, state, rate, title, author}` | 250ms마다 + `onStateChange`·`onPlaybackRateChange` 때 즉시 |
| 〃 | `{type:'error', code}` | YouTube `onError` 코드 그대로 |

- `title`·`author`는 플레이어 페이지가 `getVideoData()`로 읽어 보낸다(없으면 빈 문자열).
- export:
  - `shouldUseRemotePlayer(): boolean` — `Capacitor.getPlatform()`(`@capacitor/core`)이 `REMOTE_PLAYER_PLATFORMS`(= `['ios']`, 승인 D4 (가). Android로 넓힐 때 이 배열만 바꾼다)에 있고 `playerEmbedUrl`이 https URL일 때만 참.
  - `createRemotePlayer(mountId, { videoId, startSeconds, events })` — P14 메서드를 같은 이름·인자로 가진 객체를 돌려준다. `#mountId` div를 같은 id의 iframe으로 바꾼다(P16). iframe `src` = `playerEmbedUrl?v=…&start=…&parent=<location.origin>`, `allow="autoplay; encrypted-media; picture-in-picture"`, `referrerpolicy` 지정 안 함(기본 정책; `no-referrer` 금지, RMF).
- 받는 메시지: `e.origin === new URL(playerEmbedUrl).origin`이고 `e.source === iframe.contentWindow`일 때만.
- 시각: `getCurrentTime()`은 마지막 `status.time`에, 상태가 재생(1)이면 `(지금 - 받은 시각)/1000 × rate`를 더한 값(`duration`을 넘지 않게). 250ms 간격 때문에 A-B 끝점 판정이 늦어지지 않도록 하기 위함이다.
- `seekTo(t)`: 명령을 보내고 내부 시각을 즉시 `t`로 바꾼다(다음 `status`가 오면 그 값으로 덮음). `setPlaybackRate(r)`: 명령만 보내고 실제 값은 `status`로 반영.
- 이벤트: `ready`를 받으면 `onReady()` 한 번. `status.state`가 직전과 다르면 `onStateChange({data: state})`, `status.rate`가 다르면 `onPlaybackRateChange({data: rate})`, `error`면 `onError({data: code})`.
- `ready` 전 `play`·`pause`·`seek`·`rate`는 버린다(PracticePage는 이들을 `ready` 뒤에만 부른다, `PracticePage.tsx:428·503·938·947`).
- **`ready` 전 `cueVideoById`는 버리지 않는다(P18).** 마지막 값 하나만 `pendingCue`로 보관하고, `ready`를 받으면 그 영상이 처음 만든 영상과 다를 때 `cue` 명령을 바로 보낸다. 이때 `ready`의 `duration`·`title`·`author`는 이전 영상 값이므로 `onReady` 뒤 첫 `status`로 덮인다. 준비 중 영상을 여러 번 바꿔도 마지막 선택만 남는다.
- `destroy()`: message 리스너 해제, iframe을 원래 `<div id=mountId>`로 되돌린다.

### 5.4 PracticePage 연결

- 바뀌는 곳은 두 군데뿐이다. 나머지 플레이어 호출(P14)·상태·타이머는 그대로 둔다.
  1. YT 스크립트 로드 effect(`:1316-1340`): `shouldUseRemotePlayer()`이면 `iframe_api` 스크립트를 넣지 않는다(`onYouTubeIframeAPIReady` 등록도 하지 않는다). 첫 영상은 `:681` 경로로 원격 분기에 바로 들어간다.
  2. `createOrCuePlayer`(`:519`): **진입 가드를 분기별로 나눈다(P18).** 원격 분기는 `ytReadyRef`·`win.YT`를 보지 않고 바로 진행하고, `pendingLoadRef`에 넣지 않는다. 직접 임베드 분기는 지금 가드(`:521-524`) 그대로. 원격이면 `new win.YT.Player` 대신 `createRemotePlayer('player', { videoId, startSeconds, events })`. `events` 객체는 지금 코드의 `onReady`·`onStateChange`·`onPlaybackRateChange`·`onError`를 그대로 넘긴다(함수 본문 복제 금지 — 한 객체를 두 분기가 함께 쓰게 꺼낸다). `cueVideoById` 분기는 공통.
- 웹·Android에서 위 두 분기는 타지 않는다 → 기존 e2e(YouTube 차단 경로 포함)는 바뀌지 않아야 한다.

### 7.2 보안

- 클릭재킹: `/player-embed.html`은 사용자 동작으로 무언가를 바꾸는 기능·로그인 정보가 없고, 허용 조상은 두 앱 출처뿐이다. 나머지 경로는 기존 DENY·`'none'` 유지(Z1~Z3·스모크).
- 같은 출처 저장소: 플레이어 페이지는 운영 출처라 같은 출처 localStorage에 닿을 수 있다. 그래서 외부 스크립트는 YouTube 두 경로만 CSP로 허용하고, 페이지 코드에서 저장소를 읽지 않는다.
- `https://localhost` 허용은 개발자 PC의 로컬 https 페이지도 이 플레이어를 넣을 수 있다는 뜻이지만, 페이지가 비밀 정보를 내보내지 않으므로 위험이 없다고 판단한다.

### 7.3 운영 배포(이 Step 승인 밖)

- iOS 실기기 판정(§8.3 A5·A6)은 플레이어 페이지가 운영 도메인에 있어야 한다. 방법 두 가지 중 사용자가 그때 고른다(별도 승인):

  - (나) PR 머지 뒤 운영 배포 후 확인.
