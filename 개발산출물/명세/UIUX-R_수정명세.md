## 1. 목적과 적용 경계

동일 녹음의 중복 조작을 없애고, 트랜스포트 버튼 위계를 통일하며, 커뮤니티의 연습 공유 목적과 악기 연습실의 설정·재생 구조를 분명히 한다. 보고서 7개 항목 모두 아래에 대응한다.

- React 화면과 관련 테스트·번역만 수정 대상으로 제안한다. 서버 API 경로·필드·상태 코드, DB, 라우트, 기존 export 이름은 유지한다.
- §3·§4·§6·§7은 새 DTO·서버 기능·의존성을 추가하지 않는다. 추천 알고리즘·댓글·실시간 접속·랭킹은 어느 범위에서도 제외하고, 자료가 없는 추천/순위/사용자 활동을 만들어 채우지 않는다. **커뮤니티(§5)만** S1 프런트 → S2 게시물 좋아요(서버·DTO·DB) → S3 공개 녹음 재생(S3a 프런트 UI는 바로, S3b 녹음 파일 취득은 정책 결정 후)로 단계를 나누며 S2·S3b는 별도 승인으로 서버 계약을 변경한다.
- 녹음·메모·A/B 비교·공유/철회·집계·공유 폴더 기능을 보존한다. 공개 카드에 개인 녹음·메모·storageKey를 전달하지 않는다(S3 정책 결정 전까지 유지, §5.7).
- 튜닝은 보고서 §6의 **안 B를 구체화한 접이식 연습실 설정**을 제안한다. SettingsPage로 전역 이관하거나 저장 키/API를 신설하지 않는다. 완전 이관은 악기별 기본값·영속성·계정 범위를 별도로 결정해야 하므로 이번 수정에 포함하지 않는다.
- 기존 사용자 변경 `HomePage.module.css`, 인수인계 메모 및 입력 `report.md`를 덮어쓰지 않는다. 홈 스타일은 이번 구현 범위 밖이다.

## 3. 연습 세션 단일화 — 보고서 §1

### 3.1 구성과 데이터

`#songRecord` 순서: 요약/기록 링크 → A/B 비교(접기 가능) → 연습 세션 타임라인 → 세션 미연결 녹음(존재할 때만). 모든 폭에서 본문은 1열이며 전체 테이크를 다시 나열하는 좌측 녹음 패널은 제거한다.

- 세션 카드 모델·정렬·처음 5개/더보기 정책은 유지한다. 세션 테이크는 `take.sessionId === session.id`로 연결한다. 날짜·영상·배속으로 추측 연결하지 않는다.
- 현재 응답의 전체 sessions ID 집합에 없는 sessionId의 테이크를 “세션 미연결 녹음”으로 1회만 표시한다. 처음 5개에 없는 세션의 테이크를 미연결로 잘못 분류하지 않는다. 재연결·가짜 세션 생성·서버 데이터 수정은 하지 않는다.
- 세션 내부 행과 미연결 행이 동일한 TakeItemRow를 사용하고 듣기/완료/삭제/A·B 지정 기능을 제공한다. 테이크별 DOM 식별자로 중복 행 0건을 단언한다. 더보기 전 숨겨진 세션의 테이크는 더보기 후 접근할 수 있다.
- A/B 상태 소유자는 SongRecordPanel이다. 서로 다른 세션 및 미연결 테이크 사이에도 같은 곡 안에서 비교 가능하다. 한 테이크는 동시에 A와 B가 될 수 없다. 선택 해제·교체 정책은 기존 동작을 유지한다. 비교 오디오는 명시한 A/B 슬롯 순서를 따른다. 현재 abPair 구성에서 호출하는 sortAbTakes로 슬롯 순서를 다시 바꾸지 않으며, 공용 sortAbTakes 함수 자체와 다른 호출부는 유지한다.
- 선택한 A를 삭제할 때 B가 A로 자동 이동하지 않는다. 삭제 ID의 슬롯만 비우며, 비교는 두 유효 테이크가 모두 있을 때만 가능하다. 슬롯 교체/삭제·곡 변경·로그아웃 시 재생과 미완료 URL 응답을 무효화한다.
- 완료 성공은 응답 take를 원본 takes에 반영하고 삭제 성공은 원본에서 제거한다. 실패/권한 오류는 해당 행에 표시하고 데이터·선택을 성공 상태로 바꾸지 않는다. 메모·공유 동작은 기존 카드 책임을 유지한다.

### 3.2 프런트 계약 변경 제안

A/B 선택 전달을 위해 아래 **선택 prop만 추가**한다. 구현 승인 이후 적용하며 기존 호출부는 미전달 시 현재 동작을 유지한다.

| 인터페이스 | 추가 필드 | 의미 |
| --- | --- | --- |
| SessionTimelineProps / PracticeSessionCardProps | `abSelection?: { a: string; b: string }` | 빈 슬롯은 빈 문자열, 현재 곡 기준 선택 ID |
| 위 두 인터페이스 | `onSelectAbSlot?: (takeId: string, slot: 'a' \| 'b' \| '') => void` | TakeItemRow의 기존 콜백으로 위임 |

새 export·TakeDto 필드·필수 prop은 만들지 않는다. 두 prop이 있을 때만 카드의 TakeItemRow에 기존 `showAbCheck`, `abSlot`, `abChecked`, `onSelectAbSlot`을 연결한다. TRAILS/곡 상세 등 다른 호출부는 현행 표시를 유지한다.

### 3.3 상태·미디어·권한

| 상태 | 요구 동작 |
| --- | --- |
| 비로그인/곡 미선택 | 현행 로그인·곡 선택 안내, 테이크 요청/비교 비활성 |
| 초기 로딩 | 로딩 안내, 빈 목록 문구와 A/B 선택기 미노출 |
| 조회 실패 | 오류+재시도, 빈 성공으로 대체하지 않음 |
| 성공·세션/테이크 모두 없음 | 연습 후 기록이 생긴다는 안내, 비교 숨김 |
| 세션만 존재 | 카드/메모/공유 유지, 테이크 조작 없음 |
| 미연결 테이크만 존재 | 빈 세션 안내와 미연결 목록·비교를 함께 제공 |
| 한 슬롯만 선택 | 선택 ID 유지, 비교 재생 잠금과 두 녹음 선택 안내 |
| 듣기/완료/삭제 요청 중 | 해당 행의 중복 행동 잠금, 성공 후 갱신·실패 후 재시도 |
| 사용자 A→B/곡 전환 | 즉시 목록·슬롯·오디오 초기화, 옛 응답/알림 적용 금지 |

기존 uid+요청 토큰+슬롯 ID 가드를 유지하고 컴포넌트 폐기 시도 무효화한다. audio 초기화는 pause → removeAttribute('src') → load → dataset 제거 순서다. Drive/Supabase 경로를 임의 fallback하지 않는다. A/B는 소리 비교 슬롯을 뜻하며 사용자 A↔B 격리 검증과 구별한다.

API는 GET `/api/v1/takes/{takeId}/url` → 200 `{url,expiresIn}`, DELETE `/api/v1/takes/{takeId}` → 200 `{ok:true}`, PATCH `/api/v1/takes/{takeId}/complete` + `{completed:boolean}` → 200 `{ok:true,take:TakeDto}`를 유지한다. 기존 로그인·소유권·미디어 오류는 해당 조작 실패로 처리하고 HTTP 오류를 성공으로 변환하지 않는다. TakeDto와 SongSessionDto의 전 필드는 `frontend/src/lib/apiClient.ts:62` 및 `:79`를 유지하며 공개 DTO로 복사하지 않는다.

## 4. 트랜스포트 스타일 — 보고서 §2

- 보고서 안 A를 제안한다. 재생 버튼은 주변 `.ppTbtn`과 같은 `var(--bg)`, `var(--ink)`, `1px solid var(--line)`, `var(--radius-card)`와 최소 높이 52px를 사용한다. 단독 60px 높이·pill·반전 채움을 제거한다.
- 5개 버튼의 윗선·아랫선·높이를 맞춘다. 재생 열의 현재 1.4fr 비중과 아이콘 24px은 유지 가능하다. 긴 번역/확대 때문에 높이가 늘면 같은 행 전체가 함께 늘어난다.
- 재생/일시정지 의미·접근 가능한 이름·키보드·포커스·disabled와 저장 dirty 상태를 유지한다. 네트워크/재생 상태 로직을 바꾸지 않는다. 이 지정 요소 외의 pill을 일괄 사각화하지 않는다.

## 5. 커뮤니티 재설계 — 보고서 §3 (사용자 결정 2026-11-10 반영)

> 이 절은 초안의 §5를 대체한다. 레퍼런스(Spotify 화면·크레마클럽)는 **와이어프레임 개념**으로만 쓰며 세부 요소(개인화 선반·앨범/날짜 열·셔플·다운로드·칩 줄)는 가져오지 않는다.
> 구현은 3단계다. **S1 프런트만 → S2 게시물 좋아요(백엔드+프런트) → S3 공개 녹음 재생(S3a 프런트 UI는 S1과 함께, S3b 녹음 파일 취득만 정책 결정 후)**. S2·S3b는 서버 계약 변경이라 §5.6~5.7의 별도 승인이 필요하다.
> 초안 §5의 **연습 기록 공유 진입(내 연습 공유하기 CTA·guest 로그인 CTA·티어/이름 안내·빈 상태 단계 안내)은 폐기하지 않았고 §5.2a로 유지**한다. 재설계 중 누락됐던 부분을 복원했다. 단, CM-UI 현행 계약상 공유 대상은 세션 통계·코멘트이며 **녹음은 공개되지 않는다**(CM-UI 안내문)는 점이 S3b의 전제 변경이다.

### 5.2 모두 탭 — 선반 순서와 카드

순서: **팔로잉 → 이달의 곡 → 연습 게시물(가로 한 줄) → 큐레이션 → 쇼케이스**. "최근 공개" 선반은 삭제하고 `sort=recent` 목록 호출·`recentMoreBtn`·`recentFolders` 상태를 제거한다.

| 선반 | 단위 | 데이터(기존) |
| --- | --- | --- |
| 팔로잉 | 폴더 | `curation.home().following` |
| 이달의 곡 | **곡 1개씩**(고정) | `monthlyPick.items` |
| 연습 게시물 | 기록 카드(가로 스크롤) | 기존 에피소드 피드 첫 페이지, "모두 표시"는 LOGS 탭 이동 |

- 카드 표지는 `coverVideoId`(없으면 `coverVideoIds[0]`) 단일 썸네일. DTO 필드는 유지한다. 오류·지연 로딩은 기존 대체 영역을 쓴다.
- 폴더 카드·곡 카드 모두 **빠른 추가**를 제공한다: 웹(`hover:hover`)은 카드 호버·포커스 시 썸네일에 `+` 버튼, 모바일은 **꾹 누르기**(약 500ms, 스크롤 이동 시 취소, 컨텍스트 메뉴 차단)로 하단 시트를 연다. 동작은 "내 곡 리스트에 추가"이며 폴더는 기존 `community.clone`을 재사용한다. 곡 1개·선택 곡 추가는 **기존 `POST /api/v1/songs`를 재사용**한다(§5.3 결정 근거). 임시 폴더로 감싸 `clone`하는 방식은 쓰지 않는다.
- 카드 본체를 누르면 상세(§5.3)가 열린다. `+`/꾹 누르기와 본체 클릭은 서로를 실행하지 않는다.

### 5.2a 소개와 연습 공유 진입 (초안 유지)

- 제목 COMMUNITY 아래 "서로의 연습 기록을 보고, 나의 성장을 공유하세요" 설명을 둔다. 소개·CTA 영역은 탭 위에 두고 선반보다 먼저 보인다.
- CTA **"내 연습 공유하기"** → 기존 `/log.html`(TRAILS). 보조 설명 "연습 세션을 선택한 뒤 공유할 수 있어요". 클릭만으로 게시·동의·유료 전환을 실행하지 않는다. 공개 이름이 없으면 §5.4 모달을 먼저 연다.
- guest에는 로그인 CTA(`/settings.html#account`)를 제공하고 인증 필수 API를 호출하지 않는다. `/me` 준비·실패를 guest/빈 피드로 대체하지 않는다.
- 무료 사용자는 기록 선택까지 진입하고 실제 공유는 기존 카드의 티어 안내를 따른다. CTA가 게시 완료를 보장한다고 표시하지 않는다.
- 전체 빈 상태 안내는 "아직 공유된 연습 기록이 없어요" + ① TRAILS에서 세션 선택 ② 공개 내용 확인 ③ 동의 후 공유 단계 안내. 실제 게시물처럼 꾸미지 않는다.

### 5.3 상세 화면 (폴더·곡 공통)

첨부 와이어프레임의 뼈대만 따른다: 상단 대형 썸네일·제목·메타(공개 이름·곡 수·총 길이) → 컨트롤 바 → 곡 목록.

- 컨트롤 바: **추가**(주 버튼, 재생 아님) · **부분 선택**(체크 후 선택 곡만 추가) · **공유** · **좋아요**(폴더, 기존 `setLike`) · 팔로우/신고(기존 `FolderSheet` 기능 유지). 재생·셔플·다운로드는 두지 않는다.
- 곡 목록 열: `# / 썸네일+제목+아티스트 / 구간(A–B·배속) / 길이`. 행 클릭은 기존 `itemPracticeHref`로 이동한다.
- **곡 단위 추가 결정**: (a) 곡 1개를 임시 공개 폴더로 감싸 `clone`하는 안은 **채택하지 않는다**. `clone`은 공개 폴더 행·카테고리 슬롯·`cloneCount`를 소비하고 본인 폴더 복제를 막으며 임시 폴더 정리·숨김이 필요해 DB 오염과 한도 오류를 만든다. (b) 기존 `POST /api/v1/songs`(videoId·title·artist·rate·a·b, 이미 있으면 200·새로 만들면 201로 멱등, 본문은 둘 다 `{song}`)로 충분하므로 **서버 변경이 없다**. 프런트 `apiClient.createSong`이 현재 `a`·`b`를 body에서 빼므로(`apiClient.ts:659-672`) 입력 타입에 선택 필드 `a?`,`b?`를 더해 전달한다(서버 입력은 이미 `a`,`b` 지원). 선택 곡은 순차 호출하고 행별 “내 곡 리스트에 있음”·서버 오류(한도 초과 등 그대로)를 표시한다(§1.1 RV-4). 카테고리 지정이 필요하면 별도 결정이다.
- 기존 `FolderSheet`의 좋아요·팔로우·복제·신고 권한·오류 계약은 CM-UI 그대로 유지한다. 모바일은 시트가 전체 높이를 쓰고 닫기·포커스 복귀를 유지한다.

### 5.4 이름 설정 모달

- 로그인·`me` 준비 후 `publicName`이 없고 이번 세션에서 건너뛰지 않았으면 모달을 연다. 기존 인라인 배너는 제거한다. 입력은 기존 `PublicNameForm`을 재사용하며 서버 가드(2~20자·7일 제한·금칙어·중복)를 그대로 표시한다.
- 닫기·ESC·건너뛰기는 허용한다. 건너뛴 사실은 세션 한정(브라우저 `sessionStorage`, 읽기·쓰기 실패 시 건너뛰기 미기억)으로만 둔다.
- 이름이 없는 상태에서 **공유 시도**(내 연습 공유하기, 게시/폴더 공개 동작)는 실행하지 않고 모달을 다시 연다. 이름 저장 성공 후에만 원래 동작을 이어 간다. 자동 게시·자동 재시도는 없다.
- 포커스 트랩, 열기 전 포커스 복귀, 배경 스크롤 잠금을 지킨다. 저장 중 중복 제출 잠금, 실패 시 입력 유지.

### 5.5 LOGS 탭 — 피드 전용

- LOGS는 에피소드 게시물 피드만 표시하는 **핀터레스트형 마소니**다(데스크톱 3열, 768px 2열, 390px 1열, CSS columns로 구현하고 의존성을 추가하지 않는다). 폴더 선반·소개 영역은 없다.
- 카드는 썸네일(영상)·제목·공개 이름·요약 통계·재생(영상)·신고·좋아요(S2)를 가진다. 전체/팔로잉 범위 선택을 유지하고 더보기 실패 시 기존 카드·cursor를 보존한다.
- 집계/내 공유 폴더 링크는 보조 탐색으로 유지한다. `/community.html#all|#log|#summary|#my-shares`의 해시는 호환 유지하며 `#logs`를 추가하고 `#log`는 같은 탭으로 연결한다.
- guest·`me` 준비/실패·uid 전환 시 늦은 응답 폐기 가드는 현행(uid+요청 토큰)을 유지한다.

### 5.6 S2 — 게시물 좋아요 (서버 계약 변경, 별도 승인)

현재 좋아요는 폴더에만 있다. 게시물 좋아요를 위해 필요한 변경: ① 좋아요 테이블(게시물 ID·사용자 ID 고유, 게시물 삭제/철회 시 정리) ② `PUT/DELETE` 게시물 좋아요 API(폴더 방식과 같은 멱등·**본인 게시물 좋아요 허용(결정)**·숨김/철회 게시물 404) ③ `PublicEpisodeLogDto`에 `likeCount`·`likedByMe` 추가(기존 필드 유지) ④ guest 호출 거부, 서버 집계 기준. 프런트는 낙관적 갱신 없이 응답 값으로 반영하고 실패 시 이전 값을 유지한다. 테스트·DB 마이그레이션 범위는 착수 시 `docs/rules/backend-kotlin.md`에 따라 진행 파일에 확정한다.

### 5.7 S3 — 공개 녹음 재생

CM-UI 현행 계약은 녹음을 공개하지 않는다. 결정에 따라 **재생 버튼 UI(S3a)는 지금 만들고, 녹음 파일을 가져오는 부분(S3b)만 정책 결정 뒤로 미룬다.**

- **S3a(S1과 함께, 프런트만)**: 카드에 녹음 재생 버튼과 상태(대기·로딩·재생 중·오류), 하나만 재생되는 단일 플레이어, 오디오 초기화 순서(pause → removeAttribute('src') → load → dataset 제거), 카드 폐기·탭·계정 전환 시 요청 무효화를 구현한다. 음원 URL 취득은 `TODO(stub): S3b 공개 녹음 URL API` 주입점 한 곳에만 둔다. 서버 응답에 녹음이 없으면 버튼은 비표시이고 영상 재생만 보인다. 가짜 녹음·mock 음원은 만들지 않는다.
- **S3b(정책 결정 후, 서버 변경)**:

| 결정 필요 | 제안(미확정) |
| --- | --- |
| 공개 대상 녹음 | 게시 시 세션 테이크 중 **하나를 명시 선택**해 공개 동의(기본 비공개) |
| 접근 방식 | 공개 전용 서명 URL(만료), storageKey는 DTO에 노출하지 않음 |
| 철회·신고·숨김 | 즉시 서명 발급 차단, 이미 발급된 URL 만료 정책 |
| 쿼터·트래픽 | 재생 횟수·비용 상한과 티어 정책, 동의 문구(CM-UI 안내문 개정) |

### 5.8 mock·관리자 확인 절차 (개발 전용)

- 데이터가 없어 확인할 수 없을 때는 **개발 빌드 + `?mock=1`**에서만 프런트 mock(검은 표지 임시 폴더·곡·게시물)을 주입한다. 프로덕션 번들·서버·DB는 건드리지 않고, 폴더 상세의 곡 목록은 mock으로 검증하지 않는다.

### 5.9 상태·오류

피드·선반 각각 독립 상태다. 로딩·오류·성공 빈 상태를 구별하고 한 선반 실패가 다른 선반을 지우지 않으며 실패 영역만 재시도한다. 큐레이션 성공 빈 문구는 커뮤니티 전용 번역 키를 쓴다(`discover.empty`는 홈 문구라 변경하지 않는다). 번역은 ko/en/ja 동일 키로 추가한다.

## 6. 악기 선택·스케일·튜닝 — 보고서 §4~§6

### 6.1 악기 선택과 접이식 설정

- `#instrument-kind`는 동일 높이 44px 이상, 각 최소 폭 72px의 가로 pill 버튼군이다. 그룹에 필요한 폭을 부여하고 버튼의 축소·텍스트 줄바꿈을 막는다. 옆 컨트롤과 공간이 부족하면 그룹 전체를 다음 행으로 보낸다. 그룹 내부 8px 간격, 버튼 테두리 겹침 0건. pill은 유지한다.
- 기타/베이스에서는 `악기 설정`을 native details/summary로 표시하고 기본 접힘으로 둔다. 펼쳤을 때 기존 `#instrument-tuning`과 label을 그대로 사용한다. 별도 모달/라우트/저장 UI를 만들지 않는다.
- 접힘 중에도 선택 튜닝 이름을 summary에 표시한다. 변경은 즉시 적용하며 저장 버튼은 없다. 페이지를 떠나면 현재 구현처럼 초기화되고 장치·계정 간 동기화되지 않는다.
- 건반은 튜닝 설정을 숨긴다. 기타/베이스 전환 시 각각 마지막 페이지 내 선택값을 유지한다. 다른 악기 튜닝을 강제로 fallback하거나 새 기본값으로 저장하지 않는다.
- changeInstrument/changeTuning의 재생 중지, 유효 탭 전환, 포지션·줌·더블스톱 안전 페어 정규화를 유지한다. DS 화면의 기존 튜닝 제어도 유지한다. details의 키보드 조작과 접힘 내부 포커스 제외를 확인한다.

### 6.2 스케일 제어의 의미별 행

스케일 탭에만 전용 컨테이너/클래스를 추가한다. 공용 `.controls/.chips/.check`를 바꿔 다른 탭의 배치를 함께 변경하지 않는다.

1. 기본 설정 행: 연습 모드 → 루트 음 → 스케일 종류. circle 모드에서만 진행 방향 → 키별 마디 수를 다음 보조 행에 표시한다.
2. 표시 설정 행: 음표 라벨 → 손잡이(건반 숨김) → 재생 범위.
3. 재생 행: BPM → 근음만 보기 → 재생/중지 → 상태 문구. 상태 문구는 공간이 부족하면 별도 줄로 흐른다.

복합 버튼군을 150px 칸에 넣지 않는다. 각 그룹은 내용에 필요한 폭을 차지하고 그룹 단위로 줄바꿈한다. 390px에서는 필드별 세로 적층으로 읽기 순서를 유지하며 그룹 내 짧은 버튼은 가로로 유지한다. 긴 언어에서 한 그룹이 가용 폭을 넘으면 그룹 내부 다음 줄도 허용하되, 버튼 텍스트 자체는 한 줄·테두리 비겹침을 지킨다.

label은 공통 글꼴·line-height·최소 16px로 맞추되 번역 줄바꿈을 잘라내지 않는다. select/input/button은 44px 이상으로 높이를 맞춘다. checkbox는 같은 44px 이상 행의 가운데에 두고 임의 padding-bottom 오프셋을 제거한다. BPM의 기존 30~220, 모드/simple·circle, 라벨/hand/range 값과 재생 핸들러는 유지한다. hidden 요소에는 display 규칙이 우선하지 않도록 명시해 건반/모드별 숨김 제어가 실제로 보이지 않아야 한다.

## 7. 재해석 배치 — 보고서 §7

- 컨테이너는 1024px 미만 1열, 1024px 이상 `minmax(0,1.2fr) minmax(0,1fr)` 2열, gap 24px이다. 왼쪽은 현재 형태·해석 → 키/BPM/진행 재생 → 2-5-1 카드, 오른쪽은 퀴즈 제목·형태·점수·질문·선택지·피드백·다음 문제다. DOM 읽기 순서도 왼쪽 후 오른쪽으로 한다.
- `#ri-swap`은 768px 이상 3개 같은 폭, 미만 1열로 한다. diagram은 비율을 유지해 셀 안에 맞추고 고정폭 SVG가 이웃 칸을 침범하지 않게 한다. 불가능한 형태 안내도 셀 크기 규칙을 따른다.
- 퀴즈 선택지는 768px 이상 2열, 미만 1열이다. 긴 정답 텍스트는 줄바꿈 가능하며 모든 내용을 읽을 수 있어야 한다. 점수·단일 채점 잠금·정답/오답 피드백·다음 문제·건반 다이어그램을 유지한다.
- 상위 행의 두 패널은 윗선을 맞추고 내용 높이는 독립적으로 둔다. 억지 하단 정렬·빈 높이 채우기·그림 과대 확대는 하지 않는다. ri 전용 클래스로 구현해 공용 `.boxrow/.cell/.quiz` 사용 화면에 전파하지 않는다.
