## 1. 목표·적용 경계

영상 아래에 재생·녹음 조작을 모으고 오른쪽에는 구간 설정과 선택 폴더 곡 목록을 배치한다. 영상 아래의 불필요한 공백과 곡 목록 서랍의 반복 개방을 줄인다. 기존 연습 기록은 상단 연습 영역 다음에 전체 폭으로 유지한다.

- 이번 승인은 **문서 작성만**이다. 구현·커밋·push·PR·배포는 포함하지 않는다.
- 새 서버 API·DB·DTO·함수 시그니처·export·라우트·저장소 키 변경 없음. `apiClient` 목록 응답의 잘못된 형태를 오류로 드러내는 변경은 §5에 한정한다.
- 선택 폴더는 기존 개인 분류(Category)이며 YouTube 재생목록과 다르다. 자동 다음 곡 재생, 재정렬, 폴더 CRUD, 공개 목록, 다른 앱 데이터 fallback은 추가하지 않는다.
- UXR-1의 기록 단일화·A/B 슬롯·트랜스포트 디자인 결정을 보존한다. 새 명세가 바꾸는 범위는 상단 배치와 목록 탐색뿐이다.
- 단일 Step UXR-3으로 수행한다. 기존 UIUX-R의 UXR-1·UXR-2에 이은 세 번째 Step이며 기능을 추가로 쪼개지 않는다.

## 3. 배치 약속

### 3.1 데스크톱: viewport 961px 이상

기존 player shell 최대폭 1120px과 좌우 여백, 영상 열/360px 우측 열, 열 사이 16px을 유지한다. 첨부 그림은 구조 참고이며 픽셀 복사 기준이 아니다.

```text
곡 제목·계정 상태                         분류 / 곡 목록
┌──────────────────────────┐ ┌──────────────────┐
│ 영상 16:9                │ │ 속도·A/B·반복    │
│                          │ │ 대기·프리셋      │
└──────────────────────────┘ └──────────────────┘
타임라인                     ┌──────────────────┐
┌──────────┐ ┌─────────────┐  │ 선택 폴더명·변경 │
│ 재생 5개 │ │ 녹음·Drive │  │ 곡 목록          │
│ 키 안내  │ │ 상태·오류  │  │ (내부 스크롤)    │
└──────────┘ └─────────────┘  └──────────────────┘
이 곡의 연습 기록 / 기록 패널 (전체 폭)
```

- 왼쪽: 영상 → 타임라인 → 조작 행. 조작 행은 재생/녹음 두 칸, `minmax(0, 1fr)` 동등 열, 간격 12px. 재생 5버튼은 한 줄을 유지하고 녹음의 보조 액션은 wrap한다.
- 오른쪽: 구간 설정 → 선택 폴더 패널, 간격 16px. 속도·A/B·대기·프리셋의 순서·확인 가드를 보존한다.
- 영상과 설정 카드 윗선 일치: `practice-top:top@961`. 조작 두 칸 윗선 일치: `practice-actions:top@961`. 두 칸의 높이·아랫선 강제 일치는 하지 않는다.
- 기존 `transport:top,bottom,height`, 영상 열과 기록 영역의 왼선 약속을 유지한다. 오른쪽 두 카드의 left/right는 `practice-side:left,right`로 맞춘다.
- 곡 목록 본문은 최대 높이 320px, `overflow-y: auto`, 내용이 적으면 자연 높이. 제목·폴더 선택·오류·재시도는 스크롤 본문 밖에 둔다. 줄 수 때문에 상단 영역 높이가 무한 증가하지 않는다.
- 우측 목록과 왼쪽 조작 영역의 아랫선은 맞추지 않는다. 오류·녹음 미리 듣기에는 필요한 높이를 허용한다. 기록은 양쪽 열 중 더 긴 열 다음에 24px 간격으로 시작한다.

### 3.2 태블릿·모바일: viewport 960px 이하

- 단일 열, DOM/읽기/Tab 순서: 제목 → 영상 → 타임라인 → 재생 → 녹음 → 구간 설정 → 선택 폴더 목록 → 연습 기록.
- 재생과 녹음은 각각 전체 폭. 현재 640~960px `.ppCtl` 2열 규칙은 새 구조에 맞춰 해제하여 재생·녹음·구간이 섞이지 않게 한다.
- 폴더 목록은 기본 접힘. 헤더에 폴더명·곡 수·펼치기 버튼 표시, 펼치면 본문 최대 높이 320px. 접힌 상태에서도 폴더 변경 가능. 홈 폴더 진입은 목록을 펼치되 자동 재생·강제 페이지 스크롤 없음.
- 960↔961 전환은 선택 폴더·곡·재생 위치·진행 중 녹음을 보존한다. 단일 DOM을 CSS로 재배치하며 iframe·MediaRecorder·오디오를 폭 변경 때문에 재마운트하지 않는다. 접힘 선택은 마운트 중 보존하고 데스크톱에서는 항상 표시한다.
- 버튼 글자가 길어지면 녹음 보조 액션·헤더 액션이 wrap한다. 주 트랜스포트 5버튼 정렬은 유지한다. 페이지 가로 스크롤 금지. 390·768에서는 주요 버튼 높이 44px 이상을 목표로 한다.

## 4. 선택 폴더·곡 목록 계약

### 4.1 상태와 초기 선택

새 상태는 페이지 내부 `selectedFolderId`(전체/미분류/분류 ID), `listStatus`(idle/loading/success/error), 목록 오류, 모바일 펼침이다. 전체/미분류는 서버로 보내지 않는 가상 선택지이고 서버 ID와 구분한다. 영구 저장·새 URL parameter는 추가하지 않는다.

1. 홈의 기존 `takeOpenCategory()` 값이 있고 현재 사용자의 분류 조회가 성공하면 그 분류를 선택한다. 현재 리비전의 자동 서랍 개방을 인라인 목록 선택으로 대체한다.
2. 전달값이 삭제됐거나 현재 사용자에게 없으면 `전체 곡`을 선택하고 “선택한 폴더를 찾을 수 없어 전체 곡을 표시합니다”를 알린다. 조회 실패는 삭제로 판단하지 않는다.
3. 직접 URL 진입·홈 전달값 없음·새 계정은 `전체 곡` 기본값. 현재 곡이 여러 분류에 속해도 임의로 첫 분류를 고르지 않는다.
4. 폴더 선택은 곡을 바꾸거나 녹음을 중지하지 않는다. 곡을 바꿔도 폴더 선택은 유지한다. 선택 폴더에 현재 곡이 없으면 잘못된 항목 강조 없이 “현재 곡은 이 폴더에 없습니다” 안내만 표시한다.
5. 분류 선택지는 전체 곡 → `sortOrder` 오름차순 분류 → 미분류. 동순위는 응답 순서 유지. 미분류는 유효한 분류 ID가 하나도 없는 곡, 0곡이어도 선택 가능하다. 분류가 없으면 전체/미분류 모두 전체 곡과 동일한 결과다.
6. 곡 순서는 기존 목록 응답 순서를 보존한다. 한 폴더 안에서는 곡 ID별 1개. 여러 분류에 속하는 곡은 각 분류에서 보일 수 있다. 헤더 곡 수는 로드된 목록에서 계산하여 `songCount`와 중복 집계하지 않는다.

### 4.2 변경·곡 이동·기존 서랍

- 인라인 헤더의 `폴더 변경`은 라벨이 연결된 native select로 제공한다. 보조 헤더는 선택 폴더명과 `N곡`. 폴더 변경 후 목록 본문 scrollTop=0. 자동 재생 없음.
- 현재 곡은 `aria-current="true"`와 명도/테두리로 표시한다. 항목 제목은 줄바꿈하고 메타는 기존 상태·A/B·배속·최근 날짜를 유지한다. 현재 곡 재클릭은 재시작·녹음 중지를 유발하지 않는다.
- 다른 곡은 기존 `openSongById`를 통해 이동하며 진행 저장·녹음 종료·동기화 오류를 보존한다. 새로 동등한 재생 코드를 만들지 않는다. 전환 중 곡 항목을 비활성화하여 중복 저장·중복 전환을 막고, 종료/실패 시 복원한다. 선택 강조는 실제 videoId에만 따른다.
- 목록을 바꿀 때 현재 곡이 포함되면 해당 행만 목록 내부에서 보이게 한다. 문서 전체를 강제로 스크롤하지 않는다. 키보드 초점은 클릭한 컨트롤에 유지한다.
- 상단 `곡 목록` 서랍은 **유지**한다. 전체 폴더 탐색·URL 열기·YouTube 재생목록 가져오기를 제공한다. 인라인은 단일 폴더 탐색에 집중하며 URL 폼을 중복 추가하지 않는다.
- 서랍의 다른 폴더 곡을 선택하면 그 폴더를 인라인 선택에도 반영한다(평면 목록에서는 전체). 서랍 열기/접기만으로 인라인 선택을 바꾸지 않는다. 동일 곡 재클릭이면 서랍만 닫는다.
- 성공한 분류 할당·곡 추가·가져오기 후 동일한 목록을 재조회한다. 삭제된 선택 폴더는 성공 응답 확인 뒤 전체로 전환·안내한다. 조회 실패로 폴더를 전체로 바꾸지 않는다. 다른 화면 변경 감지는 서랍 개방 또는 명시 재시도로 하고 polling은 추가하지 않는다.

| 곡 또는 분류 실패/잘못된 envelope | “곡 목록을 불러오지 못했습니다” + `다시 시도` | 성공 0곡과 구분. 오류 영역만 재조회, 영상·구간·녹음 유지. 실패 시 이전 목록을 클릭 가능하게 남기지 않음 |
| 인증 실패/로그아웃 | 기존 인증 처리와 로그인 안내 | 이전 사용자 목록·분류명·선택·오류·스크롤 즉시 초기화 |
| A→B→A·늦은 응답 | 새 사용자의 loading/success만 표시 | uid + 증가 request sequence 모두 검사. 같은 uid로 돌아와도 이전 세대 응답 폐기 |

목록 조회는 로그인한 페이지 진입 시(영상 없어도) 시작한다. 서랍·인라인은 같은 데이터/로더를 공유한다. 재시도·계정 변경·성공 후 재조회·unmount 때 이전 세대를 무효화한다. 모든 await 이후 성공/실패/잠금 해제를 갱신하기 전 uid·세대를 확인한다. 분류만 따로 늦게 도착해 새 선택을 덮지 않도록 기존 별도 분류 조회도 동일 세대에 통합한다.

## 5. 데이터·API·오류 경계

| API/DTO | 읽는 값·용도 | 유지 계약 |
| --- | --- | --- |
| `GET /api/v1/songs` | 응답 `songs` 배열. 항목 `id`, `videoId`, `title`, `categoryIds`, `status`, `a`, `b`, `rate`, `lastDate`로 목록·필터·이동 구성 | 인증 사용자 소유·200·no-store. SongDto의 artist/statusCode/pos/memo/totalSeconds/resumeUrl/durationSec 등 나머지 필드도 제거·재정의하지 않음 |
| `GET /api/v1/categories` | 응답 `categories` 배열. `id`, `name`, `sortOrder`; `onHome`은 홈 노출 설정이며 이 화면 필터에서 제외 조건 아님. `songCount`는 응답 유지 | 인증 사용자 소유·200·no-store. 서버에 폴더 ID 필터 추가 없음 |
| 기존 저장·프리셋·녹음·분류 갱신 | 기존 요청 payload·오류 처리·상태 코드·소유권 유지 | 이번 작업은 UI 이동/재조회만 수행 |

- `apiClient`의 `listSongs`와 `categoryList`에서 envelope/배열의 부재·null·객체 오형태를 예외로 전달한다. 올바른 `[]`는 성공 0곡이다. 목록 화면의 별도 `catch(() => [])`와 중복 `Array.isArray(...) ? ... : []`로 오류를 다시 숨기지 않는다.
- 이 변경은 명세 검토 대상인 클라이언트 오류 처리이며 서버 계약·public 함수 시그니처는 유지한다. 공용 목록 소비자인 홈/분류 화면 회귀도 확인한다. 앱 전체 DTO validation 리팩터링은 범위 밖이다.
- 401은 기존 인증 경로, 기타 HTTP/네트워크/응답 형태 실패는 재시도 가능한 목록 오류로 처리한다. 새 서버 오류 코드·임의 샘플 목록·다른 앱/계정 데이터 fallback 없음.

## 6. 녹음·Drive·접근성

| 상태 | 녹음 카드 내 표시·조작 |
| --- | --- |
| 대기 | 녹음 버튼과 짧은 안내. 로그인+Drive 미연결이면 “Google Drive 연결” 액션과 기존 무료 저장 제한 안내를 축약 표시하되 실제 제한 의미 보존 |
| 녹음 중 | 정지 버튼·경과 시간·상태가 최우선. 정지 버튼 활성 유지. Drive 연결은 진행 중 녹음이 끝날 때까지 비활성화 |
| 업로드 중 | 업로드 상태 표시, 중복 녹음/재시도/Drive 연결 비활성화. 미리 듣기·파일 저장은 기존 조건 유지 |
| 업로드 실패 | 실패 이유·재업로드·파일 저장을 보존. Drive 안내보다 오류를 먼저 읽을 수 있게 배치 |
| Drive 연결 중/실패/완료 | 기존 연결 상태·실패 메시지 유지. 연결 완료하면 연결 버튼 대신 짧은 연결됨 표시. guest에는 연결 배너 없음 |
| 영상 없음 | 기존 URL 입력 빈 화면 유지, 녹음 시작 비활성. 로그인 목록은 사용 가능하여 목록에서 첫 곡을 열 수 있음 |

- 녹음 묶음(`#recBtn`, `#recRetry`, `#recSave`, `#recPlay`, `#recMsg`, Drive 연결 안내)을 통째로 이동하고 각 ID는 문서에 1개만 둔다. 기존 limit 모달·재업로드·오디오 정리·곡 귀속·A/B 기록 기능 보존.
- Drive 미연결을 실패로 표현하지 않는다. 배너 크기를 줄여도 저장 위치/제한·연결 효과를 삭제하지 않는다. 문구는 ko/en/ja 동일 의미로 i18n 키에 둔다.
- 녹음·오류 메시지는 기존 `aria-live=polite` 유지. 목록 상태도 polite로 알리되 초 단위 녹음 타이머를 새 live 영역에 중복 낭독하지 않는다.
- 모바일 펼치기 버튼은 `aria-expanded`, `aria-controls`; 접힌 본문은 Tab/스크린리더 탐색에서 제외한다. native select에 명시적 label. 키보드로 마지막 곡까지 접근하고 focus ring이 스크롤 영역에서 잘리지 않는다.
- 분류 선택은 곡의 분류 할당 버튼과 구분하여 ‘폴더 변경’으로 부른다. 오류·로딩 안내는 색만으로 구분하지 않는다. 기존 테마 토큰·직각 5버튼 디자인을 유지한다.
