## 1. 목표·승인 경계

앱 번들(iOS `capacitor://localhost`, Android `https://localhost`)에서 운영 API를 호출하고 Google 로그인 → 앱 복귀 → 세션 복원 → 본인 데이터 조회/저장·로그아웃까지 연결한다. 웹의 같은 출처 API·Google 로그인과 확장 출처 허용을 유지한다.

M1A-2 A1~A6 검수를 반복하지 않는다. 플레이어 버튼 배치 개선은 계획 §4의 별도 검토 후보다. Apple 로그인·Drive용 Google 권한 획득·범용 딥링크 라우터·오디오/화면 유지·스토어 제출은 M0-3 범위이며 이번 완료를 뜻하지 않는다. Google 로그인 성공을 Drive 연결 성공으로 표시하지 않는다.

### 2.1 외부 근거(2026-11-16 조회)

- [Supabase PKCE](https://supabase.com/docs/guides/auth/sessions/pkce-flow): code 교환·1회 사용·5분 유효기간. 앱의 대기 제한과 code 유효기간은 별개다.
- [고정 SDK 2.118.0 소스](https://raw.githubusercontent.com/supabase/supabase-js/v2.118.0/packages/core/auth-js/src/GoTrueClient.ts): `signInWithOAuth`의 `data.url`·`data.flowId`, `skipBrowserRedirect`, `exchangeCodeForSession(code, { flowId })` 확인. 교환 중 SDK 자체 저장·SIGNED_IN 통지가 먼저 발생하므로 Promise 반환 뒤 generation 검사만으로 취소를 막을 수 없다. verifier는 SDK가 관리한다.
- [Capacitor App v8](https://capacitorjs.com/docs/apis/app): custom scheme 등록, `appUrlOpen`·`getLaunchUrl` 수신. [Browser v8](https://capacitorjs.com/docs/apis/browser): 시스템 브라우저 UI·`browserFinished` 사용. Android 복귀/닫힘 순서를 성공 판정으로 사용하지 않는다.
- [Ktor 3.5.2 CORS 소스](https://raw.githubusercontent.com/ktorio/ktor/3.5.2/ktor-server/ktor-server-plugins/ktor-server-cors/common/src/io/ktor/server/plugins/cors/CORSConfig.kt): 정확한 origin predicate와 Content-Disposition 노출을 사용할 수 있다. 이는 변경안이며 현재 운영 허용 상태의 증거가 아니다.

## 3. API 출처·빌드·CORS 변경 계약

### 3.1 앱 설정

- `buildAppWeb` 기존 객체 인자에 optional `apiBaseUrl`만 추가한다. CLI 입력은 `APP_API_BASE_URL`; 미설정 때 `https://ulevelp-d5ympfsmfq-du.a.run.app`. 기존 `APP_PLAYER_EMBED_URL`은 독립 유지한다.
- 입력은 trim 후 HTTPS **Origin**만 허용(루트 `/`·후행 slash는 제거). 빈 명시값, http, credentials, query, hash, 루트 외 pathname은 빌드 실패. 생성/삭제 전에 검증하여 기존 outDir을 손상시키지 않는다. 다른 HTTPS 환경은 명시 입력으로만 사용한다.
- `dist-app/config.js` 끝에 `window.ULEVELP_CONFIG.apiBaseUrl = <JSON 문자열>;`를 주입하고 모든 11개 진입 HTML의 CSP `connect-src`에 그 Origin을 정확히 한 번 추가한다. 지시문/meta 부재는 실패. 기존 frame-src·Supabase·Drive 허용을 유지한다.
- `public/config.js`·`dist/index.html`·웹 빌드 CSP를 변경하지 않는다. 웹은 apiBaseUrl 빈 값일 때 기존 상대 경로 사용. 웹과 앱 빌드 결과를 교차 확인한다.
- 새 내부 모듈 `frontend/src/lib/apiUrl.ts`의 `resolveApiUrl(path: string): string`을 JSON·keepalive·ZIP·take fetch가 공통 사용한다. 입력 path는 `/api/v1/` 아래 상대 경로만 허용; 외부 URL·`//`·경로 탈출을 거부한다. 토큰을 임의 외부 URL로 보내지 않는다. 기존 공개 apiClient 함수 시그니처/export는 유지한다.

### 3.2 요청·응답 헤더

| 대상 | 계약 |
| --- | --- |
| 요청 | 현재 Supabase access token만 `Authorization: Bearer <token>`. 토큰은 URL·로그에 넣지 않는다. JSON은 기존 Content-Type 유지, FormData 경계는 브라우저 생성. `Accept-Language`는 getLang()의 ko/en/ja를 호출 때 넣고 호출자가 명시한 값은 보존 |
| keepalive | 기존 동기 세션 캡처·keepalive=true·payload 유지. 로그아웃 상태에서 인증 저장을 보내지 않음. 요청 당시 uid의 토큰으로만 전송하며 나중 계정의 토큰으로 재시도하지 않음 |
| ZIP·take blob | Bearer/locale 및 공통 base 적용. 응답 blob 소비 전후 uid·generation 검사. ZIP Content-Disposition 파일명을 읽을 수 있게 함. 파일 시스템 저장/공유 UI 신규 기능은 제외 |
| 쿠키 | 앱은 Bearer 인증. credentials=include나 쿠키 인증을 추가하지 않음. 서버의 기존 allowCredentials=true는 웹 호환을 위해 유지 |

CORS는 `ALLOWED_ORIGINS`에 포함된 두 모바일 문자열에만 `allowOrigins { origin == 등록값 }` 방식으로 정확히 허용한다. 일반 웹·확장 origin은 기존 allowHost 경로 유지. `capacitor://localhost.evil`·다른 포트/대소문자 변형·null·http localhost는 기본 거부. 신뢰 도메인을 Origin 없이 인증 우회하는 기능은 추가하지 않는다.

메서드 OPTIONS/GET/POST/PUT/PATCH/DELETE/HEAD 유지. 기존 3개 요청 헤더에 Accept-Language를 명시하고 `exposeHeader(HttpHeaders.ContentDisposition)` 추가. 정상/401/400/404 응답에 허용 Origin의 ACAO가 붙고 preflight는 인증 없이 처리되어야 한다. 불허 Origin은 403·ACAO 없음·라우트/DB 무실행이며 표준 JSON 에러를 보장하지 않는다. 응답을 이미 보냈으면 라우트를 멈추는 기존 가드를 유지한다.

운영 적용은 별도 배포 승인 후, 실제 기존 ALLOWED_ORIGINS를 읽고 웹+확장+모바일을 합친 전체값으로 주입한다. 저장소/CI 기본값을 모바일이나 개발 localhost로 바꾸지 않는다. URL scheme은 Origin 허용이지 신원 증명이 아니며 JWT 검증을 유지한다.

## 4. 유지하는 서버 필드·오류/상태

DB·Ktor API 경로·필드·상태 코드는 변경하지 않는다. Google 인증/토큰 교환은 Supabase SDK가 수행하며 Ktor `/login`·`/callback` API는 만들지 않는다.

| 호출 | 입력 | 정상 응답 | 실패 |
| --- | --- | --- | --- |
| GET /api/v1/me | body 없음, Bearer·locale | 200, 아래 MeResponseDto 전체, Cache-Control:no-store | 인증 누락/만료/위조 401 UNAUTHORIZED. DB 미연결 503 DB_UNAVAILABLE, 미처리 서버 오류 500 INTERNAL_ERROR(기존 계약) |
| PATCH /api/v1/me | 기존 프로필 JSON만. 이번 회귀는 `{displayName: string}`·`{locale: ko/en/ja/null}` 사용 | 200 같은 DTO | 잘못된 타입/값 400 INVALID_INPUT. displayName trim 후 최대 100자. 요청 userId로 주체를 선택하지 않음 |
| GET /api/v1/export/zip | includeAudio=true/false(생략 true) | 200 application/zip, Content-Disposition attachment 파일명 | 다른 includeAudio 400 INVALID_INPUT; 미인증 401 |
| 기존 사용자 곡·세션·take API | 기존 URL·body 그대로, JWT 주체 | 기존 DTO·상태 | 없는/타인 단건 404 NOT_FOUND, 목록 타인 행 0. 기존 오류 우선순위 유지 |

`MeResponseDto` 전 필드(서버 ProfileService.kt:35-62·TierService.kt:61-81 확인):

- 문자열: `id`, `email`, `displayName`, `role`, `storageProvider`, `tier`, `billingTier`, `creatorBio`.
- nullable 문자열: `driveFolderId`, `migratedLocalAt`, `tierOverrideUntil`, `locale`, `creatorBadge`, `publicName`, `publicNameNextChangeAt`. 시각은 기존 ISO UTC, locale은 ko/en/ja/null.
- 정수: `takeUsedBytes`, `takeQuotaBytes`. 불리언: `isCreator`, `shareAutosync`, `sharePracticeLog`.
- `keys: { notion: null | { hint: string, updatedAt: string } }`.
- `limits: { songs: int|null, categories: int|null, takeBytes: long, takeSongs: int|null, takeDurationSec: int|null, drive: boolean, ai: boolean, communityWrite: boolean }`.
- `usage: { songs: long, categories: long, takeBytes: long, takeSongs: long }`, `credits: { monthly: int, purchased: int }`.

유지하는 PATCH 필드 전수: `displayName?:string`(trim·100자 이하), `storageProvider?:'supabase'|'drive'`, `driveFolderId?:string|null`(trim·빈 값→null), `migratedLocalAt?:ISO-8601 string|null`, `shareAutosync?:boolean`, `sharePracticeLog?:boolean`, `locale?:'ko'|'en'|'ja'|null`. 생략은 기존 값 유지, nullable 필드의 명시 null은 비움. 타입/값/JSON 객체 형식 오류는 400 INVALID_INPUT. 공유 켜기는 기존 `403 TIER_UPGRADE_REQUIRED`, 학습 기록 공유에 공개 이름이 없으면 `409 PUBLIC_NAME_REQUIRED`를 유지한다(`ProfileService.kt:161-271`, `TierService.kt:303-306`). 이 기능의 정책 변경은 범위 밖이다. 기존 DELETE /me의 confirmText 계약도 변경하지 않는다.

표준 오류 DTO는 `src/main/kotlin/ulevelp/api/ApiError.kt:18-28`: `ok:false`, `source:string`(기본 server), `status:int`, `code:string`, `message:string`, `retryAfter:int|null`, 선택 `detail:object`(null이면 생략). 프런트 `ApiClientError.status/code/data`를 유지한다. CORS/CSP/네트워크 실패에 HTTP status/code를 꾸며 넣지 않는다. 204의 기존 requestApi null 처리는 유지하되 /me의 정상 상태는 200이다.

### 5.1 SDK·공개 타입

기존 `auth.signIn(redirectTo?: string): Promise<void>`·`signOut(): Promise<void>`와 다른 export를 유지한다. native만 detectSessionInUrl=false로 둔다. flowType=pkce/storageKey/persist/autoRefresh는 유지한다. native의 redirectTo 인자는 외부 복귀 URL로 사용하지 않는다.

`SupabaseClientLike.auth.signInWithOAuth` options에 optional skipBrowserRedirect, data에 `{provider: 'google', url: string|null, flowId: string|null}`을 정의한다. `exchangeCodeForSession(code: string, options?: {flowId?: string})`와 반환형 `{data: {session: SupabaseSessionLike|null, user: SupabaseUserLike|null}, error?: Error|null}`을 추가한다. 수동 setSession 경로는 추가하지 않는다.

AuthState에 optional `login?: {status: 'idle'|'opening'|'waiting'|'exchanging'|'error'; errorCode: string|null}`을 추가하고 getSnapshot에서는 항상 반환한다. 기존 user/session/me와 구분한다. native signIn Promise는 성공·취소·실패로 끝나고 중복 시작은 기존 pending Promise에 합류한다. 인증된 상태에서는 재로그인하지 않는다. 계정 전환은 로그아웃 후 시작한다.

### 5.2 상태 전이와 콜백 검증

1. App listener를 한 번 등록한 뒤 getLaunchUrl도 같은 handler에 전달한다. SDK 초기 복원 완료 후 처리하고 중복 warm/cold 통지는 한 번만 소비한다. 자신이 소유한 listener handle만 해제한다.
2. idle→opening: generation을 캡처하고 SDK에 `{provider:'google', options:{redirectTo:'ulevelp://auth/callback', skipBrowserRedirect:true}}`를 준다. data.url은 설정된 Supabase Origin의 `/auth/v1/authorize` HTTPS URL로 제한해 Browser.open에 전달한다. data.flowId가 필수이며 빈/외부 임의 URL은 실패한다.
3. Browser를 열기 전에 localStorage `ulp:native-oauth`에 `{version:1, flowId:string, startedAt:number}`를 저장한다. 비밀·code·token·verifier를 별도로 저장/출력하지 않는다. 저장 불가면 시작 실패. 앱 대기 유효기간은 10분, code 자체의 5분 기한은 SDK가 검증한다. cold 시작도 이 기록과 SDK verifier를 사용한다.
4. waiting→exchanging: URL의 protocol=ulevelp:, host=auth, pathname=/callback, userinfo/port/hash 없음을 검사한다. code는 비어 있지 않은 단일 파라미터이며 error와 동시 존재하면 거부한다. 알 수 없는 query·중복 code/error·fragment token·임의 return 목적지를 거부한다. pending 없음/기한 초과/다른 scheme은 SDK 교환 0회. Supabase의 error/error_code/error_description만 실패 통지로 해석하며 원문을 화면/로그에 노출하지 않는다.
5. pending.flowId를 명시해 exchangeCodeForSession을 한 번만 호출한다. SDK의 SIGNED_IN 통지를 그대로 수용하지 않고, 현재 attempt의 교환 완료 뒤에만 session→me 조회로 진행한다. code/verifier 불일치·재사용·SDK error면 미로그인 유지. 교환한 URL을 이력·영속 기록에 남기지 않는다. 성공·실패·취소의 종료 경로마다 pending/타이머/대기 Promise를 정리하고, 취소 표식은 §5.3의 SDK 정리가 끝날 때만 삭제한다.
6. warm 복귀는 현재 페이지 유지, cold 시작은 앱 기본 초기 페이지. 임의 URL로 이동하지 않고 user/me 반영·상태 통지로 완료한다. Browser.close 실패로 인증 성공을 되돌리지 않으며 닫기 실패와 인증 결과를 구분한다.
7. browserFinished는 waiting에서만 취소 후보로 두고, URL 이벤트와 순서가 경합하면 다음 이벤트 처리 기회까지 조정한다. exchanging 이후 닫힘 통지는 성공을 취소하지 않는다. 닫힘 통지가 없는 복귀는 10분 만료로 취소하고 app resume에서도 기한을 확인한다. 단순 appStateChange를 즉시 취소에 쓰지 않는다. 타이머/이벤트는 attempt가 일치할 때만 상태를 바꾼다.

### 5.3 취소·SDK 부수 효과·사용자 격리

- signOut 시작 시 pending을 무효화하고 generation/seq를 올려 session/me/ulp:keys/프로필 저장 큐/사용자별 화면을 먼저 비운다. 기존 프로필 지연 응답 가드를 유지한다. cold 초기화의 취소 표식 확인과 SDK 이벤트 격리는 일반 init/getSession/onAuthStateChange의 사용자 반영보다 먼저 준비한다.
- 교환 중 signOut은 SDK 교환과 직렬화한다. 교환 중 이벤트를 격리하고, SDK가 저장한 지연 성공은 local signOut으로 제거한 뒤 signOut 완료로 처리한다. 새 로그인은 이 완료까지 기다린다. SDK 이벤트 callback 안에서 SDK 호출을 await하지 않는다. 무효 attempt의 SIGNED_IN/TOKEN_REFRESHED로 signingOut을 해제하지 않는다.
- 교환이 프로세스 종료를 넘어도 취소가 복구되지 않도록 취소/로그아웃 완료 전까지 `ulp:native-oauth`에 취소 표식(`cancelled:true` 추가)을 남긴다. cold 초기화에서는 SDK local signOut을 먼저 끝낸 뒤 일반 세션 복원·기록 삭제를 한다. SDK 네트워크 미완료면 미로그인 유지·새 시작 대기. 임의 timeout으로 성공 처리하지 않는다.
- 공통 requestApi는 token 획득 전에 uid+generation을 캡처하고 fetch 전/응답 후 확인한다. GET/PATCH·ZIP·take의 이전 응답은 AbortError로 버려 새 사용자 화면/다운로드에 전달하지 않는다. AbortSignal은 fetch에 전파하고 AbortError를 일반 오류로 바꾸지 않는다. keepalive는 이미 전송한 처리를 취소한다고 주장하지 않으며 서버 소유자를 JWT로 고정한다.
- 서버 JWT→user.id→소유권 경계를 유지한다. integration appId=ulevelp를 유지하고 guitar-practice fallback은 추가하지 않는다. OAuth 외부 I/O 동안 DB 트랜잭션을 잡지 않는다. 기존 JWKS CancellationException 전파를 유지한다.

### 5.4 오류·화면 상태

신규 코드는 클라이언트 login.errorCode 전용이며 Ktor HTTP 코드가 아니다. `NATIVE_AUTH_CANCELLED`(닫기/10분 기한), `NATIVE_AUTH_CONFIG`(SDK/URL/저장/flowId 불비), `NATIVE_AUTH_OPEN_FAILED`, `NATIVE_AUTH_CALLBACK_INVALID`, `NATIVE_AUTH_EXCHANGE_FAILED`. 중복 시작은 pending에 합류하며 오류로 처리하지 않는다. 무관 URL/pending 없음은 표시·교환 없음. 정규 callback 경로의 잘못된 입력은 pending을 비우고 재시작 가능한 실패로 처리한다.

AppShell의 기존 main 안에서 children 앞에 기존 hint 스타일의 일반 문단을 두고, native에서만 `id=nativeAuthStatus`·role=status·aria-live=polite의 상태 텍스트를 추가한다. opening/waiting/exchanging은 진행 안내, 취소는 재시도 안내, 오류는 해당 번역문이다. ko/en/ja에 동일 auth.native* 키를 추가한다. Settings의 btnLogin·btnLoginBlank·accGuest/accUser·accEmail 및 기존 pillBtn·배치를 유지하고 native pending 중 로그인 시작을 disabled로 둔다. 기존 accMsg catch는 유지하며 login.status만으로 로그인 상태를 판정하지 않는다. AppShell 링크·embedded 동선·data-align-group을 이동하지 않는다(`AppShell.tsx:155-178`).

배치 약속: 390/768/1150/1280 전 폭에서 status는 main 내부 1열 흐름의 첫 문단으로, 기존 main 좌우 경계를 넘지 않고 긴 번역은 줄바꿈한다. idle·로그인 완료 뒤에는 status를 숨겨 빈 공간을 남기지 않는다. guest/진행/실패/성공 상태를 검사하며 기존 navRow:center-y·tabs:top,bottom,height·settings accountDisclosure:left,right를 보존한다. 라이트 4폭 및 데이터가 많은 다크 1280 캡처를 정렬 규격 §6 질문으로 검토한다. 새 고정 높이·오버레이·색 토큰·CSS 예외를 추가하지 않는다.

/me 실패 시 현재 me/keys를 비우고 알리는 기존 동작을 유지한다. OAuth 성공·JWT 세션 있음·me 조회 완료를 구분하며 실패한 /me를 다른 사용자 캐시로 보완하지 않는다. 네트워크/CSP/CORS 실패는 재시도 가능한 표시로 처리하고 토큰은 표시하지 않는다.

### 7.1 실기기·운영 관문

외부 설정/배포/앱 배포 승인 후 Supabase Redirect URLs에 **정확한** `ulevelp://auth/callback`을 추가하고 기존 웹 URL을 보존한다. Google 쪽은 기존 Supabase HTTPS callback을 사용하고 Google에 custom scheme을 직접 등록하지 않는다. 실제 설정은 비밀을 가려 결과에 기록한다. 운영 CORS 적용은 D2와 별도 배포 승인이 필요하다.

iPhone 17·iPad mini·Android SM_A920N·TB371FC에서 다음을 실제 확인하고 기기/OS/앱 commit/API revision을 결과에 남긴다: Google 선택→warm 복귀, 인증 중 앱 종료→cold 복귀, 앱 재시작 세션 복원, token 갱신 후 API, 취소/거부/offline→재시도, 로그아웃 후 재시작 guest, A→B/B→A 프로필·곡 분리. ZIP/Blob API 도달과 소유자를 확인하되 OS 파일 저장 UI는 완료 대상에 포함하지 않는다. 웹 Google 로그인·기존 확장도 회귀 확인한다.

mock E2E는 callback 경계 검증이며 실제 Google/OS 증거가 아니다. 외부 설정·기기가 없으면 미검증/사람 대기로 두고 앱 로그인 완료로 승격하지 않는다. Apple·Drive 모바일 인증 미대응은 M0-3 잔여 범위로 명시한다.
