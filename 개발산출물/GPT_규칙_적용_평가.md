# CLAUDE.md·GEMINI.md의 GPT 규칙 적용 평가

> 평가일: 2026-11-08 (Asia/Seoul)
> 상태: 2026-11-08 사용자 승인 후 루트 `AGENTS.md` 적용 및 원문 규칙 정비. 전역 Codex 설정은 변경하지 않음.

## 1. 결론과 범위

**공통 품질 규칙은 채택하고, 역할·승인·세션 운영 규칙은 조건을 붙여 이식하는 것이 적절하다.** 모델 이름에 묶인 역할, 고정 진행 파일, 일률적인 세션 종료는 GPT의 기본 규칙으로 옮기지 않는다.

이 문서에서 GPT는 이 저장소에서 작업하는 **Codex 에이전트**를 뜻한다. 일반 ChatGPT 대화나 계정 전체의 지침을 변경하는 문서가 아니다. 최초 평가에서는 적용 후보만 작성했고, 후속 사용자 승인으로 루트 `AGENTS.md`를 생성했다. 현재 활성 규칙은 §5의 링크에서 확인한다.

Codex의 저장소 지침 진입점으로는 루트 `AGENTS.md`가 적절하다. 공식 문서는 `AGENTS.md` 탐색과 별도 fallback 파일명 설정을 설명한다. 따라서 `CLAUDE.md`·`GEMINI.md`가 기본적으로 함께 자동 로드된다고 가정하면 안 된다. 전역 fallback 설정을 바꾸기보다 GPT에 필요한 공통 규칙을 별도 진입점에 정리하는 방안을 권장한다. [OpenAI 공식 문서: Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 4. 현재 저장소에서 확인한 주의점

1. **DB 격리 문구의 과도한 일반화:** `Tables.kt:19`의 `UsersTable`에는 `app_id`가 없고, `Tables.kt:226`의 `IntegrationsTable`에는 있다. `IntegrationService.kt:70`은 허용 앱을 `ulevelp`로 제한하고 `:112`에서 사용자와 앱 조건을 함께 적용한다. 이 실제 경계를 기준으로 규칙을 작성해야 한다.
2. **활성 작업 참조의 노후화:** `GEMINI.md`는 `개발산출물/진행_프론트기반.md`를 고정 참조하지만 현재 파일은 `완료/진행_프론트기반.md`에 있다. 협업 설명서 §0에는 이미 이동 사실이 적혀 있다. 새 GPT 규칙에 특정 진행 파일 이름을 고정하지 않는다.
3. **세션 크기 기준의 충돌:** CLAUDE는 대략 1시간 이내 단계를 제시하고, 협업 설명서 §4.3은 주니어 step을 PR·리뷰 단위로 정의한다. 역할에 맞는 기준을 선택하고 시간 제한으로 작업을 임의 중단하지 않는다.
4. **Git 권한의 예외:** CLAUDE의 일반 커밋·push 승인과 승인된 step의 자동 PR 예외를 함께 보존해야 한다. 이번 단발성 평가를 그 예외로 간주하지 않는다.
5. **검증 범위:** `package.json`에는 `npm run build`, `npm test`, `npm run test:e2e`가 있고 CI는 Kotlin `./gradlew test --no-daemon`도 사용한다. 변경 도메인에 맞게 선택하며, 문서 전용 변경에 앱 테스트 전체를 일률적으로 요구하지 않는다.

이 확인은 규칙 이식의 타당성 검토이며 전체 코드의 격리·보안·호환성 준수를 보증하는 감사 결과가 아니다. 열린 PR은 조회하지 않았으므로 동시 작업 충돌이 없다고 판정하지 않았다.

## 5. 적용된 GPT 규칙

사용자 승인으로 [루트 AGENTS.md](../AGENTS.md)를 생성했다. 이 파일이 현재 규칙 원본이며 중복된 초안 본문은 제거했다. 현재 세션에서도 파일을 직접 읽어 적용한다. 새 세션의 자동 로드 여부는 해당 세션에서 확인해야 한다.

## 6. 후속 적용과 검증 범위

`CLAUDE.md`·`GEMINI.md` 및 충돌하는 협업 설명서의 문구를 정비했다. 수정 근거와 모델별 미검토 사항은 [인수인계 메모](인수인계_메모.md)의 “AI 규칙 정비” 절에 기록한다. 규칙 보관 저장소 `choise-hun/config`의 `ULevelP/`에 프로젝트 규칙 사본과 검토 기록을 보관한다.

문서 검증 범위는 UTF-8/LF, 내부 링크, 코드 블록, diff 공백, 규칙 사본 일치 여부다. 소스·테스트 변경이 없으므로 앱 빌드·단위/E2E 테스트는 실행하지 않는다. Claude/Gemini의 실제 세션 검토와 새 Codex 세션의 자동 로드 확인을 실행한 것으로 보고하지 않는다.
