# 기능 확장 및 UI 정돈 요구사항 명세

> 역할: 기능 확장의 제품 동작·데이터/API 경계·수용 기준. 작업 순서·선행·진행률은 [상용 서비스 계획](../계획/상용_서비스_계획.md), 실행은 해당 `진행_*.md`에서 관리한다. 파일명은 기존 참조 호환을 위해 유지한다.
>
> 상태: 마스터 요구사항 명세. 아래 제품 요구, 데이터 분리, API 경계, 수용 기준을 작업별 상세 구현 명세의 기준으로 사용한다. DB·API 코드 변경은 프로젝트의 메뉴얼 게이트에 따라 실제 구현 전에 변경 항목을 승인받는다. 각 Step의 상세 구현 명세는 구현 시작 전에 별도 작성한다.
>
> 조사 기준: 2026-11-08 현재 작업 트리. 문서는 저장소의 미커밋 UI 규칙 변경도 검토 대상으로 삼았지만, 해당 변경의 머지·배포 여부를 전제하지 않는다. 참조는 줄 번호보다 파일 경로와 심볼명을 우선한다. 줄 번호는 편집 때마다 바뀔 수 있다.

## 1. 목적과 범위

이 문서는 아래 사용자 요구를 현재 DO.LOOP/ULevelP 구조에 맞는 검토 가능한 제품 요구사항과 구현 기준으로 정리한다.

1. 코드 연습실에서 CAGED 블럭 선택을 지판 가까이 배치하고, 시퀀스 칩 격자는 화면에서 제거한다.
2. 코드 연습실에서 악기를 선택하고, 악기별로 지원되는 연습 모드만 보여준다. 기타·베이스·건반을 지원한다.
3. TRAILS는 개인 기록에 집중시키고 커뮤니티를 별도 페이지로 분리한다. 커뮤니티의 모두 화면에는 큐레이션과 개별 연습 공유 게시물을 함께 보여준다. 연습 기록 카드에서 게시물을 공유할 수 있다.
4. 로그인 사용자 이름/아바타 진입을 앱 설정과 분리해 프로필 화면으로 연결한다.
5. 설정을 분류된 접이식 목록으로 바꾸고, 설정 등록 누락을 검사하는 구조를 둔다. 필과 사각형의 사용은 기존 디자인 규칙과 사용자 지정 범위에 따른다.

범위 밖: 커뮤니티 댓글·대화, 추천 알고리즘 전면 개편, 기존 레거시 화성 API 변경, 기존 화면 전체의 일괄 사각화, 별도 모바일 앱 기능.

## 4. 기능 요구사항

### REQ-1 — 스케일 CAGED 블럭 선택 위치

1. 스케일 탭의 .seqSummary 및 #sc-seq 시각화는 제거한다. scSeqNotes/scMilestoneSummary 계산은 다른 동작에서 필요하지 않은지 사용처를 조사한 뒤 제거 여부를 결정한다. 스케일 오디오 재생 및 현재 음 하이라이트에 필요한 계산·상태는 유지한다.
2. #sc-block을 스케일 지판 바로 아래, 범례 바로 위로 이동한다. 레이아웃은 스케일 패널의 주 흐름 안에 두고 전체 지판 선택과 5개 CAGED 포지션 선택을 계속 제공한다.
3. #sc-block 버튼만 사각형으로 스타일링하고 1px var(--line) 테두리, 웜 배경/텍스트 토큰, border-radius: var(--radius-card)를 사용한다. JSX 인라인 스타일은 추가하지 않는다.
4. .seq/.seqn CSS는 코드톤 화면 등 다른 사용처가 남아 있으면 유지한다. 죽은 스타일과 i18n 키는 전체 참조를 확인한 뒤에만 제거한다.
5. 지원하지 않는 스케일에서 기존 전체 지판 폴백 및 안내 상태를 보존한다. 프런트의 harmMinor/melMinor 선택 동작과 백엔드 400 오류 계약은 서로 다른 표면이므로 혼동하지 않는다.

### REQ-2 — 악기 선택 및 악기별 연습 모드

1. 코드 연습실에 상위 instrumentKind 상태(guitar/bass/keyboard)를 두고 악기 선택을 페이지 헤더에 노출한다. 줄 수/튜닝 선택은 해당 악기 아래 하위 선택으로 둔다.
2. 지원 탭은 다음과 같다.

| 악기 | 탭 | 동작 |
|---|---|---|
| guitar | scale, tone, matrix, circle, reint, tf, ds, prog | 기존 8개 기능 유지 |
| bass | scale, tone | 4/5/6현 튜닝, 베이스 음역/지판 배치, bassPluck 재생 사용. tone은 루트·3도·5도·7도와 2NPS 아르페지오만 노출 |
| keyboard | scale, tone, reint, tf, prog | 건반 SVG와 키보드 음원 재생을 지원. matrix/circle/ds는 숨김 |

3. 악기 변경 시 현재 탭이 비지원이면 첫 지원 탭 scale로 유효 상태를 즉시 정규화한다. 존재하지 않는 튜닝, 줄 쌍, 블럭 및 모드가 첫 렌더에서 자식 계산으로 전달되지 않게 effective 상태를 사용한다. 악기 변경 핸들러는 instrument/tuning/tab을 한 번에 갱신한다.
4. guitar 기본값은 g6로 둔다. 6/7현 기타, 4/5/6현 베이스 세부 튜닝 선택을 제공한다.
5. 건반 렌더러는 서버 KeyboardSvgRenderer의 음높이·건반 배치·손 표시 규칙을 기준으로 프런트 KeyboardDiagramSvg를 만든다. SVG 상호작용/색상은 현재 프런트 컴포넌트 규칙에 맞추고, 서버가 만든 SVG 문자열을 위험한 HTML로 직접 삽입하지 않는다.
6. 코드 연습실 탭 버튼은 홈 카테고리 바로가기의 사각형 그리드에서 시각 규칙을 참고하되, 홈 위젯을 변경하지 않는다. 키보드 접근성(버튼, aria-selected, 포커스)과 좁은 화면에서의 가로 넘침을 검사한다.
7. 홈의 BETTER 연습실 링크는 기존 chords.html 진입을 유지한다. 별도 랜딩 라우트는 만들지 않는다. 악기 선택 후 지원 모드를 선택하는 것이 코드 연습실 내 시작 흐름이다.

### REQ-3 — 커뮤니티 분리와 개별 연습 공유

#### 탐색 및 화면

1. LogPage는 개인 기록과 곡 보관함/상세만 담당한다. 커뮤니티 탭과 패널은 제거하고 새 CommunityPage를 /community.html로 제공한다.
2. 상단/하단 앱 내비게이션에 COMMUNITY 진입점을 추가한다. 홈 BETTER/VAULT 아래의 WHAT YOU DO? 홍보 배너도 /community.html로 연결한다. 이는 같은 화면으로 가는 두 진입점이다.
3. 커뮤니티의 모두 탭에는 기존 CurationRows를 유지하고, 그 아래 새 에피소드 섹션을 함께 렌더링한다. LOG 탭은 새 개별 연습 게시물만 노출하고 전체/팔로잉 범위를 제공한다. 기존 84일 집계는 별도 사용자 프로필/커뮤니티 로그 표면에 유지한다.
4. 게시물은 좌측 YouTube 썸네일, 제목/코멘트, 공개 세션 메타, 날짜/연습 시간, 구간 재생, 내 보관함 담기 액션을 갖는다. 썸네일은 기존 security.ts의 안전한 YouTube 썸네일 생성 규칙을 재사용한다.
5. 구간 재생은 기존 practice.html URL 규약(v, a, b, r, t)을 따른다. 공유 구간을 재생하고 해당 곡이 사용자 보관함에 없을 때는 기존 곡 추가/가져오기 동선을 사용한다. 외부에서 전달된 URL은 기존 videoId 검증을 거친다.

#### 공유와 관리

1. TRAILS 날짜별 세션 카드와 플레이어 하단 연습 기록 카드를 같은 PracticeSessionCard UI로 통합한다. 세션별 파트 요약, 커버리지, 시간, 반복 수, 테이크 개수/목록 등 두 화면에서 지원되는 메타를 동일한 순서와 표시 형식으로 구성한다. 개인 전용 메모와 오디오 재생/보관 기능은 현재 접근 권한을 유지한다.
2. 카드에 공유/공유 중지 액션을 제공한다. 공유 시작 시 선택 제목·코멘트를 입력하고 공개됨을 명시적으로 확인한 다음 저장한다. 기존 세션 메모/테이크 메모는 게시물로 복사하지 않는다.
3. 새 V10 마이그레이션은 shared_practice_cards 테이블을 추가한다. 권장 필드: id UUID PK, session_id UUID NOT NULL UNIQUE FK sessions(id) ON DELETE CASCADE, user_id UUID NOT NULL FK users(id) ON DELETE CASCADE, title TEXT NOT NULL CHECK (char_length(title) <= 80), comment TEXT NOT NULL DEFAULT '' CHECK (char_length(comment) <= 500), status TEXT NOT NULL DEFAULT 'published' CHECK (status IN ('published', 'tier_paused', 'moderation_hidden')), published_at TIMESTAMPTZ NOT NULL, hidden_at TIMESTAMPTZ NULL, hidden_reason TEXT NULL, created_at TIMESTAMPTZ NOT NULL, updated_at TIMESTAMPTZ NOT NULL. user_id/published_at 및 공개 피드 페이지네이션에 필요한 인덱스를 둔다. 세션 자체에는 is_shared/title/comment 컬럼을 추가하지 않는다. 서비스는 session_id로 세션을 조회한 뒤 세션 소유자와 user_id가 일치하는지 반드시 검증한다.
4. 신고에는 shared_practice_card_reports 별도 엔티티를 둔다. 카드/신고자/사유/선택 상세/상태/생성 및 처리 시각을 저장하고, 동일 사용자의 동일 카드 열린 신고 중복을 막는다. 운영자 화면에서 신고 확인·숨김·복구를 제공한다. 공개 사용자 작성 문구에는 기존 BannedWords 검사를 적용한다.
5. API 계약은 아래 기준으로 추가한다. 정확한 Kotlin DTO/요청 검증/오류 코드는 작업별 상세 명세에서 고정한다.

| 메서드 및 경로 | 용도 | 권한/응답 기준 |
|---|---|---|
| POST /api/v1/sessions/{sessionId}/share | 세션 공유 생성 또는 tier_paused 게시물 재게시 | 인증, 소유자, 유료 communityWrite, publicName 필요. 본문 title/comment. moderation_hidden 게시물은 재게시 불가. 공유 카드 DTO 반환 |
| DELETE /api/v1/sessions/{sessionId}/share | 작성자가 본인 게시물 공유 철회 | 인증 및 소유자 검사. 공개 피드에서 즉시 제외 |
| GET /api/v1/community/episode-logs?scope=all\|following&cursor=... | 공개 세션 카드 페이지 조회 | 인증 필수, 무료 티어 열람 허용. 공개 상태이며 유료 자격이 유효한 작성자만 노출. publishedAt 내림차순 + id tie-breaker |
| GET /api/v1/community/me/episode-logs | 로그인 사용자의 공유 게시물 목록 | 인증 사용자 본인 게시물만 포함. tier_paused/moderation_hidden 상태와 사유를 구분해 반환 |
| POST /api/v1/community/episode-logs/{postId}/reports | 게시물 신고 | 인증 사용자. 중복 열린 신고는 409 |
| GET /api/v1/admin/community/episode-logs/reports | 신고 목록 | 기존 운영 권한 가드. 처리 대기/처리 완료 필터와 페이지네이션 |
| PATCH /api/v1/admin/community/episode-logs/{postId} | 운영자 숨김/복구 | 본문 status=moderation_hidden 또는 published, reason. tier_paused는 작성자 재게시만 해제 가능. 변경자/시각을 감사 기록에 남기고 기존 운영자 audit 패턴 사용 |

6. 게시물 공개 DTO는 postId, sessionId, 공개 작성자(PublicOwnerDto: id, publicName, isCreator, creatorBadge), videoId, YouTube title/artist, title, comment, publishedAt, session date/seconds/loops, a/b/rate, coveragePct, partStats 및 video thumbnail 식별자를 포함한다. partStats는 각 name/a/b/rate/completed/seconds/loops 필드를 갖는 배열이다. takes, storageKey, 이메일, displayName, 개인 memo는 절대 포함하지 않는다.
7. 작성자는 프로필의 내 공유 기록에서 본인 게시물을 확인·철회/삭제할 수 있다. 운영자 숨김은 피드에서 제외하고 사유·신고 상태를 남긴다. 다운그레이드는 status=tier_paused로 바꾸고, 재구독 이후 작성자가 POST로 재게시하면 published로 전환한다. moderation_hidden은 운영자만 복구한다. 탈퇴 및 원본 세션/곡 삭제 시 게시물 수명주기는 참조 무결성으로 정리한다.
8. 새 카드의 공개 동의와 기존 share_practice_log는 독립적이다. 기존 동의만으로 과거 세션을 자동 게시하지 않으며, 신규 공유 버튼에 명시적 동작이 있어야 게시된다.

### REQ-4 — 프로필 진입 분리

1. SETTING은 settings.html로 유지하고, 로그인 상태의 #navAuth는 profile.html로 이동한다. 로그아웃/비로그인 상태의 인증 진입 동작과 임베드 환경 동작은 기존 계약을 보존한다.
2. 신규 ProfilePage에는 displayName, publicName, 프로필 공개 요약(실제 티어/크리에이터 정보/소개/팔로워 수), 내 공유 폴더·연습 게시물과 공유 철회 관리를 둔다. publicName 입력/변경은 기존 PublicNameForm과 서버 정책을 재사용한다. displayName과 publicName은 다른 값이다. 내 프로필 요약은 기존 /api/v1/community/users/{userId} 및 /api/v1/community/follows API 응답을 먼저 대조하고, 기존 프런트 호출 래퍼가 없으면 그때만 추가한다.
3. 프로필 화면에서 로그아웃할 수 있어야 하며 기존 auth.logout 및 로컬 전용 로그아웃 규칙을 재사용한다.
4. 서버 /me DTO에 이미 내려오는 billingTier, tierOverrideUntil, usage, creatorBio 등을 프런트 타입에 정확히 반영하고, 필요한 값의 누락/nullable 여부를 백엔드 DTO와 대조한다. 팔로워/팔로잉 정보는 현행 사용자 요약/팔로우 API가 제공하는 필드만 사용한다.
5. 새 페이지는 App.tsx, AppShell 내비게이션, Ktor SPA 진입 페이지 목록, Node server.js의 SPA 목록을 서로 맞춘다. 각 페이지에서 activeNav/current page가 일치해야 한다.

### REQ-5 — 설정 페이지 분류 및 누락 방지

1. 설정의 현행 섹션을 그룹화한다: 계정·저장소, 구독·크레딧, 공개·연동, 화면·언어, 고급·백업·데이터 관리, 운영자. displayName/publicName 등 프로필 편집은 ProfilePage로 옮기고, 계정 로그인·이메일·저장소 등 앱 설정은 SettingsPage에 둔다. 운영자 패널은 기존 권한 제한을 유지한다.
2. 기본 화면은 각 그룹의 컴팩트한 요약 행을 접힌 상태로 보여준다. 사용자가 행을 열면 기존 설정 컨트롤을 표시한다. 기존 해시(#account, #credits, #community, #screen, #langSec, #advanced 등)로 진입한 경우 해당 그룹을 열고 해당 설정으로 포커스/스크롤한다. 설정값, 저장 API, 키보드 조작, 초기 로딩 상태는 그대로 유지한다.
3. Registry는 화면 섹션 자체를 중복 정의하지 않고, 그룹/항목 ID, 제목 i18n 키, 기존 해시 별칭, 설정 페이지의 렌더 키를 연결한다. 검증은 누락된 렌더 항목, 존재하지 않는 번역 키/별칭, 중복 ID/별칭을 실패시킨다. 동적 운영자 설정과 서버 제공 항목은 고정 항목과 구분한다.
4. 기존 E2E는 /settings.html 로드 직후 #accEmail과 여러 섹션이 보인다는 가정을 포함한다. 기본 접힘으로 바꾸면 설정 준비 검증과 해시 딥링크 테스트를 새 동작에 맞춰 바꾼다. 테스트 단언을 약화하지 말고 접힘 상태, 열기, 저장 결과를 검증한다.
5. 이번 요청에서 지정되지 않은 기존 pill을 일괄 사각화하지 않는다. 이번 설정 개편에서 새 요약 행과 닫힌 리스트 행은 radius-card 사각형, 1px var(--line), 적절한 웜 토큰으로 스타일링한다. 기존 pill 입력/버튼은 용도에 맞으면 유지한다. 설정의 긴 텍스트는 작은 화면에서 줄바꿈을 허용하고 버튼 자체의 한 줄 요구와 구분한다.

## 5. 데이터·보안·호환성 필수 조건

1. 모든 세션 접근은 인증된 사용자와 sessionId를 함께 제한해 타 사용자 세션 ID 추측 접근을 막는다. 공유 작성/철회/조회에서 소유권과 공개 상태를 서버에서 검증한다.
2. 통합 데이터의 app_id 경계는 IntegrationService에서 appId를 검증하고 해당 통합 쿼리에서 userId/appId/provider를 조건으로 사용한다. 이를 무관한 모든 DB 쿼리에 app_id 조건을 덧붙이는 요구로 확대 해석하지 않는다.
3. 신규 DB 작업은 docs/rules/backend-kotlin.md의 트랜잭션·취소 전파 규칙을 따른다. YouTube 메타 조회 등 외부 I/O를 DB 트랜잭션 안에서 수행하지 않는다.
4. 프런트의 비동기 목록/저장 요청은 docs/rules/frontend-state.md의 uid·요청 순번/취소 패턴을 따른다. 계정 전환 후 이전 사용자의 응답이 새 화면을 덮어쓰지 않아야 한다.
5. 기존 /api 레거시 오류 응답을 바꾸지 않는다. 신규 /api/v1 오류는 ApiErrorResponse 표준을 사용한다. 검증 실패, 미인증, 권한 부족/티어 부족, 소유권 불일치, 없는 세션/게시물, 이미 열린 신고는 구분된 상태/코드로 응답한다.
6. 신규 경로의 게시물 ID는 UUID 등 불투명 식별자로 처리한다. 공개 작성자 정보는 PublicOwnerDto 경계로 제한하고 email/displayName은 반환하지 않는다. 사용자 입력은 길이/공백/금칙어 검증 후 텍스트로 출력하고 HTML로 해석하지 않는다.
7. 유료 티어 만료는 기존 스케줄러 및 다운그레이드 트랜잭션에서 공유 카드를 숨기고 재구독 후 자동 공개하지 않는다. 데이터는 정책에 따라 보존한다.

## 7. 구현 작업과의 연결

작업 ID CH-A·CH-B·CM-BE·CM-UI·PF·ST의 범위 요약·선행·REQ/AC 대응은 [상용 서비스 계획 §1](../계획/상용_서비스_계획.md)에 둔다. 이 문서는 순서·진행 상태를 별도로 관리하지 않는다. 작업별 실제 변경 파일·DTO·상태 코드·테스트는 착수 시 상세 구현 명세에 고정하고, 이 문서의 필드·오류·권한·수용 조건을 생략하거나 대체하지 않는다.

## 8. 상세 명세 작성/구현 전 확인 목록

1. DB/API 변경 각 작업의 승인 목록을 먼저 제시한다. 이 통합 명세는 코드 변경 승인을 대신하지 않는다.
2. 각 작업 명세는 변경 파일, 요청/응답 DTO 전 필드, 상태 코드/오류 코드, 권한/소유권, migration rollback/삭제 정책, i18n 키, DOM 계약, 기존 테스트 영향, 새 테스트 시나리오를 빠짐없이 기재한다.
3. UI 작업은 개발산출물/프론트_정렬규격.md의 순서(배치 약속 → 스펙 확인 → 구현 → 관련 layout spec → 화면 폭 검토)를 따른다. 이 명세는 스크린샷/브라우저 테스트를 실행했다고 주장하지 않는다.
4. 공개 문구 정책은 D-4를 기준으로 구현하되, 공유 제목/코멘트 moderation을 제외하거나 기존 공개 글자 금지 정책을 유지하려면 REQ-3 범위 재결정이 필요하다.
5. 이 문서의 file/symbol 참조는 현행 구조 탐색용이며 계약 정의가 아니다. 구현 직전 현재 브랜치의 실제 코드와 작업 충돌을 다시 확인한다.
