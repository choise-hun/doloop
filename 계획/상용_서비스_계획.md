## 2. 기존 기능 검수와 완료 기준

AV-1~AV-3은 “나중 기능에 쓸 코드가 있다”를 완료로 판단하지 않기 위한 관문이다. 기능별 표에 `구현 / 화면 연결 / 통합 검증 / 운영 확인`을 각각 적고 근거 커밋·실행 명령·결과 링크를 연결한다. PR·CI·화면 mock 검증만으로 뒤 단계를 완료 처리하지 않는다. 제외/N/A는 이유를 명시한다.

필수 검수 여정:

1. 유료 A의 공개 이름 설정 → 폴더 게시 → 무료 B의 발견·구간 재생·좋아요·팔로우.
2. 유료 B의 폴더 담기 → 자기 보관함 등록 결과 확인, 무료/한도 초과 실패 시 무변경 확인.
3. 수동 재게시·자동 연동의 차이, 전체/폴더별 끄기, 공유 철회 후 B에게 비노출.
4. 무료 강등·유예 종료·재구독 시 공개/자동 연동 상태와 재게시 정책.
5. 집계 로그의 동의·공개 이름·티어 조건과 메모·녹음·이메일 등 비공개 데이터 미노출(연습 기록 카드에 직접 고른 녹음 사본 제외 — S3b).
6. 신고 → owner 조회·처리·숨김 → 공개 조회 반영. API로만 가능한 운영 단계는 그 사실과 절차를 명시하고 화면 보완 필요성을 판정.
7. 계정 A↔B 전환·로그아웃·시트 전환 중 지연 응답·실패·중복 클릭의 상태 격리.
8. 재생목록 가져오기·쿼터·크레딧 예약/정산/실패 반환·30일 지급/유예·비 owner 관리 차단. 결제 미구현 경계는 구분.

운영 콘텐츠: 첫 큐레이션·이달의 곡 등록은 기존 [운영 화면 결과](../개발산출물/결과/M2-4b_운영화면큐레이션.md) §4를 입력으로 한다. 현재 등록 여부를 확인한 뒤 사용자 승인 범위에서 작성한다. 등록하지 않았다는 추정을 사실로 바꾸지 않는다.

개발 착수와 확장 완료·운영 인수 관문은 [AV-3 마감 판정](../개발산출물/결과/AV3_마감.md) §3처럼 분리한다. 로컬 통과 후 다음 개발 후보는 CH-A이며 운영 미검증을 완료로 승격하지 않는다.

AV-3 결과에는 재사용할 기존 기능, 고칠 결함, 화면 미연결 보완, 새 요구사항을 구분한다. 실제 여정이 실패하거나 차단된 핵심 경로는 웹 확장 완료로 덮지 않고 다음 행동·책임·증거를 남긴다.
