## 3. Step별 핵심 주의사항 및 검증 기준

1. **`G5b`(팔레트 밖 색 경고) 선제 방지 (`DS2-1`):**
   - [layout-check.js](../test/e2e/support/layout-check.js)의 `G5b`는 `tokens.css`에 선언된 색 토큰 목록과 계산된 RGB를 대조한다. `--panel-frosted`, `--seam-hairline`, `--seam-highlight`, `--relief-bottom-mid`를 `color-mix()` 대신 `tokens.css`에 계산된 **명시적 hex 토큰**으로 함께 정의하면(라이트/다크 3블록 모두) `G5b` 오탐 없이 통과한다.
2. **기존 곡률 테스트 일원화 (`DS2-1`):**
   - `test/design_rules.test.js` `DR-2` 외에 `r0_core.test.js`, `r1_home.test.js`, `r1_settings_notes.test.js`, `r2_chords.test.js`, `r3_practice_log.test.js`, `chords.spec.js`가 각각 `0px`/`9999px`를 하드코딩 검사하고 있다. `DS2-1`에서 허용 곡률 집합에 `var(--radius-block)`(`3px`)을 반영할 때 이 파일들을 빠짐없이 함께 정합화한다.
3. **`DR-6` (`12px` 하한) 준수:**
   - 모든 T4 계기판 라벨은 `12px`를 유지하며 `KNOWN_SMALL_TEXT` 허용 표에 새 파일/개수를 추가하지 않는다.
4. **터치 크기(`G7a`/`G7b`) 유지:**
   - 카드 내 버튼(`랜덤 ↻`, `연주하기 →` 등)을 텍스트 버튼으로 바꿀 때 390·768 폭에서 터치 영역이 `44px` 미만으로 줄지 않도록 패딩/간격을 확보한다([프론트_정렬규격.md](../개발산출물/프론트_정렬규격.md) §3).
5. **검증 명령:**
   - 단위/규칙: `npm test` (`design_rules.test.js`, `r0`~`r3` 포함)
   - 빌드: `npm run build`
   - 레이아웃 E2E + 스크린샷: `LAYOUT_SHOTS=1 npx playwright test test/e2e/layout/<화면>.spec.js` → 4개 폭(390·768·1150·1280) + 다크 1장 Q1~Q9 검토
6. **중앙 config 동기화:**
   - `docs/rules/frontend-design.md`가 개정되었으므로, `~/config` 저장소가 있는 PC에서는 `bash scripts/check-config-sync.sh --copy` 및 `check-config-sync.sh`로 동기화를 맞춘다.
