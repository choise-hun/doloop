### 2.2 `i18n/LocaleResolver.kt` (package `ulevelp.i18n`)

```kotlin
@Serializable
data class DetectedLocaleResponse(
    val locale: String,
    val country: String?,
    val source: String
)

object LocaleResolver {
    const val HEADER_CLIENT_LOCALE = "X-Client-Locale"
    val SUPPORTED_LOCALES: Set<String> = setOf("ko", "en", "ja")

    val GEO_COUNTRY_HEADERS: List<String> = listOf(
        "X-Cloud-Geo-Location",
        "X-AppEngine-Country",
        "CF-IPCountry",
        "CloudFront-Viewer-Country",
        "X-Country-Code"
    )

    /** "ko" | "en" | "ja" (소문자 정규화, "ko-KR" -> "ko"). 지원하지 않는 값이면 null */
    fun normalizeLocale(raw: String?): String?

    /**
     * 요청 헤더에서 국가 코드(ISO 3166-1 alpha-2 대문자, 예: "KR", "JP", "US")를 추출한다.
     * - X-Cloud-Geo-Location이 "KR, Gwangju"처럼 쉼표 구분이면 앞 2글자 국가 코드만 파싱한다.
     * - "XX", "ZZ", "T1" 등 미상 코드는 null로 본다.
     */
    fun extractGeoCountry(headers: Headers): String?

    /** 국가 코드 -> 기본 언어 ("KR" -> "ko", "JP" -> "ja", 그 외 2자리 영문 국가 코드 -> "en") */
    fun mapCountryToLocale(country: String): String?

    /**
     * Accept-Language 헤더(예: "ja-JP,ja;q=0.9,en-US;q=0.8,en;q=0.7")를 q 가중치 내림차순으로 파싱하여
     * SUPPORTED_LOCALES에 매칭되는 첫 언어를 반환한다. 없으면 null.
     */
    fun parseAcceptLanguage(headerValue: String?): String?

    /**
     * 비로그인/초기 진입 환경 감지 순서:
     * 1) X-Client-Locale 헤더가 유효하면 -> (locale, country, source = "header")
     * 2) GeoIP 헤더 국가 코드가 유효하면 -> (mapCountryToLocale(country), country, source = "ip_country")
     * 3) Accept-Language 헤더에 매칭되는 언어가 있으면 -> (locale, country, source = "accept_language")
     * 4) 모두 없으면 -> ("ko", country = null, source = "default")
     */
    fun detectFromRequest(call: ApplicationCall): DetectedLocaleResponse

    /** API 요청에서 사용할 단일 언어 코드 반환 (detectFromRequest(call).locale) */
    fun resolveLocale(call: ApplicationCall): String
}
```

## 5. 처리 순서·트랜잭션 경계

### 5.1 위치·환경 기반 자동 언어 감지 (`LocaleResolver.detectFromRequest`)
1. DB 접근 없음, 외부 네트워크 호출 없음(0ms 메모리 연산).
2. `call.request.headers["X-Client-Locale"]`를 `normalizeLocale`로 검사 → 유효하면 `source = "header"`로 즉시 반환 (`country`는 `extractGeoCountry` 결과 동반).
3. `extractGeoCountry(call.request.headers)` 실행:
   - `GEO_COUNTRY_HEADERS`를 순서대로 확인.
   - 값이 있으면 첫 `,` 앞부분을 `trim().uppercase()` 하여 `^[A-Z]{2}$`이고 `XX`·`ZZ`가 아니면 국가 코드로 채택.
   - 국가 코드가 채택되면 `mapCountryToLocale(country)` (`KR` → `ko`, `JP` → `ja`, 그 외 모든 국가 → `en`)를 `source = "ip_country"`로 반환.
4. GeoIP 헤더가 없으면(로컬 개발 환경 등) `call.request.headers[HttpHeaders.AcceptLanguage]`를 `parseAcceptLanguage`로 파싱:
   - `,`로 분리 → `;q=` 가중치(기본 `1.0`, `0.0..1.0` 범위 밖이면 무시) 파싱 → 가중치 내림차순 정렬(동률이면 원래 순서 유지) → 각 언어 태그의 앞 2글자(`ko`, `en`, `ja`) 매칭 시 `source = "accept_language"`로 반환.
5. 모두 해당 없으면 `DetectedLocaleResponse(locale = "ko", country = null, source = "default")` 반환.

### 5.2 첫 로그인 시 초기 언어 저장 (`SupabaseAuthPlugin` → `ProfileService.ensureUserAndProfile`)
1. 인증 플러그인에서 `val reqLocale = LocaleResolver.resolveLocale(call)`을 추출해 `profileService.ensureUserAndProfile(user, reqLocale)`을 호출한다.
2. 트랜잭션 1개: 이미 가입된 사용자면 기존単일 `SELECT`로 확인 후 종료(쓰기 쿼리 없음, 주니어 체크리스트 준수). 신규 사용자면 `ProfilesTable.insertIgnore` 시 `locale = reqLocale`로 저장한다.

## 9. 금지 사항

- 외부 IP 조회 API(`ipapi.co`, `ipinfo.io` 등)를 서버나 브라우저에서 HTTP로 호출하지 않는다(지연·쿼터·개인정보 문제. 반드시 리버스 프록시/Cloud Run 헤더와 `Accept-Language`만 쓴다).
- `SongsTable.status` DB 저장 값을 `"Practicing"`이나 `"練習中"`으로 바꾸지 않는다(DB에는 항상 `"practicing"`·`"paused"`·`"done"` 코드만 저장하고 `SongDto.status` 표시 라벨만 바꾼다).
- 노션 연동은 2026-11-05 중단·동결(`앱_명세.md` §5) — 노션 관련 코드(`OutboxRepository`·`NotionPushWorker` 등)는 건드리지 않는다(속성명 번역 없음).
- 이미 가입된 사용자의 `GET /api/v1/me` 호출마다 `profiles.locale`을 요청 헤더로 덮어쓰는 UPDATE 쿼리를 실행하지 않는다(주니어 체크리스트 "요청마다 반복되는 쓰기 금지").
