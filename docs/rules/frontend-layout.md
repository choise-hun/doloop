# 프론트엔드 반응형 정렬·레이아웃 규칙 (진입 문서)

> **규격 원본: [`개발산출물/프론트_정렬규격.md`](../../개발산출물/프론트_정렬규격.md)** — 판정식·허용 오차·간격 스케일·예외 문법·`known` 처리는 전부 거기에 있다.
> 색·곡률·글자 크기 같은 형태 규칙은 [`frontend-design.md`](frontend-design.md)에 있다. 이 문서와 원본 규격은 배치·간격 검사를 다룬다.
> 이 문서는 요약 진입점이다. 숫자나 판정 기준을 여기에 복제하지 않는다(원본과 어긋남 방지). 화면 작업 전 원본을 읽는다.

## 3층 구조

| 층 | 무엇을 잡나 | 어디에 있나 |
| --- | --- | --- |
| ① 공통 검사 G0~G8 | 넘침·형제 겹침·글자 잘림·가로 스크롤·색·처짐·터치 크기·간격 | `test/e2e/support/layout-check.js` |
| ② 배치 약속 | "이것과 저것은 윗선·아랫선·높이를 맞춘다" | 마크업 `data-align-group="<그룹>:<선>[,<선>…][@<최소폭>]"` |
| ③ 스크린샷 검토 | 여백 균형·위계·빈 상태·다크 모드 | 4개 폭(390·768·1150·1280) 캡처 + 질문 Q1~Q9 (원본 §6) |

## 작업 순서 (화면을 만들거나 배치·문구를 바꿀 때)

1. **배치 약속을 먼저 정한다** — 폭별 열 구성, 맞출 선
2. **`test/e2e/layout/<화면>.spec.js`를 먼저 쓰고 실패를 확인한다**
3. **구현한다** — 마크업에 `data-align-group`을 함께 쓴다
4. **통과시킨다** — `npx playwright test test/e2e/layout/<화면>.spec.js`
5. **스크린샷을 검토한다** — `LAYOUT_SHOTS=1`로 4개 폭 캡처 → Q1~Q9를 폭별로 판정해 결과 파일에 표로 남긴다
6. **예외는 사유와 함께** — `data-layout-ignore="<규칙ID>[ <규칙ID>…]: <사유>"`. 사유 없음·없는 ID는 G0 실패. 아직 못 고친 실패는 `known`(원본 §8-2)이며 예외와 다르다

## 검사 규칙 이름 (기준값은 원본 §5)

G0 표기 오류 · G1 카드 밖 넘침 · G2 형제 겹침 · G3 글자 잘림 · G4 가로 스크롤 · G5a 금지 색(실패)/G5b 팔레트 밖 색(경고) · G6 카드 내용 처짐 · G7a 터치 대상 최소(실패)/G7b 모바일 권장(경고) · G8 간격 스케일(경고)

## 자주 깨지는 패턴 (처방은 원본 §2 표)

- 카드의 `justify-content: space-between` → G6 (기본 `flex-start`, 바닥 고정만 `margin-top: auto`)
- 그리드 칸보다 넓은 고정폭 자식 → G2 (`width: 100%` + `max-width`, 칸은 `minmax(0, …)`)
- 한 줄 `nowrap` + 말줄임 → G3 (줄바꿈 허용, 의도면 `data-layout-ignore`)
- 전역 `a` 색 상속 → G5 (화면 모듈에서 색을 덮는다)

## 금지

- 픽셀 비교(`toHaveScreenshot`) 사용 금지 (원본 §6 결정)
- 검사를 통과시키려고 기준값·허용 오차를 완화하지 않는다. 원본 규격을 바꿀 때는 먼저 묻는다
